# 00 · 概览:愿景与全局认知

这是整套文档的**第一站**。它不讲字段、不讲接口,只做一件事:
帮你在 10 分钟内建立 GitHub Gallery 的心智模型——它是什么、要解决什么、边界在哪、
以及那几个贯穿全文的核心词到底指什么。读完这篇,再进后续任何一篇都不会迷路。

- **这篇负责**:产品主旨、要解决的问题、目标与非目标、术语表、读者路径。
- **这篇不负责**:实体字段(见 [02](./02-domain-model.md))、分层架构(见 [03](./03-architecture.md))、
  接口契约(见 [06](./06-api-contract.md))。这里只建立"是什么",不展开"怎么做"。

---

## 1. 一句话主旨

GitHub Gallery 是一个**本地部署、单人使用**的
「GitHub 项目个人知识库 + 学习追踪系统」:

> 贴链接或自动抓取热门项目 → AI 按需分析 → 收藏进库、分类打标、追踪学习状态
> → 为优质项目沉淀多角度详情文档。

**审美(handsome / 炫酷)是一等需求,不是附赠。**

## 2. 要解决什么问题

一个持续关注 GitHub 的人,面对的是这样的困境:

- **看到就丢**:每天刷到有意思的项目,收藏夹一存就再也不看,等于没存。
- **重复研究**:同一个项目隔几个月又刷到,想不起当初为什么看过、看没看懂。
- **没有学习追踪**:哪些是"想学"、哪些"正在啃"、哪些"已经用上了",全靠脑子记。
- **认知不沉淀**:研究一个项目产生的理解(怎么装、架构如何、我的笔记),散落各处,不成资产。

GitHub Gallery 把这条链路收拢成一个系统:**从易逝的信息流,到稳定的项目资产,再到深度的知识沉淀。**

## 3. 目标与非目标

**目标(要做)**

- 把"发现项目 → 收藏 → 分类打标 → 追踪学习状态 → 写详情文档"做成一条连续动线。
- 区分**易逝的流**与**稳定的库**:流用来快速筛,库用来长期管理。
- 为优质项目沉淀**多角度详情文档**(安装使用 / 项目讲解 / 我的笔记等)。
- **AI 按需辅助**:在收藏那一刻生成摘要/分类/标签,而不是对每条流数据都调用 LLM。
- 拥有**克制而高级的视觉**——审美是硬指标。

**非目标(明确不做)**

- 不是团队协作平台:**单人使用**,不做多用户、权限、评论、分享。
- 不是云 SaaS:**本地部署**优先,零配置起步(SQLite),不追求一开始就上云端。
- 不做"社交化"的 GitHub 二次封装(关注、动态、点赞流)。
- 不追求抓取全网:数据源聚焦 Trending / Search / 手动贴链接。
- 不上过重机制:不做事件总线、插件系统、微服务(详见 [03](./03-architecture.md) 的务实边界)。

## 4. 术语表(全文通用词,以此为准)

这几个词贯穿所有文档,先记牢,尤其注意 **candidate 与 repo 是两个不同实体**。

| 术语 | 中文 | 是什么 | 关键点 |
|---|---|---|---|
| **Flow** | 流 | 抓取批次组成的时间线 | 易逝、可清理;用来快速筛 |
| **Library** | 库 | 我明确收藏、长期管理的项目资产 | 稳定;分类/标签/状态/移除 |
| **Knowledge** | 知识 | 优质项目的多角度详情文档 | 深度沉淀;暂合进库的详情页 |
| **candidate** | 候选 | 流里的**临时卡片** | 只存 GitHub 原始信息,**不含 AI 字段、不调 LLM** |
| **repo** | 收藏 | 库里的**正式项目** | candidate 收藏晋升而来;含 AI 字段与用户维护字段 |
| **batch** | 批次 | 一次抓取产生的一组 candidate | `crawl_batch`;`1──N candidate` |
| **doc** | 文档 | 挂在 repo 下的详情文档 | `repo 1──N doc`;Markdown 存储、渲染为 HTML |

关系一览:

```
crawl_batch  1 ──── N  candidate  ──(收藏晋升)──▶  repo  1 ──── N  doc
   批次                候选(临时)                  收藏(正式)      详情文档
```

三层内容模型(流 / 库 / 知识)**物理上分开存储**,各司其职。用户的核心动线是**跨层流动**:

```
流里发现  →  收藏晋升进库  →  库里点开  →  写详情文档
(candidate)     (repo)                        (doc)
```

> 三层模型的详细语义、状态机、软删除、AI 触发时机,见 [01-product-model.md](./01-product-model.md);
> 实体字段与枚举取值,见 [02-domain-model.md](./02-domain-model.md)。
