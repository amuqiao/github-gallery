# 个人 AI 知识地图

本文是个人 AI 知识库的唯一结构真源，用来承载知识地图、学习大纲、章节拆分、优先级、查漏补缺和后续重建路线。

## 1. 文档定位

这份文档解决的问题不是“旧笔记怎么归档”，而是：

```text
我未来应该按什么知识结构学习 AI？
哪些概念是地基，哪些是模型，哪些是工程，哪些是项目实践？
哪些主题是我过去反复碰壁、反复拆解、应该优先解决的？
哪些内容适合做一图流、串讲、一文读懂、源码走读或速查表？
我下一步该先补哪一块，后面按什么顺序逐个击破？
```

本文负责：

- 作为个人 AI 知识体系的唯一大纲。
- 维护领域、章节、节点、子节点、依赖关系和学习顺序。
- 标记高频卡点、建议补充、待确认缺口和重建优先级。
- 指导后续生成独立的一图流、串讲、一文读懂、源码走读、项目卡片。

本文不负责：

- 复述旧笔记。
- 索引旧文件、旧总结、链接清单或原始目录。
- 维护外部 URL 仓库。
- 决定下游展示载体的最终配置。

维护原则：

```text
知识结构先于展示形式。
本文先稳定，下游展示后派生。
旧材料只能被吸收为节点、卡点、缺口和重建建议，不能反过来污染本文结构。
```

## 2. 阅读方式

这份文档按“理解依赖”组织，不按课程目录、旧文件名或资料来源组织。

优先级含义：

| 优先级 | 含义 | 处理方式 |
|---|---|---|
| P0 | 地基卡点或高频主线，不解决会影响后续多个主题 | 第一批重建 |
| P1 | 重要分支，支撑具体模型、工程或项目 | 第二批重建 |
| P2 | 扩展主题、补充视角或暂时不阻塞主线 | 后续按需处理 |

输出形态含义：

| 形态 | 适合内容 |
|---|---|
| 一图流 | 分类树、模型结构、流程链路、概念边界、演进关系 |
| 串讲 | 多个概念必须连起来理解的主链路 |
| 一文读懂 | 稳定、重要、可独立解释的核心概念、模型、框架或项目 |
| 源码走读 | 已经进入代码、项目结构、数据流、运行链路的内容 |
| 速查表 | 名词、参数、指标、维度、API、常见误区 |
| 暂存素材 | 信息不足、价值未确认、暂时不值得正式重建的线索 |

本文分为两层：

| 层级 | 章节 | 维护方式 |
|---|---|---|
| 稳定层 | 总体知识树、总学习顺序、章节大纲、节点台账 | 尽量少改，只在知识结构确实变化时更新 |
| 执行层 | 高频卡点、查漏补缺、重建路线图、下一步 | 随重建进展更新，但必须从节点台账派生 |

覆盖口径：

```text
旧材料中的有价值内容 -> 必须落到节点台账中的某个节点
重复课程目录 / 小结 / 占位 / 临时资料 -> 不作为独立节点
项目、工具、平台、案例 -> 归入项目实践或工程生态节点
具体 URL、旧文件、旧目录 -> 不进入本文
```

本文追求“概念层完全覆盖”，不是“旧文件逐条索引”。如果以后发现某个旧主题无法落入任何节点，先补节点台账，再补章节大纲。

## 4. 稳定层：总学习顺序

主线顺序：

```text
数据与特征
-> 张量 / 维度 / 矩阵运算
-> 概率统计与机器学习任务
-> 数据处理 / Pandas / sklearn 建模流程
-> 传统机器学习基线
-> 神经网络训练闭环
-> 深度学习框架与训练代码闭环
-> CNN / RNN / Transformer 等模型架构
-> 视觉 / NLP / 时序 / 多模态 / OpenCV / 语音任务
-> 微调 / 量化 / 蒸馏 / 高效 Transformer / 推理性能
-> RAG / Agent / LangChain / MCP 工程
-> LLM 网关 / 推理服务 / Agent Runtime / 记忆工程
-> LLM 平台 / WebUI / 低代码 / 客户端交互 / 云原生部署
-> 项目源码、项目卡片与方法论沉淀
```

```text
   ├─ 梯度消失、梯度爆炸、梯度裁剪、梯度范数
   ├─ Loss NaN、anomaly detection、数值溢出
   ├─ 过拟合、欠拟合、bias-variance、早停
   ├─ 数据泄漏、类别不平衡、训练/验证分布偏移
   ├─ 训练曲线、验证曲线、指标波动、回归测试
   └─ 训练问题排查路径：数据 -> 模型 -> loss -> 优化器 -> 评估
```

训练闭环的最小必学链条：

```text
输入数据
-> 参数初始化
-> 前向传播
-> 线性变换
-> 激活函数
-> 预测输出
-> 损失函数
-> 求导 / 偏导数
-> 链式法则
-> 反向传播
-> 梯度
-> 优化器
-> 参数更新
-> 下一轮前向传播
```

这条链不要再拆散维护。后续讲激活函数、损失函数、梯度、优化器时，都必须能回到这条闭环里解释它在第几步、解决什么问题、影响哪个结果。

| 环节 | 要回答的问题 | 主归属节点 |
|---|---|---|
| 前向传播 | 数据如何从输入层一步步算出预测值？ | B2 |
| 激活函数 | 为什么线性层之间需要非线性变换？ | B1、B2 |
| 损失函数 | 预测值和真实标签之间的差距如何度量？ | B2、B4 |
| 求导 / 偏导数 | 损失对某个变量或参数的变化率是多少？ | B3 |
| 链式法则 | 多层网络里误差如何一层层传回去？ | B3 |
| 反向传播 | 如何高效计算每层参数对损失的贡献？ | B2、B3 |
| 梯度 | 参数应该朝哪个方向调整？ | B3 |
| 优化器 | 如何根据梯度、学习率和历史信息更新参数？ | B5 |
| 参数更新 | 模型如何从一次错误中变得更接近目标？ | B2、B5 |

优先级：

| 节点 | 优先级 | 推荐输出 | 掌握标准 |
|---|---|---|---|
| B2-B5 神经网络如何学习 | P0 | 串讲 | 能把前向传播、激活函数、损失函数、求导/偏导数、链式法则、反向传播、梯度、优化器、参数更新连成一条链 |
| B3 导数、偏导、梯度 | P0 | 一图流 + 大白话串讲 | 能解释“为什么沿负梯度方向更新参数” |
| B4 损失函数体系 | P0 | 对比表 | 能按任务解释为什么用这个 loss |
| B6 正则化与归一化 | P1 | 一文读懂 | 能区分数据归一化、BatchNorm、LayerNorm |
| B7 训练与推理边界 | P1 | 流程图 | 能解释训练代码和推理代码为什么不同 |
| B8 深度学习框架与训练代码闭环 | P1 | 代码流程图 + 模板 | 能从 Dataset 讲到 forward、loss、backward、optimizer、checkpoint |
| B9 训练框架封装与组件注册 | P1 | 架构图 + 模板 | 能把零散训练脚本抽象成可配置、可复用的训练框架 |

重要原则：

## 12. 维护规则

### 12.1 本文只维护结构

本文只维护知识地图、学习顺序、节点状态、缺口和优先级。具体正文、代码、图解、项目卡片可以在后续独立文档中生成，但不能反过来改变本文结构，除非本文先明确调整节点。

### 12.2 不索引外部文件

本文不维护外部文件路径、旧笔记路径、历史总结路径或链接清单。未来如果从任何旧材料中发现有价值内容，只做三件事：

```text
提炼成知识节点
标记成个人卡点
写入查漏补缺或重建路线
```

不要把来源路径搬进本文。

### 12.3 展示载体是呈现层

展示页面、专题集合、条目卡片是未来呈现方式，不是知识结构真源。

```text
本文 -> 派生展示页面
本文 -> 派生知识条目
本文 -> 派生一图流 / 一文读懂 / 源码走读

展示载体不能反向决定本文结构。
```

### 12.4 暂存素材清退规则

暂存素材不能无限期堆积。任何暂存素材只能进入三种结果：

```text
升级为正式节点
-> 合并到已有节点
-> 放弃维护
```

暂存素材如果连续两个重建阶段都没有被使用，就默认不再进入本文，只在具体成品文档需要时重新提炼。

### 12.5 先试点，再铺开

不要一次性重写所有节点。每一批只处理少量高价值节点，完成后回到本文更新状态和下一步。

推荐节奏：

```text
选 1 个 P0 节点
-> 明确前置依赖
-> 选输出形态
-> 生成独立成品
-> 回到本文更新状态
-> 再处理下一个节点
```

### 12.6 节点完成标准

一个节点不能因为“写了一篇文章”就算完成。至少满足：

- 能放回本文的知识树中，位置清楚。
- 能说清前置依赖和后续关联。
- 能解释核心概念、边界和常见误区。
- 有合适输出形态，不强行一律写成长文。
- 不依赖旧笔记目录才能理解。
