主线是：

**把这个项目稳定成一个“静态展馆内容发布系统”。**

具体说，当前主线不是继续做各种优化，而是围绕这条闭环走：

1. **内容真源稳定**
   `catalog/content/{drafts,published,archived}/<hall>/items|collections/` 是新展馆内容真源。

2. **用户心智稳定**
   用户只需要记住：
   - 用 `scripts/content.sh` 创建、查询、发布、归档、恢复内容
   - 修改生成出来的 Markdown / HTML / YAML
   - 发布前跑验证

3. **发布流程稳定**
   内容从：
   `drafts -> published -> archived -> drafts`
   必须可控、可查、可验证、可回滚。

4. **展馆骨架稳定**
   当前重点是 GitHub 展馆和模型展馆。
   音乐、电影只预留入口，不提前做复杂能力。

5. **上线前拦截错误**
   通过 `content-workflow-test.sh` 和 `verify.sh release` 把错误挡在发布前。

所以主线不是：

- 不是做完整 CMS
- 不是引入数据库
- 不是继续无限扩展字段
- 不是提前实现音乐/电影展馆
- 不是追求所有 CRUD 都做满
- 不是重构所有历史代码直到“完美”

当前主线一句话：

**让 `content.sh + catalog/content + verify/workflow test` 成为稳定、可维护、可扩展的展馆发布骨架。**

下一阶段建议也要围绕这个主线：只处理会影响“发布可靠性、用户使用心智、上线前校验”的问题。其他优化先不动。
