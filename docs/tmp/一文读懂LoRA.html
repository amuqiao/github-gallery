一文读懂 · Low-Rank Adaptation (LoRA)

冻住千亿大权重，只训练一对小矩阵

微调一个 7B 模型动辄要上百 GB 显存，还要为每个任务存一份完整副本。LoRA 用一个朴素得近乎大胆的假设，把可训练参数砍掉 99% 以上——而部署时不增加任何推理延迟。

01 · 它为什么会出现

问题：微调很贵，贵的不只是训练

假设你想让 LLaMA-7B 学会写你们公司的客服话术。传统做法是全量微调（full fine-tuning）：解冻全部 70 亿参数，用你的数据继续训练。账单如下：

训练时的显存：fp16 权重约 14 GB，但这只是开始——每个参数还要配一份梯度、Adam 优化器还要再存两份状态（动量与方差，通常是 fp32）。加起来轻松突破 100 GB，一张消费级显卡根本装不下。

存储与部署：每微调出一个任务版本，就要保存一份 完整的 14 GB 模型副本。10 个客户、10 种任务？140 GB 起步，切换任务还得整模型换入换出。

问题的本质是：我们为了改动模型的一小部分行为，付出了改动全部参数的代价。LoRA（Hu et al., 2021, 微软）针对的正是这一点。

02 · 核心机制

洞察：微调带来的改变，是"低秩"的

把微调看成给每个权重矩阵加一个增量：W' = W + ΔW。全量微调直接学这个和 W 一样大的 ΔW。而 LoRA 的出发点是一个经验观察：

预训练模型适配新任务时，权重的有效变化维度远低于矩阵本身的维度。

换句话说，ΔW 这个 4096×4096 的大矩阵，其"信息含量"可能只相当于一个秩为 8 的矩阵。既然如此，为什么不直接按低秩的形式去参数化它？任何秩 ≤ r 的矩阵都能分解为两个瘦长矩阵的乘积：

h = W₀x + ΔW·x = W₀x + (α / r) · B A x

其中 W₀ 完全冻结，只训练 B (d×r) 和 A (r×d)。参数量从 d² 降到 2dr——当 r=8、d=4096 时，是 256 倍的缩减。α 是缩放系数（后面细说）。

两个精巧的细节，决定了它"开箱即用"

① B 初始化为全零，A 用高斯随机初始化。于是训练开始的第一步，BA = 0，模型输出与原始预训练模型完全一致。微调从一个"确定无害"的起点出发，逐步学出偏移——这就是为什么 LoRA 训练非常稳定。

② 旁路是加法，不改动原计算图。x 同时流过冻结的 W₀ 和新增的 BA 两条路，结果相加。原模型一个字节都没动，所有"学到的东西"都装在 B、A 里——这为后面的合并与热切换埋下伏笔。

直觉类比：与其重新装修整栋房子（全量微调），不如保持房子原样，只在需要的地方贴一层可揭下来的"改造贴膜"（BA）。贴膜很薄（低秩），但贴对了位置就能改变房间的功能。

03 · 运行过程

从训练到部署：走一遍完整流程

点击下面的步骤，看 LoRA 在每个阶段各发生了什么——尤其注意最后两步，那是它优于其他参数高效方法的关键。

起点零扰动。B 置零、A 随机，乘积为零矩阵。此刻模型的行为与预训练模型逐比特相同——不需要"预热"或担心随机初始化破坏已有能力。

省显存的真正来源。冻结参数不需要梯度、更不需要 Adam 的动量/方差状态——这三项才是显存大头。7B 模型全量微调需要 100 GB 级别；LoRA 只需装下冻结权重 + 激活值 + 一点点适配器状态，单张 24 GB 卡就能训（配合 4-bit 量化的 QLoRA 甚至更低）。学习率通常比全量微调调大一个量级（如 1e-4 ~ 3e-4）。

部署前把增量"焊"进权重：W′ = W₀ + (α/r)·BA。这是一次离线矩阵加法，之后模型结构与原版完全相同——没有旁路、没有额外算子、零额外推理延迟。这是 LoRA 与 Adapter（串联小网络，推理必然变慢）的决定性区别。

一个基座，N 张"贴膜"。换任务时减掉旧增量、加上新增量（或干脆推理时挂旁路不合并），每个任务只需存几十 MB 的 B、A。从"每任务一个 14 GB 模型"变成"14 GB + N × 20 MB"。这也是 Stable Diffusion 社区风格 LoRA 满天飞的原因——分享一个画风只需传一个小文件。

04 · 实践中怎么调

三个真正需要决定的超参数

秩 r：增量的"表达容量"

常用 4 ~ 64。原论文发现 r=1~4 在很多任务上已接近全量微调效果——这本身就是"低秩假设"成立的证据。经验法则：任务越偏"改变风格/格式/遵循指令"，小 r 越够用；越偏"学新领域、新语言"，需要越大的 r。r 加倍，参数加倍，但效果往往很快饱和，先从 8 或 16 试起。

α（lora_alpha）：增量的"音量旋钮"

实际生效的增量是 (α/r)·BA。固定 α/r 的比值，调 r 时就不必重调学习率。常见约定 α = 2r（如 r=16, α=32）。把 α/r 调大等价于放大 LoRA 的影响力。

挂在哪些层（target_modules）

原论文只挂注意力的 q_proj、v_proj 就取得了好结果；后续实践（如 QLoRA 论文）表明挂所有线性层（q/k/v/o + MLP 的 up/down/gate）通常更好，参数量依然很小。预算紧张时，优先保 q、v。

05 · 放进坐标系

和邻居们比一比

方法思路可训练参数额外推理延迟典型短板
Full Fine-tuning 解冻全部权重直接训 100% 无 显存/存储爆炸；小数据易灾难性遗忘
LoRA 冻结 W，训练低秩增量 BA ~0.1–1% 无（可合并） 大规模注入新知识时容量受限
Adapter 层间串联小瓶颈网络 ~1–5% 有（串联无法合并） 推理变慢，batch 小的时候尤其明显
Prefix / Prompt Tuning 只学一段可训练的虚拟前缀向量 <0.1% 占用上下文窗口 优化不稳定；能力上限较低
QLoRA 基座量化到 4-bit + LoRA ~0.1–1% 无 量化引入微小精度损失

一句话定位：LoRA 占住了"参数少、部署零开销、训练稳定"这个甜蜜点，所以成了参数高效微调（PEFT）的事实默认选项。QLoRA 是它的显存极限版——48 GB 单卡微调 65B 模型即出自该论文。

06 · 误区 · 反例 · 边界

什么时候不该指望 LoRA

点开每一条——理解边界比记住结论更重要。

▶误区一："LoRA 能让模型学会任何全量微调能学的东西"

不能。低秩是一个硬约束：增量 ΔW 的秩被限制在 r 以内。改变风格、语气、输出格式、指令遵循方式——这类"重定向已有能力"的任务是低秩的，LoRA 表现极好。但要让模型吸收大量全新知识（比如从头学一门语料里没见过的语言、灌入整个私有知识库），所需的权重变化可能不是低秩的，LoRA 会明显落后于全量微调。

反例式的判断法：如果你的需求更像"教模型怎么说"，用 LoRA；如果更像"教模型知道什么"，优先考虑 RAG 或全量/更大 r 的微调。

▶误区二："r 越大效果越好，往大了调准没错"

实验反复表明效果随 r 很快饱和，r 从 8 加到 256 常常只带来噪声级差异，却让适配器大 32 倍。更大的 r 还意味着更强的拟合能力——在小数据集上更容易过拟合。先小后大、盯验证集，比一上来堆 r 明智得多。

▶误区三："LoRA 是模型压缩/加速技术"

常见混淆。LoRA 压缩的是微调增量，不是模型本身：基座 14 GB 一个字节没少，推理速度也不变（合并后与原模型相同）。想让模型变小变快，那是量化、剪枝、蒸馏的领域。LoRA 省的是训练显存和每任务的存储。

▶误区四："挂了 LoRA 推理会变慢"

取决于部署方式。合并后零开销——这是设计目标。不合并、以旁路形式推理会多一点计算（换来热切换多任务的灵活性，vLLM 等框架的 multi-LoRA serving 就是这么做的，可以在同一批次里同时服务不同任务的请求）。"是否合并"是一个延迟 vs 灵活性的显式取舍，而不是缺陷。

▶误区五："训练稳定 = 不会灾难性遗忘"

LoRA 因为动的参数少，遗忘通常比全量微调轻，但不是免疫。α/r 调得激进、数据分布很窄时，合并后的模型照样可能在通用能力上退化。好在解药便宜：不满意就把增量减掉，基座毫发无损——这是全量微调给不了的"后悔药"。

07 · 最小可验证例子

十几行代码，亲眼看到 0.06%

用 Hugging Face 的 peft 库，把上面的一切落到可运行的代码上。重点看最后一行的输出——它就是本文的全部主张：

# pip install transformers peft
from transformers import AutoModelForCausalLM
from peft import LoraConfig, get_peft_model

model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-2-7b-hf")

config = LoraConfig(
    r=8,                          # 秩：增量的容量
    lora_alpha=16,                # 缩放：生效强度 = alpha/r
    target_modules=["q_proj", "v_proj"],  # 挂在哪些层
    lora_dropout=0.05,
    task_type="CAUSAL_LM",
)

model = get_peft_model(model, config)   # 冻结基座，注入 B、A
model.print_trainable_parameters()
# trainable params: 4,194,304 || all params: 6,742,609,920
# || trainable%: 0.0622   ← 只训练 0.06% 的参数

之后接任何普通的训练循环或 Trainer 即可。训练完 model.save_pretrained() 只会保存几十 MB 的适配器；部署时 model.merge_and_unload() 一行完成第 ③ 步的合并。

08 · 带走的心智模型

一句话，和它能去的地方

冻结昂贵的通用能力，把任务专属的改变参数化成一个便宜的低秩增量，用完可合并、可卸载、可叠加。

握住这个模型，很多现象会自动变得可解释：

· 为什么 Stable Diffusion 的画风 LoRA 只有几十 MB——画风是"重定向已有能力"，天然低秩；LoRA 挂在 U-Net/DiT 的注意力层上，原理与 LLM 完全相同。
· 为什么可以把两个 LoRA 加权混合出新风格——增量是加法旁路，线性可组合。
· 为什么 QLoRA、DoRA、AdaLoRA 层出不穷——它们分别在"基座怎么存（量化）""增量怎么分解（方向×幅度）""r 怎么按层分配"这几个自由度上做文章，主线从未改变。

下次遇到"想定制一个大模型但资源有限"的场景，先问三个问题：我要改的是能力还是知识？增量大概是不是低秩的？部署时需不需要热切换？——答案会直接告诉你 LoRA 适不适合，以及 r 该从多大开始。
