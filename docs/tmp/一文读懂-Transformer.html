一文读懂 · Attention Is All You Need (2017)

Transformer:
把"序列"这件事,全部交给注意力

2017 年,Google 的 8 位作者为机器翻译提出了一个不含任何循环和卷积的架构:序列里任意两个位置直接互相"看",一步到位。它当时只是一个 65M 参数的翻译模型,后来成了 BERT、GPT 以及几乎所有大模型的公共骨架。下面这个动画就是它的本职工作——注视源句,逐词生成译文。

DEMO · En→De 翻译,自回归生成中弧线 = cross-attention 权重(示意)
源句(一次性全部输入 Encoder)
译文(Decoder 逐 token 生成,每个新词都回看整个源句)
生成到句尾后自动重播;权重为人工示意,真实值需跑模型
TASK序列到序列转换原始任务是翻译;本质是"读一个 token 序列,写另一个 token 序列"
INPUT / OUTPUTtoken id 序列 → 下一个 token 的概率输入 (B, n) 整数;每步输出 (B, vocab) 分布,循环采样
核心机制Self-Attention任意两位置一步直连,路径长度 O(1);顺序信息全靠位置编码补入
规格(base)65M 参数6 层 Encoder + 6 层 Decoder,d_model=512,8 头;8 卡 P100 训 12 小时
01 · WHY

它解决什么问题:为什么 2017 年需要一个新架构

论文标题里的 "All You Need" 是对着当时的主流架构说的。2017 年做翻译的标准配方是 RNN(LSTM/GRU)+ attention:编码器逐词读入源句,解码器逐词写出译文,attention 只是辅助对齐的配菜。这套配方有三个结构性的痛点:

  • 无法并行训练:RNN 的第 t 步必须等第 t−1 步算完。句子越长,GPU 越闲——序列长度方向完全串行。
  • 长程依赖会衰减:句首信息要穿过整条循环链才能影响句尾,路径长度 O(n),隔 50 个词的指代关系很难学。
  • 信息瓶颈:早期 seq2seq 把整句压进一个固定向量;attention 缓解了它,但主干仍是循环。

Transformer 的回答很激进:把配菜变成主菜,循环和卷积全部删掉。序列里每个位置通过 self-attention 直接读取所有其他位置,任意依赖的路径长度都是 O(1),整个序列在训练时一次矩阵乘法并行算完。代价是计算量随序列长度平方增长——这个取舍到今天仍在(见第 06 节)。

输入是什么

  • 文本先经 BPE 子词切分变成整数 id 序列(原论文英德共享 37 000 词表)
  • 模型真正的输入:形状 (B, n) 的整数张量,B 是批大小,n 是 token 数
  • 没有任何"顺序"概念内建在结构里——顺序由位置编码显式加入

输出是什么

  • 每个位置一个 词表上的概率分布 (B, m, vocab)
  • 推理时只取最后一个位置的分布,选出下一个 token,拼回输入,循环直到 <eos>
  • 所以严格说它不是"输出一句话",而是反复输出"下一个词是什么"
边界先说清:本文讲的是 2017 年原版 Encoder–Decoder Transformer(翻译模型)。BERT 只取了左塔,GPT 只取了右塔,它们是后代而不是同义词——第 06 节会把这张家谱摊开。

核心数据流:一句话进,一个词出

下图是原论文架构图的"可点击版":左塔 Encoder 一次性消化整个源句,右塔 Decoder 逐词生成译文。点击步骤(或按 ← →)追踪数据,面板给出每一步的张量形状——以 "The cat sat on the mat"(6 个 token)翻译到第 3 个德语词为例,base 规格 d_model=512、8 头。

看懂这张图的关键一句话:Encoder 是"一次成像",Decoder 是"逐帧作画"。左塔对源句只算一次;右塔每生成一个新词,都带着已写出的译文重新走一遍三个子层,其中 Cross-Attention 那一层回头注视源句——这正是首屏动画里那些弧线。

03 · ATTENTION

把 Attention 拆开:一次"可微分的查字典"

Attention(Q, K, V) = softmax( QKᵀ / √dk ) · V

每个 token 的向量各自乘三个可学习矩阵,得到三种身份:Q(query)——我在找什么;K(key)——我可以被怎样找到;V(value)——找到我后实际取走的内容。QKᵀ 算出每对 token 的匹配分,softmax 归一化成权重,再对 V 加权求和。整个过程就是一次软性的、可微分的字典查询:不是命中一条记录,而是按相关度混合所有记录。

亲手点一点:词与词在"看"谁

下面这句是论文作者演示时的经典例句。点击任意 token,弧线粗细 = 注意力权重大小;切换两个"头"体会 multi-head 的含义——同一层里不同的头,学到的是完全不同的关系(权重为人工示意)。

试试点击 it —— 它指代的是 animal 还是 street?

这个例子回答了"为什么翻译需要它":把 "it" 译成 "es/sie/er"(德语代词分性别)之前,模型必须先解析出 it → animal。RNN 要跨 6 步传递这个信息,self-attention 一步直达。Multi-head 则是把 512 维切成 8 份、每份 64 维各自做一遍注意力再拼接——让"指代头""邻接头""句法头"并存,互不打架。

04 · TRAIN vs INFER

训练时学什么,推理时算什么

Transformer 最容易被忽略的一点:它在训练和推理时的运行方式完全不同。训练是全并行的"批改整张卷子",推理是串行的"一个字一个字写作文"。

训练时不需要真的"逐词生成"。把完整的正确译文右移一位喂给 Decoder(开头补 <bos>),因果掩码保证位置 i 只能看见 ≤ i 的词,于是所有位置的"预测下一词"可以在一次前向里并行计算——这就是 teacher forcing,也是 Transformer 训练快的全部秘密。

  • 学的目标:每个位置对下一个 token 的交叉熵,配 label smoothing 0.1(故意不让模型把概率押满,BLEU 更好)。
  • 学到的参数:embedding(输入、输出、softmax 前投影三处共享权重)、每层的 Q/K/V/O 投影、FFN、LayerNorm——base 共约 65M。
  • 数据:WMT14 英德 450 万句对 / 英法 3600 万句对,BPE 共享词表。
  • 训练成本(2017 年):base 8×P100 约 12 小时;big(213M 参数)约 3.5 天——相比当时 RNN 动辄数周,这是论文轰动的原因之一。
  • 学习率不是常数:先线性升温 4000 步再按步数的 −0.5 次方衰减(下图)。没有 warmup,post-LN 结构在训练初期很容易发散——这是复现踩坑率最高的一条。

lrate = d_model⁻⁰·⁵ · min(step⁻⁰·⁵, step · warmup⁻¹·⁵),warmup = 4000

推理时没有正确答案可以喂,Decoder 必须吃自己上一步的输出:

  • 循环:Encoder 对源句只算一次;之后每一步,Decoder 带着已生成序列前向一遍,取最后位置的分布,选词,拼回,直到 <eos>。生成 m 个词 = m 次 Decoder 前向。
  • beam search:原论文用 beam=4、长度惩罚 α=0.6,同时保留 4 条候选路径,比贪心稳定地高约 1 BLEU。
  • KV cache:朴素实现每步都重算历史 token 的 K/V,复杂度 O(m²);把它们缓存下来每步只算新 token,是后来所有大模型推理的标配。代价是显存随上下文线性增长。
  • 确定性:greedy/beam 是确定的;带温度采样则每次不同——"同一个模型两次答案不一样"通常是采样策略而非模型的问题。
训练并行、推理串行,这个不对称是理解今天所有 LLM 性能问题的钥匙:为什么"首 token 慢"(要算整段 prompt 的 attention)、为什么"长上下文贵"(KV cache 吃显存)、为什么有投机解码(想把串行变回并行)。根源全在 2017 年这张图里。

05 · HANDS-ON

十行代码摸到核心:最小可验证示例

import torch, math

def attention(q, k, v, mask=None):
    scores = q @ k.transpose(-2, -1) / math.sqrt(q.size(-1))
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float("-inf"))
    return torch.softmax(scores, dim=-1) @ v

B, h, n, dk = 1, 8, 6, 64                      # batch=1, 8 头, 6 个 token
q = k = v = torch.randn(B, h, n, dk)
print(attention(q, k, v).shape)              # torch.Size([1, 8, 6, 64])

# 因果掩码:下三角为 1,位置 i 只能看 ≤ i(Decoder 用)
mask = torch.tril(torch.ones(n, n))
out = attention(q, k, v, mask)

# 自检:第 0 个位置的输出应当只由第 0 个位置的 v 决定
print(torch.allclose(out[0, 0, 0], v[0, 0, 0], atol=1e-5))   # True

整个 Transformer 的"魔法"就这 5 行函数,其余都是围绕它的工程:投影、拼头、残差、归一化。最后那行 allclose 自检值得亲手跑一次——它验证了因果掩码真的挡住了未来。

import torch
import torch.nn as nn

model = nn.Transformer(                # PyTorch 内置的原论文架构
    d_model=512, nhead=8,
    num_encoder_layers=6, num_decoder_layers=6,
    dim_feedforward=2048, dropout=0.1, batch_first=True)

src = torch.rand(1, 6, 512)            # 源句 6 token(此处用随机向量代替 embedding)
tgt = torch.rand(1, 3, 512)            # 已生成 3 token
causal = nn.Transformer.generate_square_subsequent_mask(3)

out = model(src, tgt, tgt_mask=causal) # (1, 3, 512):再接 Linear→vocab 即得 logits
print(out.shape, sum(p.numel() for p in model.parameters()))
# torch.Size([1, 3, 512])  44140544 ≈ 44M(不含 embedding 与输出层)

注意 nn.Transformer 不含 embedding、位置编码和输出投影,需要自己包一层——这三块加上去正好对上论文的 65M(见下一个 tab)。想直接用现成翻译模型,可用 Hugging Face 的 Helsinki-NLP/opus-mt-en-de 或 t5-small,两者都是这套 encoder–decoder 骨架的直系后代。

65M 参数从哪来?按 base 规格逐项对账(约数),读懂这张表就读懂了模型文件里都存了什么:

模块计算式参数量
共享 Embedding(输入×2 + 输出投影)37 000 × 512,三处共享一份≈ 19.0M
每层 Encoder:自注意力 Q/K/V/O4 × 512 × 512≈ 1.05M
每层 Encoder:FFN2 × 512 × 2048≈ 2.10M
Encoder 小计≈ 3.15M × 6 层≈ 18.9M
Decoder 小计(多一个 cross-attn)≈ 4.20M × 6 层≈ 25.2M
合计19.0 + 18.9 + 25.2 + 零头≈ 65M ✓

两个值得记住的比例:FFN 占每层参数的约 2/3(后来 MoE 稀疏化的正是它);正弦位置编码零参数,纯公式计算。

06 · BOUNDARIES

对比、家谱与常见误区

和它取代的架构比(论文 Table 1 的白话版)

架构每层计算量可并行度(串行步数)任意两词的信息路径一句话
RNN / LSTMO(n · d²)O(n) 逐步串行O(n)长句训练慢、远距离关系学不动

看清这张表就看清了本质取舍:Transformer 不是计算量更小,而是把计算变成了 GPU 最擅长的稠密矩阵乘,且互相不等待。当年在 WMT14 En→De 上,base 27.3 BLEU、big 28.4 BLEU,超过包括 GNMT、ConvS2S 在内的所有前作与集成模型,训练成本却只是零头。

一张家谱:后来的模型各取走了哪一半

形态取了什么代表擅长
Encoder–Decoder(原版)双塔 + cross-attention原始 Transformer、T5、BART、Whisper翻译、摘要等"读 A 写 B"的转换任务
Encoder-only只留左塔,双向注意力BERT、RoBERTa、各类 embedding 模型理解、检索、分类——只需表示不需生成
Decoder-only只留右塔(去掉 cross-attn)GPT 系、LLaMA、几乎所有现代 LLM开放式生成;把一切任务改写成"续写"

现代 LLM 相对 2017 原版的主要改动清单,可以当"考古对照表"用:post-LN → pre-LN(深层稳定)、正弦位置编码 → RoPE/ALiBi(长度外推)、ReLU → SwiGLU、多头 → GQA/MQA(省 KV cache)、以及 FlashAttention 等 IO 感知实现。骨架没变,变的全是让它"更深、更长、更省"的细节。

适合用 / 借鉴它,当你…

  • 做任何序列转换或序列建模:文本、代码、语音、蛋白质、时间序列
  • 数据充足(百万级样本或可做预训练迁移),追求可扩展性——它的 scaling 性质经过了最充分验证
  • 需要"读 A 写 B"且输入输出差异大:encoder–decoder 形态仍是翻译/摘要/ASR 的强基线
  • 想借鉴的单点:残差 + 归一化的堆叠范式、QKV 抽象、warmup 调度、teacher forcing 训练法

不适合(原始形态),当你…

  • 序列极长(十万 token 级):O(n²) 注意力吃不消,需换稀疏/线性注意力或 SSM(如 Mamba)
  • 数据很少又不能预训练:它几乎没有归纳偏置,小数据上常不如 CNN/RNN 甚至特征工程
  • 严格流式、低延迟、端侧算力极小:自回归 + 全序列注意力天然不友好
  • 把 2017 原版超参照搬到深层模型:post-LN + 不当 warmup 大概率发散

常见误区(点开自查)

误区一:"attention 机制是这篇论文发明的"

不是。attention 由 Bahdanau 等人在 2014 年为 RNN 翻译模型提出,2017 年时已是标配。这篇论文的贡献是把 "attention 作为辅助" 推到 "attention 是全部"(标题的本意):删掉循环后依然成立,而且更好。读文献时把 "attention" 和 "Transformer" 当同义词会错乱时间线。

误区二:"Transformer 天然理解词序"

恰恰相反,self-attention 对输入是置换等变的——打乱 token 顺序,输出跟着同样打乱,模型毫无察觉。顺序信息 100% 来自显式加入的位置编码。删掉 PE,它就退化成一个高级词袋模型。这也是为什么位置编码方案(正弦 / 可学习 / RoPE / ALiBi)成了后续研究的富矿。

误区三:"Transformer 快,是因为计算量小"

它每层计算量是 O(n²·d),序列一长比 RNN 的 O(n·d²) 更贵。快的真正原因是并行:没有时间步依赖,整个序列一次矩阵乘完成,GPU 利用率天差地别。"计算量更大但墙钟时间更短",这是理解现代硬件协同设计的第一课。

误区四:"训练能并行,所以生成也快"

并行只属于训练(teacher forcing 喂的是完整答案)。推理必须等上一个 token 出来才能算下一个,严格串行。今天 LLM 推理的所有工程苦役——KV cache、投机解码、continuous batching——都是在跟这个串行性搏斗。

误区五:"照着论文复现就能训出来"

原版是 post-LN(LayerNorm 在残差之后),对学习率极其敏感:不做 warmup 或层数加深,很容易 loss 爆炸。后续研究(如 Xiong et al. 2020)证明 pre-LN 稳定得多,这也是现代实现的默认。复现失败时,第一查 warmup,第二查 LN 位置,第三查 label smoothing。

误区六:"Transformer = 大语言模型"

原版只是一个 65M 参数、只会英德/英法翻译的模型,没有海量预训练,没有涌现能力。LLM = Transformer 骨架(通常只取 decoder)+ 海量自监督数据 + 规模定律 + 对齐训练。架构是必要条件,远非充分条件——这也是判断"下一个架构能否取代它"时应有的参照系。

07 · TL;DR

带走这五句话

  • 任务:原版 Transformer 是翻译模型——token 序列进,"下一个 token 的概率"反复出;Encoder 一次读完源句,Decoder 自回归写译文。
  • 机制:self-attention = 可微分的软查字典,QKᵀ/√d_k 配 softmax;multi-head 让多种关系并存;顺序全靠位置编码补入。
  • 本质取舍:用 O(n²) 的计算换来 O(1) 的信息路径和完全并行——对 GPU 极度友好,对超长序列先天吃力。
  • 训练≠推理:训练靠 teacher forcing 全并行,推理逐 token 串行;warmup、post-LN、label smoothing 是复现三大坑。
  • 家谱:BERT 取左塔做理解,GPT 取右塔做生成,T5/Whisper 保留双塔做转换;今天的一切改进(RoPE、GQA、FlashAttention)都是在这副骨架上换零件。
