PROBLEM / 问题与边界

它解决什么、不解决什么：三兄弟分清楚

先看需求现场。一段两小时的项目会议录音，ASR（语音识别）能给你一整墙没有段落的文字——但会议纪要需要的是"张三说要延期，李四反对"；客服质检要区分坐席和客户各说了什么；多人播客要给字幕标上说话人。所有这些场景缺的是同一块拼图：把连续音频按"说话人身份"切开，输出一张"谁在何时说话"的时间表。这就是 speaker diarization（说话人分割/说话人日志，diarization 源自 diary——给录音记日志）。

边界必须先立牌子，因为它有两个长得很像的邻居，混用是这个领域最高频的沟通事故：

任务回答的问题需要预先注册声纹吗输出典型场景
Speaker Diarization谁在何时说话（who spoke when）不需要——根本不知道说话人是谁时间段 + 匿名标签（spk0, spk1…）会议纪要、播客字幕、多说话人 ASR 的前置
Speaker Verification这段话是不是某个特定的人（1:1 比对）需要（那个人的注册音）是 / 否 + 置信分声纹解锁、电话银行身份核验
Speaker Identification这段话是库里的哪一个人（1:N 检索）需要（N 个人的注册库）某个具体身份（或"库外"）"找出小王的所有发言"、司法比对
ASR（语音识别）说了什么不需要文字转写、字幕

三个立刻可用的推论：

  • diarization 的输出没有名字。spk0 只是"第 0 个聚出来的人"；想变成"张三"，要拿张三的注册声纹对每个匿名簇再做一次 identification（业内叫 speaker linking / 声纹映射），那是叠加在 diarization 之上的第二个任务。
  • 它和 ASR 是正交的。diarization 不听内容（text-independent），ASR 不看声纹；"带说话人的转写"= 两者输出在时间轴上做词级对齐，或者用近年的联合模型一次出。
  • 说话人数通常未知。verification/identification 的 N 是已知的；diarization 面对的录音里几个人，往往要它自己猜——这是它独有的、也是最难的约束，第 3 章会看到这件事如何主宰调参。
pipe

PIPELINE / 核心机制

流水线：每一步为什么必须存在

首屏那四副眼镜就是经典的聚类式流水线（cascaded / clustering-based），至今仍是生产系统的主力骨架。把因果链说透：

  1. VAD（Voice Activity Detection，语音活动检测）——先把静音、音乐、键盘声扔掉。为什么必须第一个上？因为后面的一切都建立在"这一段是人声"之上：把静音送去提声纹，得到的是毫无意义的点，白白污染聚类；而漏掉的人声后面任何一步都救不回来。VAD 的错误直接原样计入最终指标（第 4 章的 miss 和 false alarm）。
  2. 切片（segmentation）——把人声区域切成 0.5～3 秒的小窗（定长滑窗是主流；也可先用说话人变化点检测切不定长段）。为什么要切？因为"谁在说话"随时间变化，必须小到"一窗之内大概率只有一个人"，判断才有意义。
  3. 声纹嵌入（speaker embedding）——核心一跳：用一个预训练神经网络（x-vector、ECAPA-TDNN、ResNet 系）把每个小窗映射成一个 192～512 维向量，训练目标是同一人的向量彼此靠近、不同人的彼此远离（大规模说话人分类 + margin 损失练出来的）。这一步把"听起来像不像同一个人"这个玄学问题，翻译成了"两点距离近不近"这个几何问题——与说话内容无关，只留声纹特征。
  4. 聚类（clustering）——嵌入点摆进空间后，同一人的点天然抱团。常用凝聚层次聚类（AHC，按余弦距离逐步合并，距离阈值决定停在几类）或谱聚类。类数 = 说话人数——未知人数的难题，就这样被转嫁给了"阈值怎么定"。
  5. 重分割 / 后处理（resegmentation）——聚类是逐窗投票，边界只有窗口那么粗；用 VB-HMM（VBx）之类的模型按帧重新平滑标签、修边界、吸收孤立的错窗，再合并相邻同类窗成段，输出 RTTM 格式的时间表。

一句话总结机制：嵌入负责"把相似变成距离"，聚类负责"把距离变成身份"。整条流水线的成败，几乎都压在这两步的配合上——所以下一章把它们做成实验台，让你亲手把它调坏、再调好。

边界补充：与聚类式并行的另一范式是端到端 EEND（把 diarization 当成"每帧 × 每人"的多标签分类，天然吃重叠），第 5 章作为重叠问题的解法一并介绍。现代生产系统常是两者的混血（如 EEND 出局部结果 + 聚类做全局归并）。

EMBEDDING & CLUSTERING / 交互核心

实验台：亲手把聚类调坏，再调好

还是首屏那段 60 秒三人录音。左图是每个小窗的声纹嵌入投到二维后的散点（真实系统是几百维，几何直觉相同），右边是按聚类结果上色的时间轴。两个旋钮决定生死：

  • 窗长：窗越长，一窗内语音越多，嵌入越稳（点越紧）；但时间分辨率越粗，而且更容易一窗跨两人。窗越短反过来——点会明显发散，因为半秒的语音撑不起一个可靠的声纹估计。
  • AHC 距离阈值：两簇平均距离小于它就合并。阈值太大 → 不同人被并成一类（混淆飙升）；太小 → 同一人被拆成好几类。这是"说话人数未知"的难题最终落地的地方。

照着故障按钮走一遍：① 短窗发散——L=0.5s 时三团点糊成一片，就算把 τ 调到最优也留下两位数的混淆，这就是"短片段嵌入不稳"；② 阈值过松——τ=3.7 时两团被并掉，只剩 2 类，被并的那个人整段变成混淆；③ 阈值过紧——τ=1.0 拆出十来类，同一人的发言被标成好几个"不同的人"。还有一个值得留意的细节：把 L 拨到 2s，原来健康的 τ=2.4 又多聚出一类——最优阈值随窗长、信道等条件漂移，这正是它难伺候的地方。再注意一个救不掉的底：重叠区（散点里游离在两团之间的那些点）无论怎么调都贡献错误——一个窗里混着两个人的声音，嵌入落在两个质心之间，单标签聚类怎么标都至少亏一半。这就是第 5 章的主题。

把实验台的体感翻译成工程语言：窗长是"时间分辨率 vs 嵌入稳定性"的拍卖（生产常用 1.5–2s 窗、0.5–0.75s 步移的滑窗折中）；阈值是"说话人数先验"的化身——如果业务能拿到真实人数（如双人客服通话恒为 2），直接把聚类钉死在 k=2，DER 立刻显著下降。凡是能把未知变已知的先验，都值得喂给系统。

DER

METRIC / 度量

DER：错误如何被记账

实验台右下角那个分数现在正式立户。DER（Diarization Error Rate）按时间记账，把错误分成三种，除以参考标注里的语音总时长：

DER = ( 漏检 miss + 误报 false alarm + 说话人混淆 confusion ) / 参考语音总时长

  • 漏检 miss：有人在说，系统说没人（或重叠时只标出了其中一人）——主要来自 VAD 漏检和重叠；
  • 误报 false alarm：没人在说，系统说有人——来自 VAD 误报；
  • 混淆 confusion：说对了"有人"，但标错了"是谁"——来自聚类/分割错误。

还有一个容易忽略的前置步骤：系统的 spk0/spk1 和标注的 A/B/C 本来对不上号，评测先用匈牙利算法找一个对系统最有利的标签映射，再算错误——所以 DER 惩罚的是"分错人"，不是"编号不同"。

最后校准一下期望值：干净的双人电话（CallHome 类）DER 能到 5% 以下；嘈杂多人真实会议（AMI、DIHARD 类）10–25% 都属正常。DER 也不是全部——它按时长加权，说得少的人错光了也影响不大，所以补充指标 JER（按说话人平均）和"说话人计数是否正确"在应用里同样致命：纪要系统把 3 个人算成 5 个，用户不会去看 DER 有多好。

ovl

OVERLAP / 天花板

重叠语音：单标签范式的地板，端到端的起点

真实对话不排队。插话、抢话、附和（"对对对"）让真实会议里 10–20% 的语音时长是两人以上同时在说。而聚类式流水线有个先天设定：每个时刻只发一个标签——一窗一个嵌入、一个嵌入一个簇。于是重叠区无论标谁，另一个人都自动计入 miss。这不是实现不好，是范式的地板。

重叠区的账：单标签 vs 重叠感知

回答的问题：就算聚类全对，单标签系统的 DER 下界是多少？重叠感知系统赢在哪里？

REFERENCE：A 说 0–10s，B 从 6s 插话到 14s（6–10s 两人同时说）

HYPOTHESIS

逐帧记账

单标签这边已经是"最优解"了——6–8s 判给 A、8–10s 判给 B，尽量雨露均沾——重叠的 4 秒里仍然每一帧都欠一个人：miss = 4s，DER 下界 = 4 / 18 ≈ 22%，怎么调参都到不了 0。切到重叠感知：同一时刻允许两个标签，账面清零。

怎么破：从打补丁到换范式

  • 聚类式打补丁：先跑一个重叠检测器（OSD）找出多人区，再把这些区域的"第二说话人"指派给最近的簇。工程上有效，但精度受限于两阶段误差累积。
  • 换范式——EEND（End-to-End Neural Diarization）：把 diarization 改写成逐帧 × 逐说话人的多标签二分类：网络对每一帧输出"说话人 1 在说吗？说话人 2 在说吗？…"，重叠只是"两个输出同时为 1"，天然无地板。代价是新的难题：输出维度绑死了最大说话人数、训练要解决"网络的第 1 号输出对应谁"的排列问题（PIT，排列不变训练）、长录音与很多人时吃力。
  • 混血（当前主流）：EEND 在短滑窗内做局部的重叠感知分割，再用聚类把各窗的局部说话人全局归并（EEND-VC、pyannote 3.x 的思路）——局部要精细用神经网络，全局要开放人数用聚类，各取所长。

取舍一句话：录音重叠少、人数完全未知、时长很长 → 聚类式稳；重叠多、人数有上限（会议、访谈）→ 重叠感知/混血必上。选型先问一句"我的数据里重叠占多少"，比看任何 benchmark 都有用。

MISCONCEPTIONS / 常见误区

常见误区与反例

每张卡片的标题是一个流传很广的错误说法（✕），点开看正确版本（✓）和一个能当场戳破它的反例。

"diarization 能告诉我说话的是谁"

它只输出匿名聚类标签。spk0 的含义是"第 0 团点"，与任何真实身份无关。要名字，得叠加 speaker identification：拿目标人的注册声纹和每个簇的质心比对（speaker linking）。

反例：同一个人出现在两个文件里，一个文件里叫 spk0，另一个里叫 spk2——标签在文件之间没有任何一致性，跨文件追踪同一人是另一个独立任务（speaker linking / global diarization）。

"先 ASR 转成文字，再分说话人更简单"

ASR 输出的文字里不携带声纹信息，"这句话听起来是谁的嗓音"在转写那一刻就丢失了。正确的架构是并行：diarization 给时间轴上的身份，ASR 给时间轴上的词，再做词级时间对齐把两者缝合（或用联合训练的多说话人 ASR 一步到位）。

反例：两个人语言风格接近的访谈，纯文本连人类都分不出说话人切换点；而 diarization 靠声纹在文本完全相同的情况下照样能分——信息通道根本不同。

"DER 5% 就是好系统，20% 就是烂系统"

DER 只有在同数据、同 collar、同重叠计分规则下才可比。电话双人 5% 和嘈杂晚宴录音（DIHARD）20% 可能是同一水平的技术；collar 0.25s + 忽略重叠的 5%，换成严格计分可能翻倍。而且 DER 按时长加权，抓不住"人数数错"这种对产品致命的错误。

反例：第 4 章"边界抖动"档——观感几乎完美的输出，collar=0 时 DER 两位数；勾上 collar 立刻接近 0。同一份输出，两个数字。

"说话人数让模型自己定就行，不用管"

未知人数是聚类式流水线最脆弱的一环——它被压缩成一个距离阈值，而阈值对录音条件（信道、噪声、时长）敏感。任何可用的人数先验都应该喂进去：已知恰好 k 人就钉死 k，已知上限就限制最大簇数。

反例：第 3 章实验台，τ 从 2.4 拨到 3.7，三个人变两个人；而把窗长从 1.5s 换成 2s，原本健康的 τ 又开始拆人——最优阈值随录音条件漂移。而把 k 固定为 3 后，这个自由度直接消失。

"声纹嵌入只反映'这个人是谁'，很纯净"

理想上 text-independent、只编码嗓音；实际上短片段统计不足、情绪/语速、远场混响、信道（手机 vs 会议麦）都会让嵌入漂移。跨信道时，"同一人两种设备"的距离可能大于"同一设备两个人"。

反例：第 3 章把窗长拨到 0.5s——同一个人的点云直接散成一片雾，和邻团粘连。这不是模型坏了，是半秒语音在信息量上撑不起可靠的声纹估计。

"重叠语音是少数情况，先忽略没关系"

真实多人对话里重叠占语音时长 10–20% 甚至更高（插话、附和、抢话）。对单标签系统这直接是 DER 的不可修复地板；对下游更糟——重叠区的 ASR 文本本来就容易错，再配上错误的说话人标签，纪要里会出现"张三说了李四的话"。

反例：第 5 章的账——两人各说几秒、重叠 4 秒的小片段，单标签最优解 DER 也有 22%。把这个比例乘回两小时会议，就是几分钟被系统性记错账的内容。

"VAD 只是个预处理，随便用用"

VAD 的错误是唯一没有任何后续步骤能修复的错误：漏掉的语音不会再被嵌入和聚类看到（miss 直接落账），放进来的噪声会变成假的"说话人"污染聚类（false alarm + 可能多聚出一类）。很多系统 DER 的一半以上其实是 VAD 贡献的。

反例：把一段有背景音乐的录音喂给宽松的 VAD——音乐被当成语音提了嵌入，聚类多出一个"幽灵说话人"，混淆和误报同时上涨；换一个好 VAD，什么都没调，DER 掉了三分之一。

from pyannote.audio import Pipeline

pipeline = Pipeline.from_pretrained(
    "pyannote/speaker-diarization-3.1",
    use_auth_token="HF_TOKEN")          # 需在 HuggingFace 接受模型条款

# 人数未知就都不传；有先验一定要传——DER 会明显受益
diar = pipeline("meeting.wav")                       # 自动估计人数
# diar = pipeline("call.wav", num_speakers=2)        # 已知恰好 2 人
# diar = pipeline("panel.wav", min_speakers=2, max_speakers=6)

for turn, _, spk in diar.itertracks(yield_label=True):
    print(f"{turn.start:6.1f}s – {turn.end:6.1f}s  {spk}")

8.3 评测：DER 别自己手搓

python · pyannote.metrics 计算 DER（含 collar 与标签映射）
from pyannote.metrics.diarization import DiarizationErrorRate

metric = DiarizationErrorRate(collar=0.5, skip_overlap=False)
# collar=0.5 即边界两侧各 0.25s 不记账；skip_overlap 决定重叠区计不计分
# —— 报告 DER 必须同时注明这两个参数，否则数字不可比

der = metric(reference, hypothesis)      # 内部自动做最优标签映射（匈牙利）
print(metric["missed detection"], metric["false alarm"], metric["confusion"])

四条随身法则：

  1. Diarization = 匿名的"谁在何时说话"——要名字叠识别，要文字叠 ASR，三者正交。
  2. 嵌入把相似变成距离，聚类把距离变成身份——窗长管点的紧散，阈值管人的分合，人数先验是最便宜的涨点。
  3. VAD 的错和重叠的账，后面谁也救不了——一个要前置投入，一个要换范式（重叠感知/EEND）。
  4. DER 不注明 collar 与重叠规则就没有意义——对产品，人数数对往往比 DER 再降两个点更重要。
