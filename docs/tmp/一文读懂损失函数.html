它不是评分表，是训练信号

损失函数把「预测和真实答案的差距」变成一个可求导的标量，梯度顺着它流回参数——它告诉模型下一步该往哪里改，以及改多狠。这份文档围绕一条主线展开：损失函数如何定义训练目标、塑造优化方向。

Chapter 1 · Why Loss

先理解：训练为什么需要损失函数

loss = f(ŷ, y) → 一个可求导的标量

回到一次最普通的训练 step：模型对一个 batch 做前向计算得到预测 ŷ，损失函数把 ŷ 和目标 y 的差距压缩成一个标量 loss，反向传播沿着计算图算出 ∂loss/∂θ，优化器用它更新参数。整个深度学习的「学习」二字，机制上就是这一圈循环。

在这个闭环里，损失函数同时扮演三个角色：

  • 把错误变成可计算的标量。「预测得不好」是一句人话，反向传播听不懂；loss=2.37 才是机器能求导的对象。所有类型的错误——数值偏差、分错类、概率不自信——都要先被压缩成一个数。
  • 定义模型真正优化的目标。模型不知道你想要「准确率高」「用户满意」，它只知道让 loss 变小。你写下哪个 loss，模型就学哪个目标——loss 是你和模型之间唯一的合同文本。
  • 决定不同错误挨多重的罚。loss 曲线的形状决定梯度的大小：MSE 对大错误二次方放大，MAE 一视同仁，Cross Entropy 对「自信但错」施以近乎无穷的惩罚。同一个错误，换一个 loss，模型收到的修正力度完全不同。

Chapter 2 · Loss / Objective / Metric

损失函数、目标函数、评估指标的边界

objective = data_loss + λ · regularization ≠ metric

这三个词在日常交流里经常混着用，但它们出现在训练流程的不同位置、服务不同的目的。混用概念的直接后果是：看着 loss 下降却不明白为什么线上指标不动，或者试图直接「优化 F1」却发现根本没法反向传播。

四个概念，四个位置

  • Loss Function（损失函数）：对单个样本或一个 batch 计算误差的函数，比如 MSE、CrossEntropy。它必须可微（至少几乎处处可微），因为它直接参与反向传播。
  • Training Loss（训练损失）：你在日志里看到的那条曲线。它是一个 batch 上 loss 的聚合结果，会受到 reduction="mean"/"sum"、样本权重、mask、以及分布式训练下实际 batch size 的影响。同一个模型同一批数据，聚合方式不同，打印出来的数字可以差几个数量级。
  • Objective Function（目标函数）：训练时真正被优化的整体目标。它通常不只是数据损失，还包括正则项、约束项或多任务的加权和：
    objective = data_loss + λ · regularization（+ 其他任务的 loss × 权重）
    weight decay、L1 稀疏约束、KL 约束（比如 VAE、RLHF 里的 KL penalty）都住在这里。模型下山时走的是 objective 的坡面，不只是 data_loss 的。
  • Evaluation Metric（评估指标）：用来评价模型效果的量，如 Accuracy、F1、AUC、BLEU、RMSE、MAE。它面向人和业务，不一定可微（Accuracy 是阶梯函数），也不一定适合直接优化。它通常在验证/测试集上计算，用于选模型、早停、汇报。

为什么 training loss 下降 ≠ metric 提升

  • 优化目标和评估目标本来就不是同一个函数。Cross Entropy 关心概率分布的似然，Accuracy 只关心 argmax 有没有变——概率从 0.6 提到 0.99，CE 大幅下降，Accuracy 一动不动（第 9 章有交互演示）。
  • 数据分布与类别不均衡。多数类主导了平均 loss，loss 下降可能只是多数类学得更好，少数类的 Recall 依然是 0。
  • 阈值选择。F1/Precision/Recall 依赖分类阈值，loss 优化的是概率本身，阈值一天没定，metric 一天说不准。
  • 正则化、校准与泛化。objective 里的正则项会故意让 training loss 高一点，换取验证集表现；反过来，training loss 一路走低也可能是过拟合的开场。

Chapter 3 · Regression Losses

回归损失：预测连续数值时怎么惩罚错误

e = ŷ − y　·　问题只有一个：|e| 变大时，罚多重？

回归损失都围绕残差 e = ŷ − y 展开，区别只在于「惩罚随 |e| 增长的速度」。这个速度直接就是梯度——所以选回归损失，本质上是在选「大错误该分走多少梯度预算」。

MSE / L2 Loss：二次方放大

MSE = (ŷ − y)²　　∂L/∂ŷ = 2(ŷ − y)梯度与误差成正比：错 1 罚 1 份力，错 10 罚 10 份力，loss 差 100 倍。
  • 曲线是抛物线，误差越大惩罚增长越快。好处：接近最优点时梯度自然变小，收敛平稳；坏处：对离群点极其敏感——一个错 10 的样本贡献的 loss 等于 100 个错 1 的样本，梯度会被它劫持。
  • 概率解释：假设观测噪声是高斯分布 y = f(x) + ε, ε~N(0,σ²)，最大化似然恰好等价于最小化 MSE。这就是「MSE 假设高斯噪声」的含义——如果你的噪声重尾（离群点多），这个假设不成立，MSE 就不是最优选择。
  • 尺度敏感：目标值单位从 km 换成 m，同样 10% 的相对误差，MSE 数值和梯度尺度会放大 10⁶ 倍。这就是回归任务常做目标标准化（standardize / log 变换）的原因之一——否则学习率要跟着单位重调。

MAE / L1 Loss：线性惩罚

MAE = |ŷ − y|　　∂L/∂ŷ = sign(ŷ − y)梯度恒为 ±1，与误差大小无关。
  • 对离群点稳健：错 10 的样本贡献的 loss 只是错 1 的 10 倍（而非 100 倍），梯度更是完全一样大，离群点无法劫持训练方向。MAE 的最优解是条件中位数（MSE 是条件均值），中位数天然抗离群点。
  • 0 点不可导：数学上 |e| 在 e=0 处没有导数。工程上不是大问题——框架用次梯度（subgradient，通常取 0）处理；真正的麻烦是接近最优时梯度仍然是 ±1，参数会在最优点附近来回跳，需要配合学习率衰减。

Huber Loss / Smooth L1：两头的好处各取一半

|e| ≤ δ: L = e²/2　　|e| > δ: L = δ(|e| − δ/2)小误差走 MSE（梯度 ∝ e，收敛平稳），大误差走 MAE（梯度封顶为 ±δ，离群点被限流）。δ 是"多大算离群点"的分界线。

Huber 的设计意图非常直白：在最优点附近要 MSE 的平滑梯度，在离群点区域要 MAE 的梯度封顶。目标检测里的 Smooth L1 就是它的近亲。代价是多了一个超参 δ，需要按残差的量级来设。

RMSE：更多时候是 metric

RMSE = √MSE单位和 y 一致（MSE 的单位是 y 的平方），所以人读起来更直观。

RMSE 与 MSE 单调等价——最小化谁都会走到同一个最优点，所以训练时直接用 MSE（省一个开方，梯度形式也更干净），汇报时用 RMSE。这正是第 2 章「同一个量，站在 loss 侧还是 metric 侧」的实例。

Quantile / Pinball Loss：当预测一个点不够用

L_τ(e) = τ·e (e≥0 即低估时) ；(τ−1)·e (e<0 即高估时)，其中 e = y − ŷτ=0.9 时低估罚 0.9、高估只罚 0.1，模型被逼着输出第 90 分位数。

MSE 给你条件均值，MAE 给你条件中位数——都只是分布的一个点。当业务需要「90% 情况下备货够用」「给出预测区间」时，点预测不够，就用不对称的 Pinball Loss 训练若干个分位数（τ=0.1, 0.5, 0.9），得到不确定区间。它是「回归不止预测均值」这个思路的入口，这里点到为止。

Chapter 4 · Classification Losses

分类损失：预测类别时为什么常用交叉熵

CE = −log p(正确类别)　·　罚的不是"分错"，是"给正确答案的概率太低"

分类模型输出的不是数值而是概率（或产生概率的 logits）。交叉熵惩罚的对象是「你给正确答案分配了多少概率」：给得越少罚得越重，而且是对数级地重——p→0 时 loss→∞。这一个性质决定了它对「自信但错」零容忍。

Binary Cross Entropy：二分类与多标签的基座

BCE = −[ y·log p + (1−y)·log(1−p) ]y∈{0,1} 是真实标签，p∈(0,1) 是模型预测的正类概率。y=1 时只剩 −log p；y=0 时只剩 −log(1−p)。
  • 直觉：BCE 就是「真实标签指向哪一边，就看你给那一边多少概率，取负对数」。p 越接近正确一侧，loss 越接近 0；越自信地押错边，−log 把惩罚拉向无穷大。
  • 用 logits 表达时有一个非常漂亮的梯度：∂L/∂z = σ(z) − y——梯度恰好是「预测概率 − 真实标签」。错得越多，修正信号越强，且天然有界于 (−1,1)。
  • 多标签分类 = 每个标签各自做一次独立的二分类，对每个输出位各算一个 BCE 再平均。标签之间互不排斥，概率不需要加和为 1。

Cross Entropy：多分类单标签的默认答案

p = Softmax(z)　　CE = −log p[target]z 是 K 个类别的 logits；Softmax 把它们归一成加和为 1 的分布；CE 只取正确类别那一格的概率求 −log。
  • 链条是：logits →（Softmax）→ 概率分布 →（取正确类）→ −log。它表面上只看正确类别，但因为 Softmax 是归一化的，抬高正确类概率必然压低其他类——竞争关系已经内置在 Softmax 里。
  • 梯度同样优雅：∂L/∂zᵢ = pᵢ − yᵢ（y 为 one-hot）。正确类的 logit 被推高 1−p_t 份力，错误类各被压低 pᵢ 份力。预测已经很准时（p_t→1）梯度自动趋近 0。
  • Label smoothing 与软标签：把目标从尖锐的 one-hot [0,1,0] 换成 [0.05,0.9,0.05]，改变的不是模型结构而是训练目标分布——阻止模型把 logit 推向无穷来追求 p=1，缓解过拟合、改善校准。蒸馏里的 teacher 概率是同一思路的一般化。

NLL / KL / Focal / Hinge：同一家族的四个补充

  • Negative Log Likelihood：CE 的另一个名字侧面。PyTorch 里 CrossEntropyLoss = LogSoftmax + NLLLoss；数学上，最小化 CE 就是最大化正确标签的对数似然。
  • KL Divergence：KL(P‖Q) = Σ p·log(p/q)，度量「目标分布 P 和预测分布 Q 的差异」。当 P 是 one-hot 时它与 CE 只差一个常数（P 的熵）；当 P 是软分布——蒸馏的 teacher 输出、label smoothing 后的目标、分布匹配——就轮到 KL 出场。
  • Focal Loss：−(1−p_t)^γ·log p_t。解决的问题是类别极度不均衡 + 简单样本淹没训练：给已经预测得很好的样本乘上 (1−p_t)^γ 这个快速趋零的系数，把梯度预算让给难样本。出身于目标检测（前景/背景比例悬殊），思路可迁移到任何不均衡场景。
  • Hinge Loss：max(0, 1 − y·s)（y∈{−1,+1}，s 为打分）。它提醒我们分类损失不止概率一条路：Hinge 不谈概率，只要求正确类的分数领先出一个 margin，超过 margin 就零惩罚。这是 SVM 与 margin-based 方法的世界观，也是第 10 章度量学习损失的思想源头。

Chapter 5 · MSE vs Cross Entropy

MSE vs Cross Entropy：为什么分类任务通常不用 MSE

数值差距 vs 概率似然 —— 输出的含义不同，惩罚的逻辑就该不同

从输出的含义讲起：MSE 度量的是「两个数值差多远」，Cross Entropy 度量的是「一个概率分布对真实类别的解释力有多差」。回归输出是数值，所以用 MSE；分类输出是概率（或类别似然），所以用 CE。"分类标签也是 0/1 的数字，所以也能 MSE"——语法上能跑通，语义和梯度上都不合适。

把同一个二分类样本（y=1）交给两个 loss，对预测概率 p 求惩罚：

  • MSE = (p − 1)²：p=0.01（自信地押错）时 loss ≈ 0.98，惩罚有上限 1；对 p 的梯度 |2(p−1)| 最大也就 2，而且再叠加 Sigmoid 的链式项 p(1−p) 之后，恰恰在 p→0 的最错区域梯度反而趋近 0——错得最离谱的地方，修正信号最弱（饱和区问题）。
  • CE = −log p：p=0.01 时 loss ≈ 4.6 并继续冲向无穷；对 logit 的梯度是干净的 p − y，错得越多信号越强、且不会在错误一侧饱和。

两个常见误区，正面回应

  • "分类也有 0/1 标签，直接 MSE 不行吗？"能算出数，但有三笔账：① 惩罚封顶，压不住自信错误；② 经过 Sigmoid/Softmax 后梯度在最需要修正的区域饱和，收敛慢且容易卡住；③ 丢掉了概率解释，输出难以当作校准的置信度使用。经典统计里这对应「用线性回归拟合 0/1 标签 vs 用 logistic 回归」的差别。
  • "Cross Entropy 只是另一个误差公式？"不是。它有明确的概率出身：最小化 CE ≡ 最大化训练标签在模型分布下的似然（MLE），等价于最小化真实分布与预测分布之间的 KL 散度。这层身份带来了 p − y 的干净梯度、与 Softmax 的天作之合，以及对校准的天然关照——这些都不是"随便一个把差距变成数的公式"能免费获得的。
Key Idea选 loss 先问输出的语义：输出是连续数值 → 度量数值差距（MSE 家族）；输出是概率/似然 → 度量分布差距（CE 家族）。语义对了，梯度行为自然是对的。
Chapter 6 · Output ↔ Loss ↔ API

输出层、loss 和框架 API 的配对

写错配对是训练代码里最常见、最难肉眼发现的 bug

loss 函数不是孤立的：它必须和模型最后一层的输出形式、标签的格式三方对齐。框架 API（以 PyTorch 命名为例）把激活函数吸收进 loss 的方式各不相同，配错的代码往往能跑通、loss 也在降，只是模型悄悄学错了目标。

输出层配对选择器

  • 回归：Linear output + MSELoss / L1Loss / HuberLoss。最后一层不加激活（或按值域加，比如非负目标可以配 softplus），标签是连续 float，形状与输出对齐。
    • 
    
  • 二分类：单个 logit + BCEWithLogitsLoss。也可以 Sigmoid 后接 BCELoss，但工程上几乎总是推荐前者：① logits 版本内部用 log-sum-exp 技巧做了数值稳定，手动 log(sigmoid(z)) 在 |z| 很大时会下溢成 log(0)；② 少一层手写激活就少一个配错的机会；③ 它还提供 pos_weight 处理不均衡。标签是 float（不是 int），形状与输出对齐（常见坑：输出 (N,1) 标签 (N,)，广播成 N×N）。

  • 那 Softmax 什么时候用？推理时把 logits 变成人能读的概率、展示置信度、温度采样时用。训练时是否显式写出，取决于 loss API 是否已经把它吸收进去——PyTorch 的 CE 吸收了，Keras 的 CategoricalCrossentropy(from_logits=True) 用参数控制。

Chapter 7 · Labels · Stability · Reduction · Mask

  
标签格式、数值稳定、reduction 和 mask

  
训练信号被污染时，loss 曲线看起来往往一切正常


  
这一章是排错边界：四类问题都不改变"用什么 loss"的大方向，却决定训练信号是干净的还是被污染的。它们的共同点是——出了错也不报错。


  
标签格式：三种形态别混用

  
    
    
  • 回归标签：连续 float，shape 与输出对齐。
    • 
    
  • BCE 系（二分类/多标签）：float 的 0./1.（或软概率），shape 与输出逐元素对齐。
    • 
    
  • CE 系（多分类）：默认 class index（int64，值域 0..K−1），不是 one-hot；one-hot / 软标签是否可用要看具体 API 版本。
    • 
  


  
数值稳定：为什么推荐 logits 版 loss

  
直接对概率取 log，当 p 被 Sigmoid/Softmax 压到浮点下溢时会得到 log(0) = -inf，一步就把梯度炸成 NaN。BCEWithLogitsLoss、CrossEntropyLoss 这类 logits 版本在内部把 log 与 exp 合并计算，核心是 log-sum-exp 技巧：先减去 logits 的最大值再做 exp，使指数运算永不溢出：

  
logsumexp(z) = max(z) + log Σ exp(zᵢ − max(z))　　log_softmax(z)ᵢ = zᵢ − logsumexp(z)数学上恒等，数值上把 exp 的输入控制在 ≤0，彻底避开上溢；log 的输入也不再经过"先算出概率"这个下溢通道。


  
reduction：none / mean / sum 不只是显示格式

  
    
    
  • none：返回逐样本（逐元素）loss 向量——想做样本加权、mask、难例挖掘时的原材料。
    • 
    
  • mean：对所有元素取平均。梯度尺度与 batch size 解耦，学习率不用随 batch 调整（近似），是默认值。
    • 
    
  • sum：全部相加。梯度尺度 ∝ batch size——batch 从 32 换到 256，等效于学习率放大 8 倍。梯度累积、分布式训练（每卡先 mean 再 all-reduce mean，等效全局 mean）都会影响"日志里这条 loss 曲线"的可比性：对比实验先对齐 reduction 和有效 batch size。
    • 
  


  
权重与 mask：改写"谁的错更重要"

  
    
    
  • class weight / pos_weight / sample weight：把少数类或重要样本的惩罚放大——本质是直接改写目标函数中各项的系数。
    • 
    
  • 序列任务（padding token）、检测任务（背景 anchor）、分割任务（ignore 区域）：无效位置必须用 ignore_index 或显式 mask 挡在 loss 之外。padding 不是"模型自己会学会忽略"的东西——只要它参与了 loss，它就在参与梯度，就在污染训练信号。
    •

Chapter 8 · Loss Shapes Optimization

  
损失函数如何影响优化过程

  
参数在 loss 曲面上滚动，曲面的形状就是它收到的全部指令


  
优化器很笨：它只会在当前位置摸一下坡度，然后往低处挪 lr 那么远。所以 loss 曲面的形状——哪里陡、哪里平、坑在哪——完整决定了优化路径。选 loss 时值得逐条过一遍这份清单：

  
    
    
  • 大错误是否被强烈惩罚？MSE 是，二次方放大让远处的坡极陡——修正快，但一个离群点就能拽着所有参数跑。
    • 
    
  • 梯度是否稳定？MAE 的梯度恒为 ±1：远处不会爆炸，但最优点附近也不衰减，参数会绕着谷底打转；MSE 的梯度在谷底自动趋零，落地平稳。Huber 两者兼得。
    • 
    
  • 是否容易受离群点影响？MSE 的最优解是均值，被离群点直接拖走；MAE 的最优解是中位数，几乎不动。
    • 
    
  • 类别不均衡时是否被多数类主导？平均 loss 里 95% 的项来自多数类，梯度自然也是——需要 class weight / Focal / 重采样去改写权重。
    • 
    
  • mean 还是 sum？sum 让梯度尺度 ∝ batch size，等效学习率随 batch 变化；mean 解耦。换 batch size 时这条直接决定要不要重调 lr。
    •

Chapter 9 · Loss ≠ Metric

  
损失函数和评估指标为什么经常不一致

  
训练用 CE，评估看 Accuracy / F1 / AUC —— 分工，而不是矛盾


  
第 2 章画了概念边界，这一章看它们在数据上如何真的分道扬镳。先给每个常见 metric 一句定性：

  
    
    
  • Accuracy：预测对的比例。不可微（argmax 是阶梯函数，几乎处处梯度为 0，没法反向传播），且对类别不均衡不敏感——95:5 的数据上"全预测多数类"就有 95% 准确率。
    • 
    
  • Precision / Recall / F1：全部依赖阈值。关心"报出来的里面有多少真的"用 Precision，关心"真的里面抓到多少"用 Recall，F1 是两者的调和平均。适合正类稀少、误报/漏报代价不对称的场景。
    • 
    
  • AUC：把所有阈值扫一遍，衡量"随机取一正一负，正样本得分更高的概率"——它度量排序能力，和概率是否校准无关：把所有概率同乘 0.5，AUC 不变，但概率作为置信度已经不可用。
    • 
    
  • MAE / RMSE：既能当 loss 也能当 metric，但要说清此刻站在哪一侧：进 backward() 就是训练目标，只进验证报告就是评估口径（RMSE 因单位与 y 一致，报告中比 MSE 直观）。
    • 
  

  
所以"训练用 Cross Entropy、评估看 Accuracy/F1/AUC"是一种分工：CE 提供处处可微、梯度良好的优化面；metric 提供业务能读懂的验收口径。分工的代价就是两者可以不同步——下面三个例子各演示一种脱节。

Chapter 10 · Practical Rules

  
工程实践中的选择规则

  
默认值 + 例外条款，而不是绝对真理


  
下面是实用但不绝对化的判断规则——每条都是"默认从这里开始，出现某个信号时再换"：

  
    
    
  • 连续值回归：默认从 MSE 开始（配合目标标准化）；残差分布重尾、离群点明显时换 MAE 或 Huber；需要预测区间时上 Quantile Loss。
    • 
    
  • 二分类:默认单 logit + BCEWithLogitsLoss，别手写 Sigmoid+log。
    • 
    
  • 多标签分类：K 个独立 logits + BCEWithLogitsLoss，远离 Softmax。
    • 
    
  • 多分类单标签：logits + CrossEntropyLoss，标签用 class index。
    • 
    
  • 类别不均衡：按顺序考虑——class weight / pos_weight（最便宜）→ 重采样 → Focal Loss（难例极多时）。同时把 metric 从 Accuracy 换成 F1/AUC/PR-AUC，否则你看不见问题。
    • 
    
  • 多任务学习：objective 是多个 loss 的加权和，第一件事是对齐各 loss 的尺度——一个 MSE 数值 1000、一个 CE 数值 0.5，不加权就等于只训练前者。权重可手调，也可用不确定性加权等自动方案。
    • 
    
  • 软标签 / 蒸馏 / label smoothing：先确认目标是"分布"而不是"索引"，再确认 loss API 支持概率标签（PyTorch CE 的 label_smoothing 参数 / 概率 target；蒸馏常用 KLDivLoss + 温度）。
    • 
    
  • 序列建模、目标检测、分割：主 loss 通常仍是 CE/BCE 的变体，重点转移到mask、ignore_index、类别权重、以及在时间/空间维度上如何 reduction——按有效 token 数平均还是按序列平均，结果不同。
    • 
    
  • 排序 / 相似度 / 度量学习（边界补充）：当目标是"谁比谁更近/更相关"而非"是什么类"时，进入另一族损失——Contrastive Loss（拉近正对、推开负对到 margin 之外）、Triplet Loss（anchor 距正样本比距负样本近出一个 margin）、MarginRankingLoss（成对排序）。它们优化的是嵌入空间的几何关系，常见于检索、人脸、推荐召回。生成模型的损失（对抗损失、扩散模型的去噪 MSE、语言模型的 next-token CE）同样自成体系，本文不展开——但注意语言模型预训练的核心仍是 Cross Entropy。
    • 
    
  • 最后一条元规则：不要只看训练 loss。同时盯验证集 metric、训练/验证 loss 的裂口（过拟合迹象）和业务指标——loss 只是训练信号，不是验收标准。
    • 
  







  
Chapter 11 · Misconceptions

  
常见误区与反例

  
每一条都真实出现在生产代码里 · 点开看为什么错


  
"loss 就是 metric，反正都是越小越好"
loss 是可微的优化目标，metric 是面向业务的评估口径，两者函数形式、计算集合（batch vs 验证集）、用途全都不同。CE 下降 0.3 对应 Accuracy 涨多少？没有固定换算。把日志里的 training loss 当成效果汇报，是最常见的沟通事故。（见第 2、9 章）

  
"loss 越低,业务效果一定越好"
loss 度量的是你写下的训练目标。训练 loss 一路走低可能是过拟合（验证 metric 反而变差）、可能是多数类学得更好而关键少数类毫无起色、也可能业务真正在乎的是排序/校准而 loss 没有覆盖。永远用验证集 metric 和业务指标做最终裁判。

  
"多分类训练前要先手动 Softmax，再喂给 CrossEntropyLoss"
在 PyTorch 等框架里是错误用法：CrossEntropyLoss 内部已含 LogSoftmax，先手动 Softmax 等于归一化两次——loss 仍会下降，但梯度被系统性压扁、模型难以变得自信，坏得非常隐蔽。Keras 则用 from_logits=True/False 显式声明。规则：查清你的 loss API 吃 logits 还是概率。

  
"二分类必须输出两个类别再 Softmax"
不是必需。两类的 Softmax 数学上等价于单 logit 的 Sigmoid，工程上更常见、也更省事的是单 logit + BCEWithLogitsLoss（顺带获得 pos_weight 等不均衡工具）。双输出 + CE 也能用，但没有必要为二分类付出双倍输出。

  
"MSE 简单，所以分类也优先用 MSE"
分类输出的语义是概率。MSE 惩罚封顶（最错也就 1），配上 Sigmoid/Softmax 后在最错的区域梯度饱和趋零——最需要修正的时候信号最弱；而 CE 对"自信但错"给出趋向无穷的惩罚和干净的 p − y 梯度。（第 5 章有交互对比）

  
"one-hot、class index、概率分布标签可以随便替换"
必须匹配 loss API。PyTorch CrossEntropyLoss 默认吃 int64 的 class index；BCE 系吃与输出同 shape 的 float；软标签/one-hot 是否可用取决于框架和版本。格式错了，轻则报错（幸运），重则被广播机制悄悄吞掉、shape 对上了语义全错（不幸）。

  
"reduction 的 mean 和 sum 只是显示方式不同"
它们改变梯度尺度：sum 的梯度是 mean 的 N 倍，batch size 一换，等效学习率跟着换。梯度累积、多卡训练下不对齐 reduction，loss 曲线之间根本不可比。（第 7 章有交互演示）

  
"padding 位置无所谓，模型会自己学会忽略"
只要 padding 参与 loss，它就在产生梯度：模型被迫花容量去"预测 pad"，平均 loss 被无意义项稀释，学习信号被污染。必须用 ignore_index 或 mask 显式排除，并按有效 token 数做平均。（第 7 章有交互演示）

  
"评估指标不可微，所以没用"
不可微只是说它不能直接进 backward()。它照样承担评估、早停、模型选择、超参搜索的裁判角色——这些环节不需要梯度。另外也存在可微代理（soft-F1、pairwise loss 逼近 AUC），是"想优化 metric"时的进阶路线。

  
"只要换个 loss，训练问题就都能解决"
loss 只是训练系统的一个部件。指标不好还可能是：数据/标签噪声、类别分布、采样方式、模型容量与结构、正则化、学习率与调度……换 loss 之前先做误差分析——看看模型到底错在哪一类样本上。

12.1 画出损失曲线（NumPy + Matplotlib）

  
# MSE / MAE / Huber 随 error 变化；BCE 随预测概率变化
import numpy as np
import matplotlib.pyplot as plt

e = np.linspace(-4, 4, 200)
mse, mae = e**2, np.abs(e)
d = 1.0
huber = np.where(np.abs(e) <= d, 0.5*e**2, d*(np.abs(e) - 0.5*d))

p = np.linspace(0.01, 0.99, 200)
bce_y1 = -np.log(p)          # y=1 时的 BCE
bce_y0 = -np.log(1 - p)      # y=0 时的 BCE

fig, ax = plt.subplots(1, 2, figsize=(10, 3.5))
ax[0].plot(e, mse, label="MSE"); ax[0].plot(e, mae, label="MAE"); ax[0].plot(e, huber, label="Huber")
ax[0].set_xlabel("error = y_hat - y"); ax[0].legend()
ax[1].plot(p, bce_y1, label="BCE, y=1"); ax[1].plot(p, bce_y0, label="BCE, y=0")
ax[1].set_xlabel("predicted probability p"); ax[1].legend()
plt.show()

bin_head  = nn.Linear(D, 1)
y_bin     = torch.randint(0, 2, (N, 1)).float()   # 注意：float，不是 int
loss_bin  = nn.BCEWithLogitsLoss()(bin_head(x), y_bin)

# ---- 多标签：K 个独立 logits + BCEWithLogitsLoss（禁用 Softmax）----
ml_head   = nn.Linear(D, K)
y_ml      = (torch.rand(N, K) > 0.7).float()      # multi-hot float
loss_ml   = nn.BCEWithLogitsLoss()(ml_head(x), y_ml)

# ---- 多分类单标签：K 个 logits + CrossEntropyLoss ----
mc_head   = nn.Linear(D, K)
y_mc      = torch.randint(0, K, (N,))             # class index (int64)，不是 one-hot
logits    = mc_head(x)
loss_mc   = nn.CrossEntropyLoss()(logits, y_mc)   # 接收 raw logits：
# 不要写 nn.CrossEntropyLoss()(logits.softmax(-1), y_mc) —— 双重归一化，梯度被压扁


  
12.3 reduction 与标签格式

  
ce_none = nn.CrossEntropyLoss(reduction="none")(logits, y_mc)  # shape (N,) 逐样本
ce_mean = nn.CrossEntropyLoss(reduction="mean")(logits, y_mc)  # 标量，= ce_none.mean()
ce_sum  = nn.CrossEntropyLoss(reduction="sum" )(logits, y_mc)  # 标量，= mean × N，梯度也 × N

# 标签三形态与 API 的匹配（PyTorch >= 1.10 的 CE 也接受概率标签）
y_idx   = torch.tensor([2, 0, 1])                       # class index -> CE 默认形态
y_onehot= nn.functional.one_hot(y_idx, K).float()       # one-hot   -> CE 的概率形态可用
y_soft  = torch.tensor([[.05,.05,.8,.05,.05]]*3)        # soft label -> CE 概率形态 / KLDivLoss
ce_soft = nn.CrossEntropyLoss(label_smoothing=0.1)      # 或者直接让 API 做 smoothing


  
12.4 序列任务：ignore_index / mask

  
PAD = 0
# logits: (N, T, V)  targets: (N, T)，padding 位置填 PAD
loss_fn = nn.CrossEntropyLoss(ignore_index=PAD)          # pad 位置不产生 loss 与梯度
loss    = loss_fn(logits_seq.reshape(-1, V), targets.reshape(-1))

# 等价的手动 mask 写法（按"有效 token 数"平均，这一步是关键）：
raw  = nn.CrossEntropyLoss(reduction="none")(logits_seq.reshape(-1, V), targets.reshape(-1))
mask = (targets.reshape(-1) != PAD).float()
loss = (raw * mask).sum() / mask.sum()


  
12.5 loss 下降但 Accuracy 暂时不变

  
# 三个样本，argmax 全对；把 logits 整体放大（更自信），CE 降、Accuracy 不变
y      = torch.tensor([0, 1, 1])
logits = torch.tensor([[1.2, 0.8], [0.3, 0.9], [0.1, 0.6]])
for t in [1.0, 2.0, 4.0]:
    ce  = nn.CrossEntropyLoss()(logits * t, y).item()
    acc = (logits.argmax(-1) == y).float().mean().item()
    print(f"scale={t}: CE={ce:.3f}, Acc={acc:.0%}")
# scale=1.0: CE=0.556, Acc=100%
# scale=2.0: CE=0.437, Acc=100%   <- loss 一直在降
# scale=4.0: CE=0.301, Acc=100%   <- metric 一格没动
