GRADIENTS & BACKPROPAGATION · 交互式自学文档

一文读懂梯度与反向传播

反向传播不是神秘算法，而是在计算图上反复使用链式法则，把 loss 的影响传回每个参数。

这篇文档只有一条主线：梯度如何告诉参数往哪里改。下面是一条最小的训练链路——一个输入、一个权重、一个偏置、一个激活、一个 loss。拖动滑杆、切换激活函数和 loss，图上会同时给出前向值、每条边的局部导数、链式相乘后的 dL/dw，以及参数更新方向。整篇文章要做的，就是把这张小图讲透，再推广到真实的深层网络。

01

GEOMETRY / 几何直觉

先理解：梯度到底告诉模型什么

把所有维度先压到一维：假设整个模型只有一个参数 w，loss 是关于它的函数 L(w)。导数 dL/dw 回答的问题非常朴素：站在当前的 w 上，往右挪一点点，loss 会变大还是变小、变多快。

就这一个数字，承担了训练里的三个角色：

  • 衡量局部影响：|dL/dw| 大，说明 w 附近 loss 对它很敏感；接近 0，说明动 w 几乎不影响 loss。
  • 指出上升最快方向：导数为正 → 向右 loss 上升；为负 → 向左 loss 上升。推广到多维，梯度向量指向 loss 上升最快的方向。
  • 给出更新规则：既然梯度指向上升最快方向，想让 loss 变小，就沿反方向走——w ← w − η·dL/dw，这就是梯度下降。

导数切线演示器

回答的问题："斜率"如何变成"更新方向"？为什么梯度只保证局部下降、不保证全局最优？

当前： L(w) = ?　　dL/dw = ?　　负梯度方向：?
上一步效果：还没走过
⚠ 学习率太大：一步跨过了谷底，loss 反而在两侧来回弹跳甚至变大。梯度只在"当前位置附近"有效，步子太大就超出了它的有效范围。

试三件事：① 把 w 拖到左边的谷里，连走 20 步——它会停在局部最低点，即使右边还有更低的谷。② 把 w 放在山顶附近，注意斜率接近 0，更新几乎不动。③ 把 η 拉到 1.5 再连走，观察震荡。这三个现象分别对应：梯度是局部信息、驻点处信号消失、步长决定梯度信息的可用范围。

记住这一章的结论：梯度不是"误差有多大"，而是"往哪边改、改动的性价比多高"。它只描述当前点附近一小圈的地形，所以梯度下降是"摸着坡走"，不是"看着地图走"——不保证一步、甚至任意多步到达全局最优。

02

DEFINITIONS / 概念边界

导数、偏导数、梯度：别再混用

这三个词经常被当成同义词，但它们回答的是三个不同的问题。真实网络有百万级参数，loss 是 L(w_1, w_2, ..., w_n) 这样的多变量函数，边界必须画清：

  • Derivative（导数）：单变量函数的变化率，如一维例子里的 dL/dw。几何直觉就是上一章的切线斜率。
  • Partial Derivative（偏导数）：多变量函数中，把其它变量暂时冻结，只看一个变量变化对结果的影响，记作 ∂L/∂w_i。注意"冻结"是分析手段，不是训练手段——求 ∂L/∂w_1 不代表只训练 w_1。
  • Gradient（梯度）：把对每个参数的偏导数排成一个向量 ∇L = [∂L/∂w_1, ..., ∂L/∂w_n]。方向是 loss 上升最快的方向，长度（范数）是局部变化的强度。训练日志里看的 "grad norm" 就是它的长度。
  • Jacobian（雅可比矩阵）：当函数是"向量进、向量出"（比如一层网络 h = Wx），所有输出对所有输入的偏导数排成矩阵。反向传播里每一层传递梯度本质上是"向量乘 Jacobian"，但框架的 autograd 会隐式处理，几乎不需要手工展开。
  • Hessian（黑塞矩阵）：二阶导数矩阵，描述曲率（坡是变陡还是变缓）。牛顿法等二阶优化会用到，日常训练里知道它存在、并且太大算不动，就够了。
概念适用函数形态输出形态几何直觉训练中常见位置容易误解的点
Derivativeℝ → ℝ（单变量）一个标量切线斜率推导单个标量路径，如 dL/da只在单变量语境下叫"导数"，多变量时应说偏导
Partial Derivativeℝⁿ → ℝ（多变量到标量）一个标量（对某一个变量）沿一根坐标轴切开曲面看斜率∂L/∂w_i，即 w_i.grad 里的单个元素"冻结其它变量"是求导视角，不是训练时真的不更新它们
Gradientℝⁿ → ℝn 维向量指向上升最快方向的箭头loss.backward() 后每个参数的 .grad 合起来它是变化率向量，不是误差值；loss 很大时梯度可能是 0
Jacobianℝⁿ → ℝᵐ（向量到向量）m×n 矩阵局部线性近似（每个输出对每个输入的敏感度）层与层之间传梯度：grad_in = Jᵀ · grad_out，autograd 隐式完成不需要显式构造整个矩阵，框架算的是"向量-Jacobian 乘积"
Hessianℝⁿ → ℝn×n 矩阵曲率：坡度本身怎么变二阶优化、损失景观分析（边界知识）参数百万级时 O(n²) 存不下，实用中多用近似

一句话收束：训练一个网络时，我们对每个参数各求一个偏导数，拼成梯度向量，然后沿它的反方向更新。"求导""偏导""梯度"说的是同一件事在不同维度下的形态，而"反向传播"是高效算出这个向量的方法——它是什么方法？答案是下一章的链式法则。

03

CHAIN RULE / 链式法则

链式法则：局部变化如何连成整体影响

神经网络的 loss 对某个深处参数的依赖，是一层套一层的复合函数。最简单的复合是 L = g(f(w))，链式法则说：

dL/dw = dL/df · df/dw

为什么是相乘？做一个"扰动传递"的推理：w 动一点 Δw，f 大约动 (df/dw)·Δw；f 动了这么多，L 又大约动 (dL/df)·(df/dw)·Δw。每一段局部导数都是一个"放大倍率"，扰动穿过一段就被乘上一个倍率——倍率串联，自然相乘。

用一个具体的四节点链条来算，每一段都能落到数字上：

w → z = 2w + 1 → a = z² → L = (a − y)²

链式法则计算器

回答的问题：每段局部导数各自是什么含义？为什么把它们乘起来就是总导数？

链式法则预测： w 增加 Δw = 0.01，L 大约变化 dL/dw × Δw = ?
实际重算前向： L(w + Δw) − L(w) = ?　两者相差 ?（Δw 越小差得越少——导数本来就是极限意义下的比率）

注意红色一行的三个数：dL/da 依赖前向算出的 a，da/dz 依赖前向算出的 z。也就是说，反向要用的局部导数，取决于前向留下的中间值——这个观察是第 4 章"为什么要存中间值"的伏笔。再把 Δw 拉大到 0.5，看预测和实际的偏差如何变大：链式法则给的是切线近似，只在局部成立。

反向传播的全部内容，就是把这个"逐段相乘"系统化：在任意复杂的计算图上，从 loss 出发，沿每条边乘上局部导数，一路乘回每个参数；公共路段只算一次、被所有参数复用。它不是新的数学，是链式法则在图结构上的高效执行。

04

COMPUTATION GRAPH / 计算图

计算图：把一次前向计算拆成可求导节点

要在复杂函数上系统地用链式法则，先要把计算本身画成图：

  • 节点：变量、参数、操作产生的中间结果（首屏图里的 x, w, b, z, a, L 都是节点）。
  • 边：数据依赖关系。前向时数据沿边流动；反向时同一条边反过来用，成为梯度传播路径，每条边自带一个局部导数。

两个方向的遍历规则完全对称：

  • forward：按依赖顺序（拓扑序）从输入算到 loss，每个节点等它的输入都就绪后计算自己的值。
  • backward：从 loss 出发（dL/dL = 1），按反向拓扑序访问节点；每到一个节点，把"上游传来的梯度 × 本条边的局部导数"发给它的每个输入。

为什么训练比推理更耗显存：中间值必须留着

回看第 3 章：dL/da = 2(a − y) 需要 a，da/dz = 2z 需要 z。反向计算局部导数时，普遍需要前向的中间结果。推理算完一层就可以扔掉上一层的输出，训练却必须把这些激活值留到 backward 用完为止——这就是同一个模型"训练显存 ≫ 推理显存"的主要原因，也是 gradient checkpointing（丢掉一部分中间值、反向时重算）这种"时间换显存"技巧存在的理由。

fan-out：一个变量喂给多个下游，梯度要相加

链条只是计算图的特例。真实的图里，一个节点常常同时流向多个下游（权重共享、残差连接、一个特征被多个 head 使用）。这时它收到的梯度是所有路径各自贡献之和——因为 w 动一点，每条路径都会独立地把这份扰动带到 loss，总影响是叠加的。

fan-out 与梯度累加演示

回答的问题：当 w 同时影响两条路径时，dL/dw 为什么是两条路径梯度之和？

上路： ∂L/∂p · ∂p/∂w = ?　　下路： ∂L/∂q · ∂q/∂w = ?
累加： dL/dw = 上路 + 下路 = ?　（验证：L = 6w²，dL/dw = 12w = ?，完全一致）

这个"多条路径求和"就是框架里 .grad 用 += 累加的数学根源：backward 沿每条到达参数的路径各送来一份梯度，参数把它们加起来。它是正确行为；但同一机制也解释了第 9 章的坑——如果跨迭代忘记清零，上一轮的梯度也会被加进来。

到这里，反向传播的三块拼图齐了：计算图给出遍历顺序，链式法则给出每条边上的乘法，fan-out 规则给出汇合处的加法。下一章把它们串成一次完整的、带数字的训练迭代。

STEP BY STEP / 逐步执行

反向传播一步步算什么

用一个带 ReLU 的最小神经元，走完"前向 → 反向 → 更新"的完整循环：

x → z = wx + b → a = ReLU(z) → L = (a − y)²

步骤 0/10：准备开始

⚠ 当前 z ≤ 0，ReLU 输出恒为 0，∂a/∂z = 0。往后看：dL/dw 和 dL/db 都会是 0，这一轮 w、b 完全不更新。试着调大 w 或 b 让 z 回到正区间，对比两种情况下的第 5～8 步。

两个必做实验：① 调 w、b 把 z 在正负区间之间切换，观察 ∂a/∂z 在 1 和 0 之间跳变时，dL/dw 如何被整条抹零；② 播完 10 步后调大 lr 再看第 9、10 步——梯度没变，变的只是步长。这正是分工线：反向传播（第 4～8 步）只负责算梯度；优化器（第 9～10 步）才负责用梯度更新参数。换优化器（SGD → Adam）换的是后两步的策略，前面的梯度计算一个字都不变。

把播放器里的内容写成通用清单，任何一轮训练迭代都是：

  1. 前向：按拓扑序算出 z、a、…、L，顺手保存反向要用的中间值；
  2. 反向：从 dL/dL = 1 出发，逐边乘局部导数（dL/da → ×∂a/∂z → ×∂z/∂w 或 ×∂z/∂b），汇合处相加，得到每个参数的梯度；
  3. 更新：优化器拿着梯度执行 w ← w − lr·dL/dw（或更复杂的规则）。
06

GRADIENT FLOW / 梯度流

梯度流：为什么深层网络训练会变难

把第 5 章的单神经元叠成 n 层，第一层权重 w_1 的梯度是一条很长的链式乘积：

dL/dw_1 = dL/dh_n · dh_n/dh_{n−1} · … · dh_2/dh_1 · dh_1/dw_1

梯度流指的就是：误差信号从 loss 出发、沿计算图逐层传向前层时的强弱和路径。链条里每个因子 dh_{k+1}/dh_k 是第 k 层的"局部放大倍率"（由该层权重和激活函数导数共同决定）。于是问题变成一道乘法题：

  • 倍率普遍小于 1：连乘后指数级衰减。0.5³⁰ ≈ 10⁻⁹——前层几乎收不到信号，这就是梯度消失。
  • 倍率普遍大于 1：连乘后指数级增长。1.5³⁰ ≈ 1.9×10⁵——前层收到失真的巨大信号，这就是梯度爆炸。
  • 倍率稳定在 1 附近：信号能大致等幅穿过所有层，训练才健康。深度学习结构设计的很大一部分，就是想办法把这些倍率钉在 1 附近。

最后划清一个常被说窄的边界：梯度流不只由激活函数决定。每层的倍率里还乘着权重（初始化尺度、训练中的漂移）；归一化层会重整每层输出的分布从而稳定倍率；残差连接 h_{k+1} = h_k + F(h_k) 让局部导数变成 1 + F′，给梯度留了一条"倍率恒为 1 的高速路"；loss 的形状、优化器的自适应缩放、数据尺度都会改变链条两端的量级。第 7、8 章排查原因时，要把这些因素全部放进候选清单。

07

VANISHING / 梯度消失

梯度消失：信号传不回前层

数学直觉

链式乘积里混入太多接近 0 的因子。最经典的来源是饱和激活：Sigmoid 的导数 σ′(z) = σ(z)(1−σ(z)) 最大只有 0.25（在 z=0 处），|z| 稍大就掉到 0.01 以下；Tanh 好一些（导数最大 1），但饱和区同样趋 0。每过一层至多打 0.25 折，10 层 Sigmoid 就是至多 0.25¹⁰ ≈ 10⁻⁶——用第 6 章的模拟器把 |g| 设为 0.2 就能看到这条陡降的直线。

典型表现

  • 前层参数更新极慢：靠近输入的层 .grad 范数比末层小很多个数量级，参数几乎不动；
  • loss 下降缓慢或早早停滞：模型只在"调最后几层"，前层学不到特征；
  • 逐层打印梯度范数时，呈现从后往前指数衰减的阶梯。

常见原因

  • 饱和激活函数（Sigmoid/Tanh 用在深层主干上）；
  • 初始化不合适：权重太小 → 每层倍率整体偏小；权重太大 → 激活被推进饱和区，导数趋 0（殊途同归）；
  • 网络过深且没有为梯度留通路；
  • 缺少归一化或残差路径，层间分布逐层漂移进坏区间。

缓解思路（组合拳，不是单选题）

  • 换激活：ReLU 正区间导数恒为 1，GELU/SiLU 平滑且不易饱和；
  • 对症初始化：Xavier（配 Tanh/Sigmoid）、He（配 ReLU 族），目标都是让每层倍率的期望接近 1；
  • 归一化：BatchNorm/LayerNorm 把每层输入拉回激活函数的敏感区；
  • 残差连接：给梯度一条绕过非线性的恒等通路，这是百层以上网络能训的关键；
  • 合理的学习率与优化器：Adam 类的逐参数缩放能部分补偿前层的小梯度，但补偿不了严格为 0 的梯度。

动手感受：回到首屏，把激活切到 Sigmoid，再把 w 或 b 拉到让 |z| > 4——看 ∂a/∂z 掉到 0.02 以下，dL/dw 随之接近 0，哪怕 loss 明明还很大。"loss 大"和"梯度大"是两回事，饱和时误差再大也传不出去。

08

EXPLODING / 梯度爆炸

梯度爆炸：更新被过大梯度带偏

数学直觉

同一条链式乘积，这次是大于 1 的因子连乘。权重尺度偏大时每层倍率 > 1，n 层就是指数增长。RNN 是重灾区：同一个权重矩阵在每个时间步重复参与乘积，序列长 100 就相当于 100 层共享权重的网络，倍率哪怕只有 1.1，累积后也是 1.1¹⁰⁰ ≈ 1.4×10⁴。

典型表现

  • loss 突然变成 NaN/inf，或剧烈震荡、跳崖式反弹；
  • 参数范数或梯度范数在某几步内异常增大（先于 NaN 出现，是最好的预警指标）；
  • 训练对学习率极度敏感：lr 稍大就炸，稍小又慢——说明梯度量级本身不稳定。

常见原因

  • 初始化尺度过大，或训练中权重逐渐膨胀；
  • 学习率过大：一次过冲把参数甩进更陡的区域，梯度更大 → 步子更大，正反馈直到溢出（第 1 章的震荡实验就是它的一维版本）；
  • 输入或目标没归一化：比如回归目标是上万量级，dL/da = 2(a−y) 从第一步起就巨大；
  • 序列过长或递归结构不稳定，乘积链条太长。

缓解思路

  • gradient clipping：给梯度范数设上限（如 clip_grad_norm_(params, 1.0)），保住方向、砍掉长度，是最直接的保险丝；
  • 合理初始化 + normalization：从源头把每层倍率压回 1 附近；
  • 降低学习率 / warmup：训练初期梯度最不稳定，先用小步试探；
  • 检查数据尺度与异常样本：一个数值离谱的样本就能贡献一次爆炸；标准化输入和目标常常比调模型更有效。

注意消失与爆炸的不对称：爆炸有"外科手术式"的止血手段（clip），消失没有——梯度一旦衰减成 0，信息已经丢了，放大 0 还是 0，只能靠结构（残差、归一化、激活、初始化）预防。这也是为什么现代架构的默认配置几乎都内置了抗消失设计。

AUTOGRAD / 工程边界

自动微分和手写反向传播的边界

好消息：前面几章手算的所有东西，训练时都不需要你写。框架的 autograd 做的正是这三件事：

  • 记录计算图：前向执行时，每个作用在 requires_grad 张量上的操作都被登记到图（"tape"）里，同时保存反向要用的中间值；
  • 自动执行反向传播：调用 loss.backward() 时，按反向拓扑序，对每个操作套用预先定义好的局部导数规则，做的就是第 3～5 章的逐边相乘；
  • 累积参数梯度：沿多条路径到达同一参数的梯度用 += 累加进 .grad（第 4 章 fan-out 的加法）。

而你负责的，是 autograd 无法替你判断的部分：

  • 正确写 forward（模型结构本身）；正确构造 loss（一个标量）；
  • 按固定节奏调用三件套：optimizer.zero_grad() → loss.backward() → optimizer.step()；
  • 管理梯度的"开关"：detach() / torch.no_grad() 明确哪些计算不该进入图。

五个必须认识的框架概念

概念作用忘记/误用的后果
requires_grad标记张量需要参与建图、接收梯度为 False 的参数 .grad 恒为 None，永远不更新
loss.backward()从 loss 反向遍历计算图，把梯度累加进各参数 .grad不调用则没有梯度；对非标量直接调用会报错（需先聚合成标量）

optimizer.zero_grad()清空上一轮残留的 .grad因为 backward 是 +=，忘清会把历史梯度混进本轮，更新方向被污染（见第 12 章演示）
detach() / no_grad()把张量/代码块从计算图上摘下来：目标值构造、评估、EMA 更新等场景必需误用在主路径上 → 图被切断，上游参数梯度为 0，模型"部分瘫痪"且不报错

关于梯度累积再强调一次：多次 backward() 之间不清零，.grad 默认一直累加。这既是 bug 来源（忘记 zero_grad），也是特性——大 batch 装不下显存时，故意累积 k 个小 batch 的梯度再 step 一次，等效于 k 倍 batch size。同一机制，是坑还是工具，取决于你是否知道它在发生。

边界补充：PyTorch 的动态图（边执行边建图，每轮可以不同）与 TensorFlow 1.x 式的静态图（先定义后运行，利于全局优化）只是"什么时候建图"的工程取舍，梯度的数学内容完全相同，不必展开成框架史。

DEBUGGING / 工程排错

工程排错：怎么看梯度是否正常

训练异常时，梯度是最有信息量的生命体征。下面的判断都是经验阈值而非铁律——量级会随模型、loss reduction（mean 还是 sum）、batch size 变化，重点是看相对关系和趋势：

  • 看梯度范数：逐层打印 p.grad.norm()。是否有层接近 0（消失/断图/死激活）？是否有层异常大或 NaN（爆炸/数据异常）？前层是否比末层小很多个数量级？
  • 看参数更新：参数是不是完全不动（梯度为 0 或 lr 过小）？更新量 |Δw| 是否远大于参数本身的尺度 |w|（步子太大）？经验上 |Δw|/|w| 在 1e-3 左右比较舒适。
  • 看训练曲线：loss 是否下降？是否突然跳变成 NaN（爆炸）？是否锯齿状剧烈震荡（lr 大/数据脏）？是否早早平掉（消失/容量/lr 小）？
  • 看数据和尺度：输入归一化了吗？回归目标是不是上万量级？loss 用 sum 还是 mean（sum 会让梯度随 batch size 线性放大）？有没有个别离群样本单独引爆某一步？

MISCONCEPTIONS / 常见误区

常见误区与反例

每张卡片的标题是一个流传很广的错误说法（✕），点开看正确版本（✓）和一个能当场戳破它的反例。

"反向传播就是梯度下降"

反向传播算梯度，梯度下降用梯度更新参数，是流水线上相邻的两道工序（对应第 5 章播放器的第 4～8 步和第 9～10 步）。

反例：把 SGD 换成 Adam，backward 的每一步计算原封不动，变的只是拿到梯度之后怎么走；反过来，用数值差分（不做反向传播）算出梯度，也照样能做梯度下降，只是慢得没法用。

"梯度就是 loss 的大小"

梯度是 loss 对参数的变化率，不是误差值本身。loss 大不代表梯度大，loss 小也不代表梯度小。

反例：首屏切到 Sigmoid、把 z 推到 5 以外——loss 可以很大，但 ∂a/∂z ≈ 0，梯度几乎为零；反之在陡坡上，loss 很小也能有很大的梯度。

"偏导数就是只对一个参数训练"

"冻结其它变量"只是分析某一个变量局部影响的数学视角。训练时对所有参数各求一个偏导数、拼成梯度、同时更新全部参数。

反例：loss.backward() 一次调用就填好了网络里每一个参数的 .grad，没有任何"轮流训练"发生。

"链式法则只是个求导公式技巧"

它是"深模型能分层求梯度"的结构性基础：因为总导数 = 局部导数之积，每层只需知道自己的局部导数和上游传来的梯度，无须理解整个网络——模块化、层可复用、autograd 可实现，全都建立在这一点上。

反例：如果没有链式法则的分解，对一个 50 层网络求 dL/dw_1 就得把 50 层复合函数整体展开求导——每加一层都要重新推一遍全网公式。

"梯度消失只由激活函数导致"

激活导数只是链式乘积里的一类因子。每层倍率还乘着权重（初始化、深度让问题指数化），而归一化、残差、数据尺度、loss 选择都会改变这些倍率。

反例：全 ReLU 网络（正区间导数恒为 1）在初始化权重过小时照样消失——倍率由权重贡献的部分小于 1，连乘依旧衰减。

"梯度爆炸只要调小学习率就行"

lr 只缩放步长，不解决梯度量级本身不稳定。该做的是 clip 兜底 + 检查初始化、数据尺度、异常样本和结构（尤其长序列）。

反例：回归目标是 1e4 量级且没标准化时，把 lr 调小 100 倍只是把"立刻炸"变成"慢慢炸"，而对目标做个标准化就能根治。

"有了 autograd，理解反向传播就不重要了"

autograd 接管的是计算，不是诊断。梯度消失/爆炸、dead ReLU、图被 detach 切断、忘记 zero_grad——这些故障 autograd 全都"正确地"执行，不报任何错。能不能从梯度范数的形状读出病因（第 10 章），完全取决于你是否理解梯度流。

反例：第 10 章面板里 "detach 误用" 那种前层梯度恒为 0 的形状，不懂计算图的人会去调学习率，懂的人直接去 forward 里找那行 detach()。

"梯度为 0 说明模型收敛了"

梯度为 0 只说明局部信号消失，原因可能是：真的到了（局部）极小点、激活饱和、dead ReLU、图被 detach 切断、数值下溢。收敛与否要结合 loss 水平和验证指标判断。

反例：第 5 章播放器里把 z 调成负数——梯度精确为 0，但 loss 还大得很，模型只是"这条路走死了"，不是"学好了"。

最小代码示例：把前面的图翻译成代码

12.1 NumPy 手写一个标量计算图（对应第 5 章播放器）

numpy · 手写 forward + backward
import numpy as np

x, y = 1.5, 2.0          # 数据
w, b = 0.8, -0.3         # 参数
lr = 0.1

for step in range(50):
    # ---- forward：按拓扑序算值，保存中间结果 z、a ----
    z = w * x + b
    a = max(z, 0.0)                  # ReLU
    L = (a - y) ** 2

    # ---- backward：从 loss 逐边乘局部导数（用到了保存的 a、z）----
    dL_da = 2 * (a - y)              # 边 a→L
    da_dz = 1.0 if z > 0 else 0.0   # 边 z→a（ReLU 的分段导数）
    dL_dz = dL_da * da_dz
    dL_dw = dL_dz * x                 # 边 w→z：∂z/∂w = x
    dL_db = dL_dz * 1.0               # 边 b→z：∂z/∂b = 1

    # ---- update：这两行属于"优化器"，不属于反向传播 ----
    w -= lr * dL_dw
    b -= lr * dL_db

12.2 PyTorch：同一件事交给 autograd（对应第 9 章）

pytorch · requires_grad / backward / .grad
import torch

x, y = torch.tensor(1.5), torch.tensor(2.0)
w = torch.tensor(0.8,  requires_grad=True)   # 声明：给我建图、算梯度
b = torch.tensor(-0.3, requires_grad=True)
opt = torch.optim.SGD([w, b], lr=0.1)

for step in range(50):
    loss = (torch.relu(w * x + b) - y) ** 2   # forward，同时悄悄记录计算图
    opt.zero_grad()      # 清掉上一轮残留（backward 是累加的！）
    loss.backward()      # 反向遍历计算图 → 填 w.grad, b.grad
    opt.step()           # 用梯度更新参数（优化器的职责）

# w.grad 此刻的值 = 12.1 节手写的 dL_dw，逐位一致

12.3 忘记 zero_grad：梯度累积现象

pytorch · 同一个 loss 反复 backward，.grad 越滚越大
w = torch.tensor(1.0, requires_grad=True)
for i in range(3):
    loss = (w * 2.0) ** 2        # dL/dw = 8w = 8
    loss.backward()
    print(w.grad)                # 8., 16., 24. —— 一直在 +=
    # 缺了 w.grad.zero_()（或 opt.zero_grad()），历史梯度混进了本轮

# 同一机制的正确用法：显存不够时故意累积 k 个小 batch 再 step 一次，
# 等效于 k 倍 batch size —— 是坑还是工具，取决于是否有意为之。

12.4 detach()：从图上剪断一条边

pytorch · detach 切断梯度
w = torch.tensor(1.0, requires_grad=True)

h = w * 3.0
loss = (h - 1.0) ** 2
loss.backward()
print(w.grad)          # tensor(12.) —— 图连通：L → h → w

w.grad = None
h = (w * 3.0).detach() # h 被摘下计算图，成了普通常数
loss = (h - 1.0) ** 2
loss.backward()
print(w.grad)          # None —— 梯度到 h 为止，传不回 w，且不报错

# 正当用途：构造训练目标（如 target network / EMA / 伪标签）、
# 只做统计不参与训练的分支。误用在主路径上 = 第 10 章的"detach 误用"形状。

12.5 梯度消失现场：多层 Sigmoid 的逐层梯度范数

pytorch · 观察范数逐层衰减
import torch, torch.nn as nn

layers = []
for _ in range(12):
    layers += [nn.Linear(64, 64), nn.Sigmoid()]   # 每层导数 ≤ 0.25
net = nn.Sequential(*layers, nn.Linear(64, 1))

x = torch.randn(32, 64)
loss = net(x).pow(2).mean()
loss.backward()

for i, m in enumerate(net):
    if isinstance(m, nn.Linear):
        print(f"layer {i:2d}  grad norm = {m.weight.grad.norm():.3e}")
# 典型输出：靠近 loss 的层 ~1e-2，最前层 ~1e-8 —— 指数衰减的阶梯
# 把 nn.Sigmoid() 换成 nn.ReLU() 再跑一遍，对比形状

12.6 梯度爆炸现场 + clip 保险丝

pytorch · 权重尺度过大导致爆炸，用 clip_grad_norm_ 兜底
layers = []
for _ in range(12):
    lin = nn.Linear(64, 64)
    nn.init.normal_(lin.weight, std=1.0)   # 故意把初始化调大 → 每层倍率 > 1
    layers += [lin, nn.Tanh()]
net = nn.Sequential(*layers, nn.Linear(64, 1))

loss = net(torch.randn(32, 64)).pow(2).mean()
loss.backward()
total = torch.nn.utils.clip_grad_norm_(net.parameters(), max_norm=1.0)
print(f"clip 前总范数 = {total:.3e}")   # 常见 1e3 ~ 1e6 量级
# clip_grad_norm_ 在 backward 之后、optimizer.step() 之前调用：
# 若总范数超过 max_norm，就整体等比例缩小 —— 保方向、砍长度

梯度爆炸大于 1 的倍率连乘 → 信号指数增长长路径上的连乘增长（RNN 尤甚）loss 震荡/NaN、对 lr 极敏感范数骤增先于 NaN 出现；clip 是保险丝

四条随身法则：

  1. 梯度是变化率，不是误差——loss 大 ≠ 梯度大，梯度 0 ≠ 收敛。
  2. backward 乘、汇合加、跨轮清零——链式法则、fan-out、zero_grad 三件事对应三种运算。
  3. 深度是放大器——每层倍率对 1 的偏差被层数指数放大；结构设计（激活、初始化、归一化、残差）都是在把倍率钉回 1。
  4. 先看逐层梯度范数再动手——形状会直接告诉你该查激活、初始化、数据尺度、lr 还是那行 detach。
