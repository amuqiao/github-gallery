# Embedding 系列写作 Runbook

本文维护 Embedding 系列《一文读懂》的提示词组装方式，目标是产出 1 篇总览和 4 篇专题，而不是维护 5 份重复的完整模板。

## 写作结构

推荐拆成 5 篇：

1. **一文读懂 Embedding**：讲共同心智模型，解释对象如何变成向量、向量空间如何表达相似性，以及检索、聚类、分类和多模态匹配如何基于 embedding 工作。
2. **一文读懂 Text Embedding**：讲文本输入如何经过切分、tokenization、encoder、pooling 或归一化形成向量，并落到语义检索、RAG、分类和推荐等场景。
3. **一文读懂 Image Embedding**：讲图像输入如何经过预处理、视觉 encoder 或多模态 encoder 形成向量，并落到以图搜图、图文匹配、相似图聚类等场景。
4. **一文读懂 Audio Embedding**：讲音频输入如何经过重采样、切片、频谱或模型编码形成向量，并落到说话人识别、音频检索、音乐相似度和声音事件匹配等场景。
5. **一文读懂 RAG**：讲如何用 embedding 检索外部知识，再把检索结果组织进 LLM 上下文，让模型基于可追溯资料回答问题，而不是只依赖参数记忆。

不要把 5 篇合成一篇长文。总览篇只建立共同模型和对比框架，具体输入处理、模型选择、Python 实现、伪代码和方案选型放到专题篇里。RAG 是 embedding 的典型应用专题，但它的重点不是“文本如何变向量”，而是“检索、拼接上下文、生成、引用和评估”这一整条问答链路。

## 总览篇追加要求

```md
主题：Embedding：从 Text / Image / Audio 到向量空间

本文是 Embedding 系列总览，目标是建立共同心智模型，而不是深入某一种模态的工程实现。

请重点讲清：
- embedding 为什么存在：它把文本、图片、音频等对象转换成可计算、可比较、可索引的向量
- 向量空间如何表达相似性：距离、方向、聚类、边界和相似度计算的直觉
- embedding 如何支撑检索、聚类、分类、推荐、去重、匹配和多模态搜索
- text embedding、image embedding、audio embedding 的共同点和差异：输入形态、预处理、encoder、向量语义、典型用途和误区
- 总览篇只做对比和路线图，不展开完整 Python 实现；实现细节放到专题篇
```

## RAG 专题追加要求

```md
主题：RAG：让大模型先查资料再回答

本文面向 Python 开发者，目标是讲清 RAG 的完整心智模型和最小工程实现路径。RAG 是 embedding 的应用专题，不要把它写成 Text Embedding 的重复解释。

请重点讲清：
- RAG 为什么存在：LLM 参数记忆不等于可更新、可审计、可引用的业务知识；RAG 用外部知识库补足这一点
- RAG 的主链路：文档采集、清洗、切分、embedding、写入向量库、查询改写、召回、重排、上下文组装、LLM 生成、引用返回
- RAG 和微调、长上下文、传统搜索、Text Embedding 的边界区别：分别解决什么问题，不能互相替代的地方在哪里
- 切分策略如何影响效果：chunk 大小、overlap、标题层级、元数据、段落边界、表格和代码块的处理原则
- 检索质量如何提升：关键词检索 + 向量检索的混合召回、reranker、metadata filter、query rewrite、去重和上下文压缩
- 生成质量如何控制：只允许基于检索材料回答、保留引用、处理无答案、避免把召回噪声写成事实
- Python 实现主链路：加载文档、切分、批量 embedding、写入向量库、查询检索、拼 prompt、调用 LLM、返回答案和引用
- 给出简短伪代码，展示主链路即可，不写完整项目脚手架
- 给出方案选型：轻量本地验证、云 API + 托管向量库、企业内网知识库、多租户知识库分别适合什么场景
- 给出常见失败模式：切分太碎或太大、只用向量检索、top_k 不合理、上下文塞太多、引用丢失、权限过滤缺失、没有离线评测集
```

## 维护规则

- 本文只维护 Embedding 系列的写作拆分和提示词组装方式，不复制完整通用模板。
- 总览篇不承担工程实现细节；专题篇必须补充实现路径、伪代码和方案选型。
- 专题篇默认面向 Python 开发者，但具体库、模型、云服务、向量库和 LLM 应由生成任务按需指定。
- 如果后续要讲具体模型、库或项目，例如某个 embedding 模型、向量数据库或开源库，应优先使用模型、工具或开源项目模板，不要塞进本文。
