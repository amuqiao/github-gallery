# 知识点提示词模板 - 一文读懂版

本文维护机制、概念、协议、工具链原理等知识点类《一文读懂》专项提示词，重点补充问题来源、核心机制、因果关系、对比反例和迁移使用。

使用方式：直接复制下面代码块作为完整提示词使用；具体知识点、读者背景和期望深度由生成任务补充。

## 提示词

```md

为指定知识点生成《一文读懂》单文件交互式 HTML，核心目标是让读者快速建立心智模型并能迁移使用。

建议：
- 以下维度按知识点特点取舍，不要机械逐项展开；优先围绕一条最能解释知识点的主线组织内容
- 从具体问题或真实场景切入，先讲清它为什么出现、解决什么问题、边界在哪
- 围绕核心机制与因果主线展开，抓住关键概念、运行过程或推导路径，并给出最小可验证例子
- 可根据知识点特点灵活调整结构，怎么好懂怎么来，避免把文章写成术语清单或百科条目
- 重视对比和反例：讲清相近概念、常见误区、适用/不适用场景和取舍
- 重视可视化：用图表、流程图、状态图、对比表或示意图呈现抽象关系
- 善用交互：可通过步骤切换、悬停提示、展开详情、案例演示等方式让读者主动探索
- 单文件内联资源，离线可打开，自然中文表达即可，专业术语、命令、代码保留英文
- 首屏视觉贴合知识点本身，让人一眼抓住主题和核心问题
```

## 维护规则

- 本模板只维护知识点的对象差异：问题来源、核心机制、运行过程、因果关系、对比反例和迁移使用。
- 模板正文必须保持可独立复制使用，不依赖其他提示词片段。
- 模板应保持生成方向感，不要扩展成逐项验收清单；通用维度只作为取舍依据，具体任务应保留模型组织文章的空间。
- 如果某个要求只适用于部署、语言框架、模型或开源项目，优先放进对应专项模板，不要写进知识点模板。
- 如果后续需要更细的数学推导、标准协议解读或工程排错清单，单独新增专项片段，不要把本模板变成百科大纲。
