# 一文读懂提示词目录

本文说明如何选择和维护《一文读懂》单文件交互式 HTML 提示词。

## 选择规则

先判断本次目标属于解释型内容，还是工程落地型内容。

解释型内容优先使用对象模板：

- [知识点提示词模板-一文读懂版.md](./知识点提示词模板-一文读懂版.md)：机制、概念、协议、工具链原理。
- [算法提示词模板-一文读懂版.md](./算法提示词模板-一文读懂版.md)：算法过程、状态推进、正确性直觉和复杂度。
- [模型提示词模板-一文读懂版.md](./模型提示词模板-一文读懂版.md)：单个 AI 模型的任务、输入输出、数据流、训练/推理差异。
- [工具使用提示词模板-一文读懂版.md](./工具使用提示词模板-一文读懂版.md)：单工具、单调用面、具体使用场景。
- [开源项目提示词模板-一文读懂版.md](./开源项目提示词模板-一文读懂版.md)：项目定位、仓库结构、运行主线和采用边界。

工程落地型内容优先使用：

- [AI 工程节点落地说明提示词模板 - 一文读懂版.md](<./AI 工程节点落地说明提示词模板 - 一文读懂版.md>)：AI 工程探索、POC、节点落地、现有 AI 系统解剖、评估和升级路线。

可追加片段：

- [1.风格模板.md](./1.风格模板.md)：追加视觉风格要求。

## 复制规则

- 代码块外正文只说明职责、适用场景、选择规则和维护规则。
- `md` 代码块里的内容才是要复制给 LLM 的提示词。
- 文档必须明确标注代码块属于“完整提示词”还是“可追加片段”。
- 完整提示词可以单独复制使用；可追加片段只能追加在完整提示词后。
- 维护参考、示例标尺和历史讨论不要伪装成可复制提示词。

## 公共生成方向

所有《一文读懂》模板默认遵守：

- 建立心智模型，不写百科摘要或静态展示页。
- 围绕一个核心对象、核心流程或状态变化组织全文，先讲主干，再展开分支。
- 首屏贴合主题本体，优先让读者看见核心问题、运行路径、输入输出关系或关键机制。
- 可视化和交互只服务理解、对比、验证和迁移，避免无关动效和装饰性控件。
- 示例尽量真实、最小、可验证；单文件内联资源，离线可打开。
- 维度按主题特点取舍，不机械逐项展开，保留生成模型根据具体对象安排章节的空间。

## 维护规则

- 对象模板只维护对象差异，不承担工程落地全链路。
- 工程落地全链路优先进入 AI 工程节点落地说明模板。
- 新增模板前先判断能否通过现有对象模板、AI 工程节点模板或 runbook 专题追加要求解决。
