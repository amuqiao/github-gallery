# 一文读懂公共生成约束

本文保留“一文读懂”单文件交互式 HTML 的公共经验参考。各专项提示词文档必须保持独立可复制使用，不依赖本文组合生成。

使用方式：本文不作为生成入口；生成时直接使用对应专项提示词文档的代码块。

```md
 公共提示词应该只保留 5 类高杠杆要求：
1. 目标：建立心智模型，不是百科。
2. 首屏：贴合主题本体，最好可交互。
3. 主线：围绕核心对象/流程展开。
4. 表达：可视化和交互服务理解，不装饰。
5. 真实：真实示例、最小验证、单文件离线。
6. 学习：HTML 是自学型交互文档，交互必须帮助读者理解、对比、验证和迁移，而不是只做展示。
```

## 公共经验

```md

通用要求：
- 生成《一文读懂》单文件交互式 HTML。目标不是百科介绍或静态摘要页，而是让读者快速建立心智模型：看懂它是什么、解决什么问题、边界在哪、核心机制如何运转，并能判断、使用、迁移或借鉴。
- 首屏必须贴合主题本身，优先呈现真实界面、真实文件、真实配置、核心产物、核心流程或强相关隐喻；如果主题适合交互，首屏应让读者通过点击、切换或调整看到执行顺序、状态变化、输入输出关系或关键机制。
- 内容围绕一个能贯穿全文的核心对象展开，例如一张工作流图的一生、一次请求的完整链路、一个状态变化过程、一份配置如何影响运行结果、一个最小例子如何扩展成真实场景；先讲主干，再展开分支和细节。
- 可视化和交互必须服务理解。优先表现数据流、状态变化、依赖关系、参数影响、层级分工、概念边界、正确/错误对照或排错路径；不要为了丰富页面而加入无关动效、装饰图或机械化控件。
- 示例尽量真实、最小、可验证。优先使用真实文件名、目录结构、配置片段、JSON、API/CLI 调用、最小代码、执行日志或核心产物；工程/部署/配置类主题要讲清从输入到可用结果的主路径，以及每步产出、验证方式和常见错误。
- 单文件内联资源，离线可打开；自然中文表达，专业术语、命令、代码、协议、文件名、库名保留英文。
- 生成结果应是自学型交互文档，而不是静态展示页或视觉 demo。读者应能通过阅读、切换、拖动、对比、展开、自检或最小实验逐步理清知识点；每个交互组件都应回答一个明确理解问题，避免加入只装饰、不帮助理解的动效。
```

## 维护规则

- 本文只保留跨模板的历史经验，不作为专项模板的索引或依赖入口。
- 专项模板必须独立维护完整提示词正文，使用者应能直接复制对应代码块。
- 如果某个经验只适用于一类主题，优先放进对应专项模板。
- 如果本文后续继续保留，应避免扩展成第二套模板体系。
