# 算法提示词模板 - 一文读懂版

本文维护算法类《一文读懂》专项提示词，重点补充问题建模、核心状态与推进过程、代表性例子、正确性直觉、复杂度边界和适用取舍。

使用方式：直接复制下面代码块作为完整提示词使用；算法名称、问题背景、输入输出格式、读者基础和期望深度由具体生成任务补充。可按需追加风格片段；如果目标转向工程落地，优先使用 AI 工程节点落地说明模板。

## 完整提示词

```md
为指定算法生成《一文读懂》单文件交互式 HTML，核心目标是让读者真正理解这个算法解决什么问题、为什么这样做、每一步如何推进、什么时候适合用，并能把它迁移到相近问题中。

建议：
- 以下维度按算法特点取舍，不要机械逐项展开；优先围绕一条最能解释算法的主线组织内容
- 从问题建模切入，先讲清算法要解决的真实问题、输入/输出、关键约束、前置依赖，以及不用这个算法时会遇到什么困难
- 抓住核心状态与推进过程，说明关键对象、状态变量、数据结构、决策规则、停止条件和输出语义
- 围绕一次完整执行过程展开，用一个最小但有代表性的例子演示状态如何变化、候选解如何被保留或淘汰、最终答案如何产生
- 讲清“为什么正确”的直觉，不要只给结论；可根据算法特点选择不变量、贪心选择性质、最优子结构、剪枝逻辑或交换论证等表达方式
- 讲清成本、边界和取舍：复杂度从哪里来，瓶颈在哪里，适用/不适用场景是什么，关键参数、输入噪声或工程约束会怎样影响结果
- 可根据算法类型灵活调整结构：排序类突出比较/交换/稳定性，图算法突出节点边和路径状态，动态规划突出状态定义和转移，搜索/回溯突出搜索树和剪枝，随机/近似算法突出概率和误差边界，在线/流式算法突出增量更新
- 重视可视化：用数组变化、指针移动、队列/栈状态、图遍历、搜索树、状态转移表、时间线、坐标系或对比表呈现抽象过程
- 善用交互：可通过单步执行、速度控制、输入切换、状态高亮、复杂度对比、边界案例切换、自检题等方式让读者主动验证理解
- 示例尽量真实、最小、可验证，可包含伪代码、关键代码片段、输入输出样例、手算过程、测试用例和常见实现坑；代码语言可按任务指定，未指定时优先使用易读伪代码
- 单文件内联资源，离线可打开，自然中文表达即可，专业术语、变量名、代码、复杂度符号和算法名保留英文
- 首屏视觉贴合算法本身，让人一眼看到问题对象、核心状态和主推进过程，而不是只展示标题或抽象装饰
```

## 维护规则

- 本模板只维护算法的对象差异：问题建模、核心状态、推进过程、代表性例子、正确性直觉、复杂度边界、对比取舍和迁移能力。
- 模板正文必须保持可独立复制使用，不依赖其他提示词片段。
- 模板应保持生成方向感，不要扩展成逐项验收清单；通用维度只作为取舍依据，具体任务应保留模型组织文章的空间。
- 如果某个要求只适用于具体算法、竞赛题、机器学习模型、论文方法或工程系统，优先放进具体生成任务，不要写进通用模板。
- 如果后续需要更强的数学证明、竞赛题解、源码实现或性能调优清单，单独新增专项片段，不要把本模板变成证明模板或刷题模板。
