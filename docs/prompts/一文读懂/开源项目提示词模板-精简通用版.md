# 开源项目提示词模板 - 精简通用版

本文维护开源项目类《一文读懂》专项提示词，重点补充项目定位、真实结构、核心工作流、使用路径和采用边界。

使用方式：直接复制下面代码块作为完整提示词使用；项目仓库地址使用 `{repo_url}` 传入。

## 提示词

```md
已知开源项目 {repo_url} 为指定项目生成《一文读懂》单文件交互式 HTML，核心目标是让读者快速理解项目解决什么问题、如何运转、怎么使用或集成，并能判断是否适合采用、学习或借鉴。

建议：
- 从项目定位切入，先讲清它是什么、为什么出现、解决什么问题、边界在哪，以及它在同类工具或系统中的位置
- 围绕核心工作流或核心数据流展开，讲清输入从哪里来、经过哪些模块、产生什么结果，避免写成 README 摘要或功能清单
- 可根据项目特点灵活调整结构，怎么好懂怎么来；工具类项目可突出使用路径，框架类项目可突出扩展点，平台类项目可突出架构和运行链路
- 重视真实项目结构：讲清关键目录、核心模块、主要命令、配置文件、API/CLI 入口、运行时依赖和典型部署方式
- 重视对比和边界：讲清相近项目、常见误区、适用/不适用场景、工程成本和采用风险
- 重视可视化：用架构图、数据流图、调用链路、模块依赖、目录结构、工作流示意或输入输出对照呈现抽象关系
- 善用交互：可通过步骤切换、悬停提示、展开详情、流程高亮、配置对照、案例演示等方式让读者主动探索
- 示例尽量真实、最小、可验证，可包含安装启动、最小配置、CLI/API 调用、核心输出、日志片段或项目目录片段
- 单文件内联资源，离线可打开，自然中文表达即可，专业术语、命令、代码、文件名、库名保留英文
- 首屏视觉贴合项目本身，让人一眼抓住项目定位、核心问题和最主要的工作流
```

## 维护规则

- 本模板只维护开源项目的对象差异：项目定位、仓库结构、运行链路、使用方式、集成方式和采用风险。
- 模板正文必须保持可独立复制使用，不依赖其他提示词片段。
- 如果某个要求只适用于特定项目或技术栈，优先放进具体生成任务，不要写进通用模板。
- 如果后续需要更强的项目审计、源码阅读或架构评审要求，单独新增专项片段，不要把本模板变成源码分析清单。
