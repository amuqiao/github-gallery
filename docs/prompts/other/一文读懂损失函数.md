## 1. 先理解：训练为什么需要损失函数
- 从一次训练 step 讲起：模型输出预测，损失函数衡量预测和目标的差距，优化器根据梯度更新参数
- 讲清损失函数的三个作用：
  - 把错误变成可计算的标量
  - 定义模型真正优化的目标
  - 决定不同错误会产生多强的梯度惩罚
- 用可视化展示：同一个预测错误，在 MSE、MAE、Cross Entropy 下会产生不同的 loss 和梯度
- 强调：loss 越小通常表示训练目标越接近，但不等于业务效果一定更好

## 2. 损失函数、目标函数、评估指标的边界
必须单独成章，避免读者混用概念。

讲清以下区别：
- Loss Function：
  - 对单个样本或一个 batch 计算误差
  - 直接参与反向传播
- Training Loss：
  - 通常是一个 batch 上 loss 的聚合结果
  - 会受到 `mean`、`sum`、样本权重、mask、分布式训练 batch size 的影响
- Objective Function：
  - 训练时真正优化的整体目标
  - 通常是 loss 加上正则项、约束项或多任务权重
  - 示例：`objective = data_loss + lambda * regularization`
- Evaluation Metric：
  - 用来评价模型效果，不一定可微，也不一定适合优化
  - 示例：Accuracy / F1 / AUC / BLEU / RMSE / MAE
- 说明为什么训练 loss 下降不必然代表 metric 提升：
  - 优化目标和评估目标不一致
  - 数据分布、类别不均衡、阈值选择会影响 metric
  - 正则化、校准、泛化能力也会造成差异

## 3. 回归损失：预测连续数值时怎么惩罚错误
必须覆盖：
- MSE / L2 Loss：
  - 公式、曲线形状、误差越大惩罚越强
  - 为什么对离群点敏感
  - 与高斯噪声假设的关系可简要解释
  - 说明目标值尺度会直接影响 MSE 数值和梯度尺度
- MAE / L1 Loss：
  - 公式、线性惩罚
  - 为什么比 MSE 更抗离群点
  - 在 0 点不可导的工程处理可简要说明
- Huber Loss / Smooth L1：
  - 小误差像 MSE，大误差像 MAE
  - 解释它如何平衡稳定梯度和抗离群点
- RMSE：
  - 常作为评估指标
  - 解释它与 MSE 的关系，以及为什么不总是直接作为训练 loss
- Quantile Loss / Pinball Loss：
  - 作为预测分位数或不确定区间的补充
  - 重点讲它解决“预测一个点不够”这个问题即可

## 4. 分类损失：预测类别时为什么常用交叉熵
必须覆盖：
- Binary Cross Entropy：
  - 用于二分类或多标签分类
  - 讲清真实标签 `y` 和预测概率 `p` 的关系
  - 解释预测越自信但越错，惩罚越大
- Cross Entropy：
  - 用于多分类单标签
  - 讲清 logits、Softmax、目标类别概率之间的关系
  - 解释为什么它关注正确类别的概率
  - 补充 label smoothing 和软标签：它们改变的不是模型结构，而是训练目标分布
- Negative Log Likelihood：
  - 简要说明与 Cross Entropy 的关系
- KL Divergence：
  - 作为分布对分布的差异度量
  - 可用于蒸馏、软标签或分布匹配场景
- Focal Loss：
  - 作为类别不均衡和难样本关注的补充
  - 重点讲解决什么问题，不要展开成公式堆砌
- Hinge Loss：
  - 作为 SVM 和 margin-based 分类的边界补充
  - 用来说明“分类损失不只有概率式交叉熵”

## 5. MSE vs Cross Entropy：为什么分类任务通常不用 MSE
- 从输出含义讲起：
  - MSE 适合连续数值差距
  - Cross Entropy 适合概率分布或类别似然
- 对比同一个二分类样本：
  - 使用 MSE 时，错误概率的梯度可能不够符合分类优化需求
  - 使用 Cross Entropy 时，对自信错误惩罚更强
- 讲清常见误区：
  - “分类也有 0/1 标签，所以可以直接 MSE”不一定合适
  - “Cross Entropy 只是另一个误差公式”是误区，它有概率和最大似然解释

## 6. 输出层、loss 和框架 API 的配对
必须讲清工程使用边界，避免读者写错训练代码。

覆盖以下配对：
- 回归：
  - Linear output + MSELoss / L1Loss / HuberLoss
- 二分类：
  - 单个 logit + BCEWithLogitsLoss
  - 或 Sigmoid probability + BCELoss
  - 推荐解释为什么实际工程常用 `BCEWithLogitsLoss`
  - 标签通常是 float，形状需要和输出对齐
- 多标签分类：
  - 多个独立 logits + BCEWithLogitsLoss
  - 每个标签独立判断，不要求概率和为 1
- 多分类单标签：
  - logits + CrossEntropyLoss
  - 说明 PyTorch `CrossEntropyLoss` 通常接收 raw logits，不需要先手动 Softmax
  - 标签通常是类别索引，而不是已经 Softmax 的概率；软标签场景要单独说明 API 支持情况
- Softmax：
  - 常用于解释概率、推理展示或采样
  - 训练时是否显式使用取决于 loss API

## 7. 标签格式、数值稳定、reduction 和 mask
这一章用于补足工程训练最容易写错的边界，不要写成框架 API 手册。

必须覆盖：
- 标签格式：
  - 回归标签通常是连续 float
  - 二分类/多标签 BCE 标签通常是 float 且和输出同 shape
  - 多分类 CE 标签常见形式是 class index，软标签或 one-hot 要看具体 API
- 数值稳定：
  - 直接对概率取 `log` 容易遇到 `log(0)`
  - `BCEWithLogitsLoss`、`CrossEntropyLoss` 这类 logits 版本通常内部做了更稳定的计算
  - Softmax + log 的组合应讲清 `logsumexp` 思路，但不要展开成数值分析长文
- reduction：
  - `none` / `mean` / `sum` 会改变 loss 聚合方式和梯度尺度
  - batch size、梯度累积、分布式训练会影响 loss 数值的解释
- 权重与 mask：
  - `class_weight` / `pos_weight` / `sample_weight` 改变不同样本或类别的惩罚强度
  - 序列任务、检测任务或 padding 位置需要 `ignore_index` 或 mask，避免无效位置参与 loss

## 9. 损失函数和评估指标为什么经常不一致
必须覆盖：
- Accuracy：
  - 不可微，且对类别不均衡不敏感
- F1 / Precision / Recall：
  - 依赖阈值，适合关注正类、召回或误报场景
- AUC：
  - 衡量排序能力，不等同于概率校准
- MAE / RMSE：
  - 既可以是 loss，也可以是 metric，但用途和解释要分清
- 解释为什么训练时用 Cross Entropy，评估时看 Accuracy/F1/AUC 是常见组合
- 用一个小例子展示：

## 10. 工程实践中的选择规则
给出实用但不绝对化的判断：
- 连续值回归：
  - 默认从 MSE 开始
  - 离群点明显时考虑 MAE 或 Huber
- 二分类：
  - 默认使用 logits + BCEWithLogitsLoss
- 多标签分类：
  - 使用多个独立 logits + BCEWithLogitsLoss
- 多分类单标签：
  - 默认使用 logits + CrossEntropyLoss
- 类别不均衡：
  - 可考虑 class weight、sample weight、Focal Loss 或重采样
- 多任务学习：
  - 目标函数可能是多个 loss 的加权和，需要关注 loss 尺度
- 软标签、蒸馏或 label smoothing：
  - 关注目标分布和 loss API 是否支持概率标签
- 序列建模、目标检测、分割：
  - 关注 mask、ignore index、类别权重和空间/时间维度上的 reduction
- 排序或相似度学习：
  - 可作为补充介绍 Contrastive Loss、Triplet Loss、Margin Ranking Loss 的适用边界
- 不要只看训练 loss，要同时看验证集 metric、过拟合迹象和业务指标

## 11. 常见误区与反例
必须包含：
- “loss 就是 metric”是误区
- “loss 越低，业务效果一定越好”是误区
- “多分类训练前要手动 Softmax 再喂给 CrossEntropyLoss”在很多框架里是错误用法
- “二分类一定要输出两个类别再 Softmax”不是必需，单 logit + Sigmoid/BCE 更常见
- “MSE 简单，所以分类也优先用 MSE”是误区
- “标签 one-hot、class index、概率分布可以随便替换”是误区，必须匹配 loss API
- “`mean` 和 `sum` 只是显示方式不同”是误区，它们会影响梯度尺度和学习率感受
- “padding 位置无所谓，模型会自己学会忽略”是误区，无效位置参与 loss 会污染训练信号
- “评估指标不可微就不能用”是误区，它可以用于评估、早停和模型选择，但通常不直接反向传播
- “只换 loss 就能解决所有训练问题”是误区，还要看数据、标签噪声、模型结构、采样、正则化和学习率
