# 旧笔记知识地图整理提示词模板

本文维护旧 Markdown 笔记库整理类提示词，重点从已有零散笔记中提取知识概念、识别重复与残缺、构建知识地图，并规划哪些内容适合做一图流、串讲或《一文读懂》重建。

本模板输出 Markdown 分析报告，不生成 HTML；后续真正生成一图流或《一文读懂》成品时，再切换到对应 HTML 生成模板。

使用方式：直接复制下面代码块作为完整提示词使用；笔记目录、文件清单、原文片段、目标领域和期望粒度由具体整理任务补充。

## 提示词

```md
请基于我提供的 Markdown 笔记库内容，做一次知识库盘点和知识地图整理。

核心目标不是重写旧笔记，不是润色原文，也不是直接生成新的《一文读懂》成品，而是先从旧笔记中提取知识结构：识别有哪些概念、主题、主节点、子节点、重复内容、半成品内容和缺口，并规划后续哪些内容适合做一图流、串讲或独立《一文读懂》。

请注意：
- 用户提供的文件名、标题和片段只代表旧笔记现状，不等于最终知识结构
- 不要按“一个旧文件 = 一个新节点”机械整理，要按知识概念、关系和读者理解路径重新归类
- 不要直接改写整篇旧笔记；只提取结构、关系、问题和重建建议
- 如果需要基于领域常识补充可能遗漏的概念，必须标记为“建议补充 / 待确认”，不要伪装成旧笔记中已经存在的内容
- 如果不同笔记之间存在重复、冲突、范围重叠或半成品状态，要明确指出，并给出合并、拆分、归档或后续补写建议

输出格式要求：
- 本次输出使用 Markdown，不生成 HTML
- 用 Markdown 标题组织主要章节
- 概念清单、文件映射和重建计划优先用表格
- 缩进树、关系表或 Mermaid 只在能明显降低理解成本时使用
- 不要为了满足格式而强行画图
- 不要输出 HTML 标签、内联样式、网页布局或单文件网页结构
- 不要输出最终《一文读懂》正文，只输出整理结果和重建建议

请按以下结构输出：

## 1. 笔记库现状总览

- 概括这批笔记大致覆盖的领域、主线和内容形态
- 判断当前主要问题：重复、散乱、缺主线、概念缺口、粒度不一致、半成品过多、标题和内容不匹配等
- 说明哪些内容已经可复用，哪些内容需要重构，哪些内容只适合作为素材暂存

## 2. 概念抽取与归类

从笔记中提取核心概念，并按知识层级归类。每个概念尽量包含：

- 概念名称
- 所属层级：领域 / 主分类 / 主节点 / 子节点 / 机制 / 流程 / 方法 / 工具 / 应用 / 评估方式
- 来源文件或来源片段
- 当前状态：完整 / 可合并 / 重复 / 半成品 / 只是一条线索 / 待确认
- 和其他概念的关系：上下位、依赖、因果、流程、对比、替代、演进或应用关系

## 3. 知识地图草案

输出一份可用于后续维护的知识地图草案，优先按读者理解路径组织，而不是按旧文件目录组织。

建议包含：
- 主领域
- 主分类
- 主节点
- 子节点
- 节点之间的连接关系
- 推荐阅读或理解顺序
- 哪些节点是地基，哪些节点是分支，哪些节点是应用出口

如果关系复杂，可以用缩进树、关系表或 Mermaid 图表示意；可视化只服务结构理解，不要为了形式感画图。

## 4. 重复、残缺与冲突整理

列出需要处理的问题：

- 重复内容：哪些文件或段落讲的是同一件事，建议保留哪条主线
- 范围重叠：哪些内容应该合并成一个主节点，哪些应该拆成多个子节点
- 半成品内容：哪些只有灵感或片段，后续需要补哪些信息
- 概念缺口：按该领域知识结构看，可能缺少哪些关键概念，并标记为“建议补充 / 待确认”
- 表达问题：哪些标题、分类或文件名容易误导后续维护

## 5. 链接与外部资料清单

如果旧笔记中包含 URL、论文链接、GitHub 仓库、官方文档、博客、教程、视频、数据集或工具链接，请提取并整理为表格。

只整理用户提供内容中已经出现的链接、引用或外部资料线索；不要联网检索、不要主动补全外部资料、不要编造旧笔记中没有出现的链接。如果某类资料明显缺失，只标记为“待补充资料需求”。

每条链接尽量包含：

- 链接标题或上下文
- URL / 来源标识
- 出现位置：来源文件、段落或片段
- 资料类型：官方文档 / 论文 / 仓库 / 博客 / 教程 / 视频 / 数据集 / 工具 / 未知
- 关联概念或知识节点
- 用途或处理建议：核心参考 / 补充阅读 / 待核实线索 / 暂存 / 归档候选
- 当前状态：已在笔记中使用 / 重复链接 / 需核验 / 待补来源

不要把链接正文内容完整搬运到报告里，只提取链接、上下文、分类和用途判断。没有实际访问验证时，不要断言链接有效、失效或内容过时，只能标记为“需核验”。

默认不要单独生成链接库文件；如果外部资料数量较多、跨多个重建节点复用，或用户明确要求，可以在报告中建议后续单独维护 `links.md` 或 `references.md`。

## 6. 内容形态建议

为每个重要节点判断适合的重建形态：

- 一图流：适合概念关系、流程链路、分类树、对比边界、模型演进、架构层级
- 串讲：适合多个概念必须连起来理解的主链路，例如“问题 -> 机制 -> 结果 -> 取舍”
- 一文读懂：适合稳定、重要、可独立解释的核心概念、主节点、模型、框架或项目
- 暂存素材：适合信息不足、价值未确认、只是一条线索或暂时不值得整理的内容
- 归档候选：适合重复、过时、和当前知识地图关系很弱的内容

输出时请说明推荐理由，不要只给标签。

## 7. 后续重建路线图

给出一个低维护成本的重建计划：

- 第一批优先建设的主节点
- 适合先做的一图流
- 适合串讲的主题
- 适合独立《一文读懂》的节点
- 暂时不处理或只归档的内容
- 每个候选重建项的标题建议、目标、输入素材和依赖关系

优先让知识库变得有序，而不是追求一次性补全所有内容。

这里只列候选节点、推荐理由、重建输入和依赖关系，不展开文章大纲或正文。

## 8. 文件处理建议

给出旧文件到新知识地图节点的映射建议：

- 保留
- 合并
- 拆分
- 改名
- 移动到素材区
- 归档候选

不要建议直接删除旧笔记；如果确实不建议继续维护，只标记为“归档候选”，等待人工确认。
```

## 维护规则

- 本模板只负责旧笔记库盘点、概念抽取、知识地图整理和重建规划，输出 Markdown 分析报告，不负责生成 HTML，也不负责生成最终《一文读懂》正文。
- 模板正文必须保持可独立复制使用，不依赖其他提示词片段。
- 不要把旧文件名机械等同为新知识节点；整理结果应以概念关系、读者理解路径和后续维护成本为准。
- URL 和外部资料应在报告内单独归类，避免散落在概念节点中；只整理用户提供内容中已有的链接线索，不默认联网检索或单独生成链接库文件。
- 如果后续要生成某个节点的正式文章，再切换到知识点、领域知识地图、模型、语言框架或开源项目等专项模板。
