# 领域知识地图提示词模板 - 一文读懂版

本文维护领域级知识地图类《一文读懂》专项提示词，重点补充领域边界、全局结构、概念层级、分支关系、深入入口和容易混淆的边界，帮助读者在深入细节前先建立领域总览，而不是生成完整课程、术语词典或单点概念讲解。

使用方式：直接复制下面代码块作为完整提示词使用；只需要在生成任务中补充领域名称、读者背景、关注方向和期望深度。用户给出的零散概念、笔记文件名或已有材料只作为背景线索，不作为完整目录或覆盖清单。

## 提示词

```md
请以「深度学习基础概念知识地图」为主题，生成《一文读懂》单文件交互式 HTML。

核心目标不是讲完整课程，不是生成术语词典，也不是深入某几个单点概念，而是帮助读者先建立领域知识地图：知道这个领域覆盖什么、主干分支有哪些、关键概念分别处在哪一层、概念之间如何连接，以及后续可以按兴趣、问题或应用目标深入哪里。

如果用户提供了零散概念、笔记文件名、已有材料或随手举例，只把它们当作理解用户关注方向的背景线索；不要把它们当成完整目录、覆盖清单或生成边界。请主动补全该领域中基础、关键、常见、容易混淆、对后续深入学习有支撑作用的概念，并把它们放回整体结构中解释。

建议：
- 先切清领域边界：讲清这个领域是什么、不是什么，和相邻领域、上位概念、下位分支分别是什么关系
- 先给全局结构，再展开局部概念；优先呈现“领域全景 -> 主干分支 -> 关键概念 -> 典型方法/对象 -> 应用场景 -> 深入入口”的理解路径
- 主动补全领域概念版图，不要只围绕用户可能已经知道、已经提到或已有笔记覆盖的少数概念展开
- 把概念放回层级中解释：区分基础概念、核心机制、子领域、方法体系、模型/工具/对象、流程环节、评估方式、工程实践和应用方向
- 讲清概念之间的关系：上下位关系、依赖关系、因果关系、流程关系、替代关系、演进关系和应用关系
- 每个主干分支都回答三个问题：它解决什么问题、依赖哪些前置概念、常见代表对象或产物是什么
- 对容易混淆的概念做边界对照，说明它们为什么容易混、上下位关系是什么、适用范围有什么不同、应该如何判断
- 给出“先认识即可 / 需要理解 / 值得深入”的分层标记，帮助读者避免一开始陷入所有细节
- 给出按目标选择的深入入口，例如偏理论、偏工程、偏应用、偏研究、偏产品或偏实践时分别应该优先看哪些分支
- 输出应包含“看到一个新名词时如何归类”的小节，帮助读者把零散笔记放回知识地图
- 示例只服务全局理解：可以选择 1-2 个典型问题贯穿展示它们如何落到概念、方法、流程、工具和应用，不要把每个概念都写成长篇解释
- 重视可视化：用知识树、分层地图、概念关系图、任务-方法-工具-应用矩阵、演进时间线或边界对照表呈现抽象结构
- 善用交互：可通过点击分支展开、视角切换、场景筛选、术语悬停解释、关系高亮、知识卡片翻转、路径选择器等方式帮助读者主动探索
- 单文件内联资源，离线可打开；自然中文表达，专业术语、模型名、算法名、工具名、代码、命令和文件名保留英文
- 首屏必须直接呈现领域全景地图或可交互大纲，让人一眼看到领域范围、主干分支和可进入的学习方向
```

## 维护规则

- 本模板只维护领域总览的对象差异：领域边界、全局结构、概念层级、分支关系、边界对照、分层标记和深入入口。
- 模板正文必须保持可独立复制使用，不依赖其他提示词片段。
- 具体任务中的零散概念、笔记文件名或已有材料只作为背景线索，不应写成模板的固定覆盖清单。
- 如果某个要求只适用于单一知识点、模型、语言框架或开源项目，优先放进对应专项模板，不要写进领域知识地图模板。
- 如果后续需要具体学习计划、练习题、论文路线或项目实战路线，单独新增专项片段，不要把本模板变成课程大纲。
