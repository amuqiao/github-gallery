01它是什么？解决什么问题？

一句话：视频界的「全自动翻译流水线」

想把一部中文教程视频发到 YouTube 面向英语观众，传统做法要：听录逐句文稿 → 人工翻译 → 找配音或自己念 → 剪辑对轨 → 压制字幕。 一个 10 分钟视频可能耗掉一整天。

pyVideoTrans 把这条链路整个自动化了。你只需选择视频、源语言、目标语言和一个配音声音，点击开始， 软件依次完成音频分离、语音识别（ASR）、字幕翻译、语音合成（TTS）、音画对齐和最终合成，最后输出一个 「说着目标语言、带目标语言字幕」的新视频。

它的三个关键设计取向：

🧩

模块化 · 每一环都可换

识别、翻译、配音三大环节各自支持二十多种渠道/模型，本地模型与在线 API 自由组合，不被任何单一服务绑死。

🔒

可完全离线

Faster-Whisper 识别 + Ollama/M2M100 翻译 + 本地 TTS，全流程可在本机跑通，隐私敏感素材不出电脑。

🎛️

可暂停校对

识别、翻译、配音每个阶段都可以暂停下来人工修改字幕再继续，兼顾自动化效率与成品质量。

02核心功能一览

不只是「视频翻译」，更是一个音视频处理工具箱

🎥

全自动视频翻译

一键完成 ASR → 翻译 → TTS → 合成的完整链路，这是软件的主功能（标准模式）。

📝

音视频转字幕

批量把音频/视频转成 SRT 字幕，支持说话人分离（Speaker Diarization），自动区分「谁在说话」。

🗣️

多角色 AI 配音

为不同说话人分配不同配音音色——访谈、对话类视频不再「一个声音念到底」。

🧬

声音克隆配音

集成 F5-TTS、CosyVoice、GPT-SoVITS 等零样本克隆模型，可从原视频截取参考片段，让配音保留「原声音色」。

🌐

字幕翻译

单独翻译 SRT 字幕文件，支持传统机器翻译和 LLM 翻译（可结合上下文，译文更自然），可输出双语字幕。

🔊

字幕配音

拿一份 SRT 字幕直接合成整段配音音频，常用于给已有字幕的视频补配音。

🛠️

辅助工具箱

人声/背景音分离、音视频合并、字幕嵌入、音画对齐、文稿匹配等一批实用小工具。

💻

四种使用形态

图形界面（GUI）、命令行（CLI，适合服务器批处理）、浏览器 WebUI（远程/内网）、Docker 容器化部署。

03工作原理：九阶段处理流水线

理解了这条流水线，就理解了整个项目（官方架构文档 v4.03）

软件把「视频翻译配音」拆解为 9 个独立阶段，像工厂流水线一样依次执行。 每个阶段职责单一、可被跳过——这正是它能衍生出多种工作模式的原因。颜色对应四大环节： ■ 识别 ■ 翻译 ■ 配音 ■ 合成。

①

预处理 prepare()

用 FFmpeg 把视频拆成「无声视频流 + 原始音频流」；可选人声/背景分离（UVR / Spleeter）与降噪；建立缓存目录。

▼
②

语音识别 recogn()

调用 ASR 引擎（默认 Faster-Whisper，共支持 22 种渠道）把音频转成带时间戳的 SRT 字幕；可选标点恢复、LLM 智能重新断句。

▼
③

说话人分离 diariz()

用 pyannote、阿里 CAM++ 等模型给每条字幕标注说话人（spk），为多角色配音做准备。此步失败不会阻断整体流程。

▼
④

字幕翻译 trans()

把源语言字幕翻译为目标语言（支持 24 种翻译渠道：DeepSeek、ChatGPT、Gemini、谷歌、微软、本地 Ollama 等），可生成双语字幕。

▼
⑤

配音 dubbing()

按目标字幕逐条调用 TTS 引擎（34 种渠道）合成语音；克隆类引擎可自动从原音频截取参考片段来复刻原声音色。

▼
⑥

音画对齐 align()

最见功力的一步。翻译后句子长度必然变化（中译英通常变长），软件通过「配音加速 + 视频慢放 + 去除字幕间隙静音 + 强制对齐」组合策略，让新配音精确贴合原画面口型节奏。

▼
⑦

二次识别 recogn2pass()

对合成好的配音再做一次 ASR，重新生成时间轴更精确、句子更短小的字幕——保证最终字幕与配音严丝合缝。

▼
⑧

最终合成 assembling()

FFmpeg 把无声视频流、新配音、背景音乐、目标字幕合并为成品视频（字幕可硬嵌或软封装）。

▼
⑨

收尾 task_done()

把成品从临时目录移入输出目录，清理缓存，发送完成通知。

为什么要「人声分离」？如果视频有背景音乐，直接替换音轨会把 BGM 一起丢掉。 先把人声和背景分开，只翻译替换人声，最后再把原背景音乐合回去——成品听感自然得多。

04五个开关 = 多种工作模式

流水线之所以灵活，靠的是 5 个布尔标志位

每个任务创建时会根据你的配置自动算出 5 个标志位，决定哪些阶段被执行、哪些被跳过 （定义于 videotrans/task/_base.py）： 

should_recogn    # 需要语音识别吗？（没有现成字幕 → True）
should_trans     # 需要翻译吗？（源语言 ≠ 目标语言 → True）
should_dubbing   # 需要配音吗？（选择了配音角色 → True）
should_hebing    # 需要合并嵌入吗？（有配音或需嵌字幕 → True）
should_separate  # 需要人声/背景分离吗？

不同的开关组合，就「拼」出了软件菜单里的各种功能：

功能识别翻译配音合并
视频翻译配音（标准模式）✓✓✓✓
音视频转字幕（提取模式）✓可选✗✗
字幕配音✗✗✓✓
仅翻译字幕文件✗✓✗✗

这是一种很值得学习的工程设计：不为每个功能写一套代码，而是用一条流水线 + 开关组合覆盖所有场景， 新功能往往只是一种新的开关组合。

05内部架构：多线程「生产者-消费者」

批量处理 100 个视频时，它是怎么不卡界面、还能并行的？

软件基于 多队列 + 专职工作线程 的经典生产者-消费者模式（PySide6 的 QThread）：

  1. 生产者投料

    MultVideo 线程把每个视频封装为任务对象，推入第一个队列 prepare_queue。

  2. 九类专职 Worker 接力

    每个处理阶段对应一类 Worker 线程（WorkerPrepare、WorkerRegcon、WorkerTrans、WorkerDubb、WorkerAlign、WorkerAssemb……），各自只盯自己的专属队列，取到任务就处理。

  3. 按开关智能路由

    Worker 干完活后，根据任务的标志位决定「下一跳」：比如翻译完成后，有配音角色就丢进 dubb_queue，没有就直接跳到合成或收尾队列。

  4. 统一容错

    所有 Worker 继承同一个 BaseWorker 基类，异常被统一捕获并翻译成用户可读的错误提示；单个任务失败不影响队列中的其他任务。

这带来两个直观好处：① 流水线并行——第 1 个视频在配音时，第 2 个视频可以同时在做识别，批量效率高； ② 界面不冻结——所有重活都在后台线程，主线程只负责 UI 与进度信号。

技术栈速览：Python 3.10+ · GUI 用 PySide6（Qt）· 音视频处理靠 FFmpeg · 本地识别用 faster-whisper · WebUI 基于 Gradio · 任务配置用分层 dataclass 体系（TaskCfgBase → STT/TTS/STS → VTT）。

07安装与使用

从「双击就能用」到「服务器批量部署」

方式一：Windows 整合包（最简单）

  1. 下载

    到 GitHub Releases 页面下载预打包版本（Win 10/11，免装 Python）。

  2. 解压

    解压到不含中文和空格的路径，如 D:\pyVideoTrans（不要在压缩包里直接运行）。

  3. 启动

    双击 sp.exe。想用 GPU 加速需安装 CUDA 12.8 与 cuDNN 9.11。

方式二：源码部署（macOS / Linux / 开发者）

官方推荐用 uv 管理环境；前置要求：Python 3.10、FFmpeg（须在 PATH 中）。

# 1. 安装 FFmpeg（macOS 示例：brew install ffmpeg libsndfile git）
# 2. 克隆并安装依赖
git clone https://github.com/jianchang512/pyvideotrans.git
cd pyvideotrans
uv sync

# 3. 启动图形界面
uv run sp.py

方式三：命令行 CLI（服务器 / 批处理）

# 视频翻译：中文 → 英文，用指定配音角色
uv run cli.py --task vtv --name "./video.mp4" \
  --source_language_code zh-cn --target_language_code en \
  --voice_role "en-US-GuyNeural"

# 音频转字幕
uv run cli.py --task stt --name "./audio.wav" --model_name large-v3

# 翻译字幕文件
uv run cli.py --task sts --name "./subs.srt" --target_language_code en

# 字幕转语音
uv run cli.py --task tts --name "./subs.srt" --voice_role "zh-CN-YunyangNeural"

四个任务代号即四种核心模式：vtv 视频翻译、stt 语音转字幕、sts 字幕翻译、tts 字幕配音。

方式四：WebUI / Docker（远程与容器化）

# WebUI（基于 Gradio，浏览器访问，适合内网共享）
uv sync --extra webui
uv run webui.py

# Docker 部署
docker build -t pyvideotrans-webui .
docker run -d -p 7860:7860 --name pyvideotrans pyvideotrans-webui

08实战建议与常见坑

来自文档与社区的高频经验

🎧

源音频质量决定上限

识别是整条链路的第一环，嘈杂/带混响的音频会让后续全部走偏。BGM 重的视频务必勾选人声分离。

✍️

善用「暂停校对」

在识别和翻译完成后暂停，花几分钟人工修正字幕，成品质量远高于全自动一把梭。

⏱️

理解音画对齐的取舍

译文变长时只能「配音加速」或「视频慢放」，两者都开由软件自动平衡；语速要求高的内容建议先精简译文。

🖥️

GPU 不是必需但很值

CPU 也能跑，但 Faster-Whisper 在 NVIDIA GPU（CUDA）下速度提升数倍；长视频批量处理强烈建议上 GPU。

🈶

路径避开中文与空格

Windows 下软件目录和素材路径尽量使用纯英文路径，可避开大量 FFmpeg 相关的诡异报错。

📖

遇到报错先查文档

官方文档 pyvideotrans.com 与问答社区 bbs.pyvideotrans.com 覆盖了绝大多数 FAQ，社区支持把错误日志交给 AI 自动分析。

一段话总结

pyVideoTrans 的本质是一条可自由换件的视频本地化流水线： 九个阶段各司其职，五个开关组合出全部功能，几十种识别/翻译/配音引擎即插即用， 从「双击 exe 的小白」到「Docker 批量部署的团队」都能找到自己的用法。 如果你有跨语言分发视频内容的需求，它几乎是目前开源世界里最完整的一站式方案。
