一文读懂 · 多目标跟踪 (MOT) · ECCV 2022

ByteTrack 每一个检测框都算数 —— 用两级关联,把"低分框"从垃圾堆里救回来

多目标跟踪器几乎都要先把低置信度的检测框扔掉,可目标被遮挡时,分数恰恰会掉下去——被扔掉的往往正是最需要跟住的那个人。ByteTrack 的回答简单到近乎朴素:低分框不扔,让已有轨迹的运动预测来给它们"作保"。下面这段画面就是全文的主线:行人 B 走进棚架、检测分数跌破阈值,注意它的 ID 有没有丢。

SECTION 01 · 问题建模

多目标跟踪,和一个躲不开的"阈值困境"

输入:一段视频,以及一个检测器(如 YOLOX)在每一帧给出的检测框集合 D_t = {(box, score)}。输出:一组轨迹 {T_k},每条轨迹是"同一个物体在连续帧中的 box 序列",带有全程一致的身份 ID。这就是 tracking-by-detection 范式:检测器负责"每帧有什么",跟踪器负责"跨帧是谁"。

核心难点只有一个词:关联 (association)——把第 t 帧的检测框正确接到第 t−1 帧的轨迹上。关联依赖两个前置件:一个不太差的检测器,和一个跨帧相似度(经典做法是 Kalman filter 预测轨迹下一帧位置,再算预测框与检测框的 IoU,用 Hungarian 算法做二分图最优匹配——这套组合就是 SORT)。

那问题出在哪?检测器的每个框都带一个置信度分数,而传统流程的第一步是设一个阈值 τ,把低分框全部丢掉。现在请你亲手挑一个 τ:

交互 · 一帧检测结果,8 个框,τ 放哪?
τ = 0.60(虚线以下丢弃)拖动滑杆试试
✅ 保留真目标 3/5
🕳️ 漏掉被遮挡目标 2/2
👻 混入背景误检 0/3

你会发现不存在两全的 τ:真目标(尤其被遮挡的)和背景误检的分数分布是重叠的。τ 调高,遮挡目标的框被丢掉,轨迹在遮挡期断裂、目标重现时换 ID(碎片化 + ID switch);τ 调低,大量误检涌入匹配,产生虚假轨迹。SORT、DeepSORT、FairMOT 等一整代方法都默认接受了这个困境,只在"丢掉低分框之后"做文章。

ByteTrack 的破题:不在一维的分数轴上选点,而是把检测框按分数分成高分池 D_high和低分池 D_low两档,分两轮、按不同的规则使用。低分框不再靠分数自证清白,而是靠"有没有一条已存在的轨迹预测到了它的位置"来甄别——用运动先验代替分数阈值做判决。这套关联策略叫 BYTE(意为每个 box 如同 byte,再小也保留),ByteTrack = BYTE + YOLOX 检测器。
SECTION 02 · 核心对象与状态

跟踪器脑子里装着什么

BYTE 是一个逐帧推进的在线算法:任何时刻只依赖"当前帧检测 + 已维护的轨迹状态",不回看未来。它维护的核心状态出乎意料地少:

① 轨迹对象 STrack

每条轨迹是一个 Kalman filter 实例,状态向量为 (x, y, a, h, vx, vy, va, vh)——中心坐标、宽高比、高度,以及各自的速度。predict 按匀速假设外推一帧;update 用匹配上的检测框修正位置与速度。速度是这套系统唯一的"记忆",它让轨迹在没有检测的帧里也能推测目标去了哪。

② 轨迹生命周期(状态机)

New 新建→Tracked 跟踪中⇄Lost 暂失(保留 track_buffer 帧)→Removed 移除

Tracked 轨迹某帧没匹配上任何框 → 转 Lost,但不删除,继续参与后续帧的(第一次)关联,给短暂消失的目标留复活窗口;连续 Lost 超过 track_buffer(默认 30 帧 ≈ 1 秒)才 Removed。

③ 每帧的两个检测池

D_high score ≥ τ_high(≈0.6):可信度高,享有全部权限——可匹配任何轨迹,匹配剩下的还能新建轨迹。
D_low τ_low ≤ score < τ_high:嫌疑对象,权限受限——只能在第二轮匹配"刚刚还在被跟踪、这一轮却没配上"的轨迹,匹配不上就丢弃,永远不能新建轨迹。

注意这个不对称的权限设计:高分框能"开户",低分框只能"续命"。这一条不起眼的规则,是低分框敢被留下的全部前提——后面§5 会解释为什么。

SECTION 03 · 主流程

每一帧,五步走:预测 → 一关 → 二关 → 收尾

0 · 检测分池检测器出框,按分数切成 D_high / D_low
1 · Kalman 预测所有轨迹(含 Lost)外推到当前帧
2 · 第一次关联D_high × 全部轨迹,IoU + Hungarian
3 · 第二次关联D_low × 一关剩下的 Tracked 轨迹
4 · 收尾剩余高分框开新轨迹;没配上的轨迹转 Lost;超时 Removed;剩余低分框丢弃
# BYTE 关联(论文 Algorithm 1 简化版)
输入: 视频 V, 检测器 Det, 阈值 τ_high, τ_low        T ← ∅   # 轨迹集合
for frame f in V:
    D      ← Det(f)
    D_high ← {d ∈ D : score(d) ≥ τ_high}
    D_low  ← {d ∈ D : τ_low ≤ score(d) < τ_high}
    for t in T:  t.kalman_predict()               # 匀速外推一帧

    # ---- 第一次关联:高分框 × 全部轨迹(含 Lost) ----
    M₁ ← Hungarian( IoU(T, D_high) )              # IoU 过低的门控掉
    匹配对 → t.update(d)
    T_remain ← 一关未匹配 且 上一帧仍为 Tracked 的轨迹
    D_remain ← 一关未匹配的高分框

    # ---- 第二次关联:低分框只配"刚刚还在被跟踪"的轨迹 ----
    M₂ ← Hungarian( IoU(T_remain, D_low) )
    匹配对 → t.update(d)
    未匹配的 D_low → 丢弃                          # 永不新建轨迹!
    未匹配的轨迹  → 标记 Lost(保留 track_buffer 帧)

    # ---- 收尾 ----
    for d in D_remain: T ← T ∪ new_track(d)       # 只有高分框能开新轨迹
    移除 Lost 超过 track_buffer 的轨迹
输出: 每条轨迹的 (id, 逐帧 box)

就这么多——没有神经网络做关联、没有外观特征、没有训练。BYTE 是纯粹的匹配策略,新增的只有"第二次关联"这十来行。它能即插即用地装进任何 tracking-by-detection 跟踪器(论文把它装进 SORT、DeepSORT、JDE、FairMOT,MOTA/IDF1 全部上涨)。

  • 两个高分框、零条轨迹 → 一关空转,收尾阶段新建 ID 1(行人A)、ID 2(行人B)。新轨迹只能由高分框创建。
  • 出现 0.28 分的背景误检。BYTE 会看它吗?会——但二关时没有任何"落单"的轨迹可供匹配(A、B 都在一关配上了),于是直接丢弃。误检连参赛资格都拿不到。
  • B 进入棚架,分数跌到低分池。BYTE 模式:一关只配上 A;B 的轨迹落单,进入二关,与低分框 IoU 0.63~0.95,匹配成功——注意 Kalman 速度被低分框持续校正,预测框贴着 B 的拐弯路线走。高分框-only 模式:低分框被直接扔掉,ID 2 转 Lost,预测框按旧速度直直向右漂移,离真实位置越来越远。
  • 再来一个误检(0.33 分)。此时 B 的轨迹确实落单在二关等待——但误检和 B 的预测框 IoU=0,Hungarian 只会把 B 的真实低分框配给它。运动先验完成了分数阈值做不到的甄别。
  • B 走出棚架,分数恢复 0.86。BYTE:轨迹预测早已跟到出口,一关高分匹配,仍是 ID 2。高分框-only:Lost 轨迹的预测漂在老路线上,与新检测 IoU=0,匹配失败 → 收尾新建 ID 3——ID switch 发生,计数器 +1。
  • (仅高分框-only 模式)旧 ID 2 连续 Lost 超过 buffer(演示中设 6 帧),被 Removed。一条轨迹就此碎成两段。
输出语义:算法结束时,每条轨迹给出"ID + 逐帧 box 序列"。BYTE 模式下本场景输出 2 条完整轨迹;高分框-only 模式输出 3 条(其中 B 断成两截)。评测指标里,前者 IDF1/MOTA 更高——ByteTrack 论文在 MOT17 上拿到 80.3 MOTA / 77.3 IDF1,30 FPS,当年同时刷新精度与速度。
SECTION 05 · 为什么这样是对的

低分框凭什么可信?三条支撑直觉

直觉 A · 分数低 ≠ 框是错的

遮挡时分数必然下降

检测分数衡量的是"这块像素看起来多像完整目标"。目标被遮挡、模糊、截断时,框的位置往往仍然大致正确,只是分数掉了。也就是说低分池里混着两类东西:降级的真目标 + 背景误检。按分数一刀切,等于把两类同罪论处。BYTE 的第二次关联正是给前者一条申诉通道。

直觉 B · 运动先验当担保人

二关是"有罪推定 + 保释"

低分框想被采纳,必须满足苛刻条件:恰好有一条上一帧还在被正常跟踪的轨迹,这一帧没配上高分框,且其 Kalman 预测与该低分框 IoU 足够高。背景误检出现的位置是随机的,几乎不可能连续多帧撞进某条轨迹的预测框里;而被遮挡的真目标恰好就在预测位置上。先验越强,甄别越准——这也解释了为什么二关只用刚落单的 Tracked 轨迹、不用 Lost 轨迹:Lost 已多帧未校正,预测不确定性大,拿不可靠的先验去担保不可靠的观测,错配风险陡增。

直觉 C · 不对称权限封死风险敞口

低分框只能续命,不能开户

最坏情况下误检真的骗过了二关会怎样?它只能让一条已有轨迹多续一帧(下一帧大概率被真检测拉回),永远不会凭空制造一条虚假轨迹——因为新建轨迹是高分框的专属权限。虚警的代价被结构性地封顶了。这就是为什么"保留低分框"在 BYTE 里安全,而在"直接调低 τ"的方案里是灾难。

直觉 D · 一个隐含不变量

轨迹连续性靠"持续校正"维持

实验台里最关键的一幕:高分框-only 模式下保留 Lost 轨迹也没能救回 B——因为 B 拐了弯,匀速预测在 4 帧无校正后已漂出目标一整个身位。BYTE 维持的不变量是:只要目标还产生任何检测证据(哪怕低分),轨迹的状态估计就与真实位置保持同步。匀速假设只需在"相邻两帧"这个尺度上近似成立即可,而这几乎总是成立的。

SECTION 06 · 成本、参数与边界

代价几乎为零,但要知道它在哪些地方会碎

复杂度:设当前轨迹数 N、检测数 M(拥挤场景也就几十上百)。每帧开销 = IoU 矩阵 O(N·M) + Hungarian 匹配 O(n³) + Kalman 常数级更新——微秒到毫秒级。第二次关联只是把这套流程再跑一小遍,整条流水线的瓶颈完全在检测器上(ByteTrack 的 30 FPS 里 YOLOX 占了绝大头)。内存上仅多保留 Lost 轨迹缓冲,可忽略。这是 BYTE 最漂亮的性价比:近乎零成本换来显著的 IDF1 提升。

关键参数与调法

参数典型值调大 / 调小会怎样
τ_high0.5 ~ 0.6调大:高分池更纯,但更多真目标坠入低分池,轨迹起点变晚、更依赖二关;调小:误检开始混入一关甚至开出假轨迹。对不同检测器需要重标定(分数分布不同)。
τ_low≈ 0.1低分池的地板。调太低,二关候选里噪声框暴增,拥挤场景可能错配;调太高,退化回传统做法。
track_buffer30 帧(≈1s)决定 Lost 轨迹的存活期。调大能挺过更长遮挡,但久未校正的预测漂移后,复活时错接他人的风险上升;调小则短暂消失即断链。
match_threshIoU 门控 ≈ 0.2(一关)低于门控的配对直接禁止。调松:漂移的预测也能强行匹配,易错接;调紧:轻微抖动即断匹配。二关通常用更紧的门控。

适合用 BYTE 的场景

  • 有一个较强的检测器(前置依赖!低分池里得真有"降级真目标",全是噪声就没得救)
  • 帧率较高、相邻帧位移小 —— IoU 与匀速假设都成立
  • 相机静止或缓慢运动(监控、体育转播、无人机悬停)
  • 遮挡频繁但短暂的行人 / 车辆场景 —— 正是它的主场
  • 需要实时、需要简单可维护、不想训练关联模型

会碎的地方(及社区补丁)

  • 相机剧烈运动:匀速模型在图像坐标系里失效,预测框整体漂移 → BoT-SORT 加全局运动补偿 (CMC)
  • 长时遮挡(> buffer)或目标出画再回:纯运动关联无能为力 → 需要 ReID 外观特征找回
  • 外观相似目标近距交叉:两条轨迹预测框重叠,纯 IoU 可能互换 ID → 加外观项,或 OC-SORT 式观测中心化修正
  • 低帧率视频:帧间位移大到 IoU 归零,匹配整体失效
  • 非线性急变机动(体育、无人机竞速):Kalman 匀速先验本身不准,二关的"担保人"失信
SECTION 07 · 迁移与举一反三

把 BYTE 的思想带走

BYTE 首先是一个可插拔组件:任何"逐帧观测 + 轨迹关联"的系统,只要观测带置信度、轨迹带预测,就能加装第二次关联。论文自己做了示范——装到 SORT / DeepSORT / JDE / FairMOT 上全部涨点;后续的 BoT-SORT、以及大量工业部署(行人分析、自动驾驶感知、零售客流)都以它为底座。

更值得带走的是那条抽象原则:

低置信度观测 ≠ 无用观测。先用高置信度观测建立可靠的状态先验,再让先验去甄别低置信度证据——并给低置信度证据以受限的权限(只能延续假设,不能创造假设)。

照这个模子可以套很多相近问题:雷达/声呐点迹关联里对弱回波的二次利用;细胞显微追踪中分裂、失焦导致的弱检测;SLAM 特征匹配里先用强特征解位姿、再用位姿约束回收弱特征;甚至日志异常关联——先由高置信告警建立事件链,再吸纳低置信日志补全链条而不允许它们单独立案。判断能不能迁移,就问三个问题:① 低分证据里是否真的混有降级的真信号?② 是否存在足够强的先验(运动模型 / 几何约束 / 因果链)能替分数做判决?③ 能否把"创造新假设"的权限只留给高置信证据?三个都答"是",BYTE 的结构就能照搬。
