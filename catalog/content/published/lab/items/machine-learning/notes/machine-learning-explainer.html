机器学习,一张地图看清全域

这不是一门课程,而是一张知识地图:先看清领域覆盖什么、主干分支有哪些、每个概念处在哪一层,再决定往哪里深入。理解本页只需要一个核心认知——机器学习不是一棵树,而是同一块领地的三种切法。切换下面的视角,看同一批概念如何重新归位。

按学习范式切(靠什么信号学) 按方法体系切(用什么模型) 按任务应用切(解决什么问题)

追踪一个概念:点击 ,再切换视角,观察它落到哪一列——同一个东西,在不同切法下属于不同分类,这正是初学最容易混乱的原因。

01

先切清边界:机器学习是什么、不是什么

机器学习(Machine Learning, ML)是让计算机从数据中自动学出规律、而不是由人逐条编写规则的一类方法。判断某个东西属不属于 ML,就看这一条:行为是学出来的,还是写死的。

✓ 属于机器学习

  • 给一万封标注过的邮件,让模型学会判断垃圾邮件
  • 让程序自己下几百万盘棋,试错出走子策略
  • 不给任何标签,让算法自己把用户分成几群
  • 大语言模型读海量文本,预训练出语言规律

✗ 不属于机器学习

  • 手写 if 邮件含"中奖" then 拦截 —— 规则系统,没有"学"
  • 数据库查询、报表统计 —— 只是检索汇总,不产生模型
  • 普通爬虫、自动化脚本 —— 自动化 ≠ 智能化
  • 纯专家系统 —— 知识由人编码,而非从数据中归纳

它在更大的版图里处于什么位置

人工智能 AI(上位概念)

一切"让机器表现出智能"的努力,包括不学习的方法(规则系统、搜索、专家系统)。

机器学习 ML(AI 的主流实现路径)

从数据中学规律。同时与统计学深度重叠、被数据科学作为核心工具使用。

深度学习 DL(ML 的一类方法)

用深层神经网络自动学特征,是当前 ML 中最主流的方法体系,但不是全部——XGBoost 在表格数据上仍常胜过它。

常见误解:"AI = 机器学习 = 深度学习 = 大模型"。实际是层层包含关系:大模型 ⊂ 深度学习 ⊂ 机器学习 ⊂ 人工智能。日常语境混用没问题,但读文献、做技术选型时必须分清层级。
02

主干分支:每一支解决什么、依赖什么、产出什么

下面按首屏地图的三个视角组织。每个分支都回答三个问题:解决什么问题 / 依赖哪些前置概念 / 代表对象或产物是什么。点击展开。标记含义:先认识即可 需要理解 值得深入

按学习范式:靠什么信号学

解决什么问题有"标准答案"(标注数据)时,学习输入到输出的映射。两大任务:分类(离散类别)与回归(连续数值)。
依赖的前置概念特征 feature、标签 label、损失函数、训练集 / 测试集划分、过拟合与泛化。
代表对象 / 产物线性回归、逻辑回归、决策树、SVM、随机森林、XGBoost;产物是一个可预测的分类器或回归器。

这是 ML 的主战场,工业界 80% 的落地问题(风控评分、点击率预估、质检)最终都被建模成监督学习。入门首选。

解决什么问题没有标签时,发现数据的内在结构:相似的分在一起(聚类)、高维压到低维(降维)、找出异常点(异常检测)。
依赖的前置概念距离与相似度度量、特征空间的概念;评估比监督学习更依赖人的判断。
代表对象 / 产物K-means、层次聚类、PCA、t-SNE;产物是数据的分组或低维表示,常作为下游任务的预处理。
解决什么问题序贯决策:没有现成答案,智能体与环境交互,靠奖励信号试错出最优策略。适合下棋、机器人控制、推荐调度。
依赖的前置概念智能体 / 环境 / 状态 / 动作 / 奖励,马尔可夫决策过程 MDP,探索与利用的权衡。
代表对象 / 产物Q-learning、DQN、PPO;产物是一个策略。RLHF 用它对齐大模型。

除非目标就是游戏 AI / 机器人 / 大模型对齐,初学阶段知道它的定位即可,不必先啃。

解决什么问题标注太贵。半监督:少量标注 + 大量未标注一起学。自监督:从数据本身构造标签(如遮住一个词让模型猜)。
依赖的前置概念监督学习的全部基础,外加"预训练 → 微调"的两阶段思维。
代表对象 / 产物BERT 的掩码预测、GPT 的下一词预测、对比学习 SimCLR;产物是可迁移的预训练模型。

自监督是整个大模型时代的基石——理解它,就理解了 GPT 为什么不需要人工标注也能学会语言。

按方法体系:用什么模型

解决什么问题中小规模、结构化(表格)数据上的预测。需要人先做特征工程,但训练快、可解释、样本效率高。
依赖的前置概念线性代数与概率基础、特征工程、正则化、交叉验证。
代表对象 / 产物决策树、SVM、朴素贝叶斯、集成学习(Random Forest、XGBoost、LightGBM)。

别被"传统"二字误导:表格数据竞赛和企业风控里,梯度提升树至今仍是首选,常打败深度学习。

解决什么问题图像、文本、语音等高维非结构化数据——特征无法人工设计,由多层神经网络自动学出。
依赖的前置概念神经元与层、反向传播、梯度下降、GPU 并行;工程上依赖 PyTorch / TensorFlow。
代表对象 / 产物CNN(图像)、RNN/LSTM(序列,已渐被取代)、Transformer(当前统治级架构)、扩散模型(生成图像)。

关键认知:深度学习横切所有范式——它可以做监督(图像分类)、自监督(GPT 预训练)、强化(DQN)。它回答"用什么模型",不回答"靠什么信号学"。

解决什么问题不只是判别(这是猫还是狗),而是生成新样本:写文章、画图、合成语音。学的是数据的分布本身。
依赖的前置概念深度学习基础、概率分布、自监督预训练。
代表对象 / 产物GAN、VAE、扩散模型(Stable Diffusion)、大语言模型(GPT、Claude)。

按任务应用:解决什么问题

解决什么问题CV:让机器看懂图像(分类、检测、分割、生成)。NLP:让机器处理语言(翻译、问答、摘要、对话)。
依赖的前置概念深度学习方法体系;CV 靠 CNN/ViT,NLP 靠 Transformer 与词嵌入 embedding。
代表对象 / 产物ResNet、YOLO、BERT、GPT;产物是人脸识别、自动驾驶感知、聊天助手等能力。

应用领域是"问题的集合",不是新的学习原理——CV 和 NLP 用的底层范式与方法都来自前两个视角。选一条应用线深入,是最常见的学习路径。

解决什么问题推荐:预测"你会喜欢什么"。语音:识别 ASR 与合成 TTS。时序:预测随时间变化的量(销量、股价、负载)。
依赖的前置概念监督学习为主;推荐还涉及协同过滤与 embedding,时序涉及自相关等统计概念。
代表对象 / 产物协同过滤、双塔模型、Whisper、ARIMA/Prophet;产物是信息流排序、语音助手、销量预测系统。
03

概念层级:每个名词各就各位

学 ML 最大的困扰是名词多且不知道它们"重不重要、在哪一层"。这张八层地图把常见概念全部归位——以后遇到任何新名词,先问它属于哪一层。悬停带虚线下划线的词可看解释。

① 基础概念所有分支共用的地基
无论走哪条线都绕不开 值得深入
特征 feature标签 label损失函数 loss梯度下降过拟合 / 欠拟合泛化 generalization训练 / 验证 / 测试集
② 学习范式子领域,按信号切
监督 · 无监督 · 强化 · 自监督 / 半监督 需要理解
③ 方法体系按模型类型切
传统 ML · 深度学习 · 集成学习 · 概率图模型 · 生成式模型 需要理解
④ 模型 / 算法 / 工具具体可运行的对象
算法与架构:XGBoost ResNet Transformer BERT;框架与库:scikit-learn PyTorch TensorFlow Hugging Face —— 按需掌握,不必穷尽 先认识即可
⑤ 流程环节一个项目的生命周期
数据收集 → 清洗 → 特征工程 → 训练 → 调参 → 评估 → 部署 → 监控 需要理解
⑥ 评估方式怎么判断模型好坏
分类:准确率、精确率 / 召回率、F1、AUC;回归:MSE / MAE;方法:交叉验证 值得深入
⑦ 工程实践让模型活在生产环境
MLOps、数据标注、模型部署与推理优化、A/B 测试、模型监控与漂移检测 先认识即可
⑧ 应用方向问题所在的行业场景
搜索与推荐、金融风控、医疗影像、自动驾驶、智能客服、内容生成 先认识即可
分层标记的用法:①⑥ 两层值得任何人深入(基础概念 + 评估思维决定你能不能正确使用模型);②③⑤ 需要建立准确理解;④⑦⑧ 先认识轮廓,等具体任务出现再按需深入——初学者最常犯的错误就是一头扎进第④层背模型清单。
04

易混概念边界对照

五组最常被混淆的概念。每组给出关系类型、对照表和一句话判断方法。点击展开。

最典型的误会是把它们当并列关系。实际上:强化学习回答"靠什么信号学"(范式层),深度学习回答"用什么模型"(方法层),两者正交。

深度学习强化学习
所在维度方法体系(用不用深层神经网络)学习范式(靠奖励信号试错)
可否组合可以——用深度网络做强化学习 = 深度强化学习(DQN、AlphaGo)
判断法:问"它描述的是数据 / 信号,还是模型结构?" 信号 → 范式层;结构 → 方法层。
概念范围反例(属于上层但不属于本层)
AI一切让机器表现智能的方法——
ML从数据中学规律的 AI规则专家系统是 AI 但不是 ML
DL用深层神经网络的 MLXGBoost 是 ML 但不是 DL
大模型 LLM超大规模自监督预训练的 DLResNet 是 DL 但不是大模型
判断法:从里向外问三次——"用神经网络吗?规模巨大且预训练吗?从数据学吗?" 依次定位到 DL、LLM、ML。
分类 classification聚类 clustering
范式监督学习(有标签)无监督学习(无标签)
类别来源人预先定义(垃圾 / 正常)算法自己发现,含义靠人事后解读
典型算法逻辑回归、决策树、SVMK-means、层次聚类、DBSCAN
判断法:问"训练时知道正确答案吗?" 知道 → 分类;不知道 → 聚类。
参数 parameter超参数 hyperparameter
由谁决定模型从数据中学出来(权重、偏置)人在训练前设定(学习率、树深度、层数)
数量级可达千亿("7B 模型"指 70 亿参数)通常几个到几十个
如何优化梯度下降等训练算法网格搜索、贝叶斯优化,即"调参"
判断法:问"训练结束后这个值是算法算出来的吗?" 是 → 参数;训练前就得填 → 超参数。
统计学机器学习数据科学
核心追求解释与推断:变量间关系是否显著预测与泛化:新样本上准不准用数据解决业务问题的全流程
典型产出置信区间、假设检验结论可部署的预测模型分析报告 + 模型 + 决策建议
关系ML 大量借用统计学理论;数据科学把 ML 作为工具箱之一,还包含数据工程与业务分析
判断法:关心"为什么"(解释)偏统计;关心"预测得准不准"偏 ML;关心"业务问题有没有解决"是数据科学。
05

两个问题贯穿全图

示例的目的不是教会你做项目,而是演示一个真实问题如何逐层落进这张地图:从任务定位到范式、方法、流程、评估、工具、应用,每一步都对应第 03 节的某一层。

示例 A · 垃圾邮件识别(判别式问题的标准路径)

目标:给定一封邮件,判断是否垃圾邮件

任务定位 ⑧→②
这是一个二分类问题;有历史标注邮件 → 落入监督学习范式
方法选择 ③④
起步用传统 ML:词频特征 + 朴素贝叶斯或逻辑回归;数据量大、要理解语义时升级为深度学习(BERT 微调)
流程环节 ⑤
收集邮件 → 清洗(去 HTML)→ 特征工程(分词、TF-IDF)→ 划分训练 / 测试集 → 训练 → 调参
评估方式 ⑥
不能只看准确率——垃圾邮件占比低时全判"正常"也有 95% 准确率。要看精确率(别误杀正常邮件)与召回率(别漏放垃圾)的权衡
工程与应用 ⑦⑧
用 scikit-learn 训练、部署为在线服务、监控误判率随时间的漂移

示例 B · 让模型学会写文章(生成式问题的对照路径)

目标:训练一个能续写文本的语言模型——注意每一层的选择如何不同

任务定位 ⑧→②
生成任务,没有人工标注 → 自监督学习:把"预测下一个词"当作从数据自造的标签
方法选择 ③④
必须用深度学习——语言特征无法人工设计;架构选 Transformer(即 GPT 路线)
流程环节 ⑤
海量文本 → 预训练(学语言规律)→ 指令微调 → RLHF(用强化学习对齐人类偏好——三种范式在此汇合)
评估方式 ⑥
困惑度 perplexity + 基准测试 + 人工评估——生成任务没有唯一正确答案,评估远比分类难
工程与应用 ⑦⑧
PyTorch + GPU 集群训练,推理优化后成为聊天助手、写作工具
对照两条路径可以看到地图的用法:同样的八层结构,不同的问题在每层做出不同选择。会走这张图,比记住任何单个算法都重要。
06

看到一个新名词,如何归类

以后读文章、听分享遇到陌生术语,不要立刻去查教程,先用下面五个问题把它放回地图——多数时候"知道它在哪一层"就够了。

它描述的是"靠什么信号 / 数据学习"?(如对比学习、少样本学习)→放入 ② 范式层,想清它更接近监督、无监督还是强化
它是一种网络结构、算法或具体模型名?(如 ViT、LoRA、LightGBM)→放入 ③/④ 方法与模型层,先只记它属于哪个方法家族、擅长什么数据
它是衡量好坏的指标或验证手段?(如 BLEU、mAP)→放入 ⑥ 评估层,弄清它对应哪类任务
它是软件库、平台或流程工具?(如 MLflow、ONNX)→放入 ④/⑦ 工具与工程层,有具体需要时再学
它是某个业务场景或产品能力?(如 OCR、智能风控)→放入 ⑧ 应用层,追问一句"它底层是哪类任务 + 哪种方法"
都不匹配时,大概率是① 基础概念层的理论词(如"归纳偏置""维度灾难")——这类词值得认真查,因为它们会反复出现在所有分支里。
07

按你的目标选深入入口

全景建立之后,不同目标应该优先走不同的分支。选择你的画像:

想搞懂原理与数学

适合:在校学生、想打牢地基再动手的人

  1. 主攻 ① 基础概念 + ② 范式层:损失函数、梯度下降、偏差-方差权衡,推公式而不只是记结论
  2. 系统读一本教材:周志华《机器学习》(西瓜书)或 Bishop, PRML;进阶 ESL
  3. 数学补给按需进行:线性代数 → 概率统计 → 凸优化,不必全部学完再开始

想成为算法 / ML 工程师

适合:有编程基础、目标是工业界岗位的人

  1. 主攻 ③④⑤⑦ 方法、工具与工程层:scikit-learn 打底,PyTorch 进深度学习
  2. 完整跑通 ⑤ 的全流程若干次:从脏数据到可部署模型,重点练特征工程与调参
  3. 补 MLOps:实验管理、模型部署、监控——工程岗真正的分水岭在第⑦层

想深入某个应用领域

适合:目标明确指向 CV、NLP、推荐等方向的人

  1. 先用 ①②③ 层建立最小共同基础(监督学习 + 深度学习入门即可)
  2. 然后只沿一条应用线垂直深入:NLP 走 词嵌入 → Transformer → 预训练模型;CV 走 CNN → 检测 / 分割 → ViT
  3. 用该领域的经典数据集复现 2–3 个代表模型,比广撒网学十个领域有效得多

想做研究、读写论文

适合:研究生或准备进入前沿方向的人

  1. 在 ②③ 层选定细分方向(自监督、生成式模型、对齐……),读该方向的综述 survey 建立谱系
  2. 精读 5–10 篇里程碑论文并复现其一:如 Attention Is All You Need
  3. 养成追踪习惯:arXiv + 顶会(NeurIPS / ICML / CVPR / ACL)

想做 AI 产品 / 决策

适合:产品经理、业务负责人,不写代码但要做判断

  1. 主攻 ②⑥⑧ 层:分清任务类型(分类 / 生成 / 排序),看懂评估指标,了解每类应用的成熟度
  2. 重点建立能力边界感:什么问题适合 ML(有数据、可容错、模式稳定),什么不适合(强因果、零容错、规则明确)
  3. 学会问工程师三个问题:数据从哪来?怎么评估?错了的代价是什么?
