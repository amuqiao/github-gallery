01 · 能力契约

它承诺什么，不承诺什么

InsightFace 是 deepinsight 团队维护的开源人脸分析库。对使用者来说，它的契约可以压缩成一句话：给我任意一张含人脸的图像，我返回每张脸的位置、关键点和一个 512 维特征向量——向量之间的距离近似"是不是同一个人"。

输入

  • 一张图：BGR 的 numpy 数组（cv2.imread 的产物），任意分辨率
  • 不接视频流、不管抽帧——那是你的循环该做的事

输出

  • list[Face]，每个 Face 含：
  • bbox 人脸框 (x1,y1,x2,y2)
  • kps 五个关键点 (5,2)
  • embedding 512 维特征向量
  • det_score、年龄、性别等附加项

隐含承诺

  • 向量可比：同一人的两张脸，embedding 余弦相似度显著高于不同人
  • 这是整个库最有价值、也最容易被误解的承诺——它给分数，不给判定

明确不负责

  • 活体检测：照片翻拍它照样认
  • 跟踪：帧与帧之间谁是谁，交给 ByteTrack 这类算法
  • 底库检索：百万级向量搜索交给 faiss
  • 阈值：多像算同一人，由你校准
为什么必须是多阶段协同，而不是"一个模型"？因为"认人"在数学上被拆成了两个不同的问题："哪里有脸"是检测问题（对整图做密集预测），"这是谁的脸"是度量学习问题（对标准化的脸产出可比向量）。两个问题用两个专门的模型，而两个模型之间——过滤候选框、把歪脸摆正、比较向量、下判定——全部由不学习的确定性算法衔接。模型决定精度上限，算法决定这些精度能不能被串成可用的能力。
02 · 贯穿案例

两个文件，一个问题

全文只用这一个最小案例，每个阶段都回到它：手里有一张双人合影 photo.jpg 和一张 Alice 的证件照 ref.jpg，要回答——照片里有没有 Alice？

photo.jpg
1280×720 合影，一张大正脸 + 一张较小的侧脸。读入后是 (720, 1280, 3) uint8。
ref.jpg
Alice 的单人正脸照。它会走完全相同的流水线，产出一条 512 维参考向量。
GOALphoto.jpg 里的哪张脸（如果有）与 ref.jpg 是同一个人？期望输出：face 0 → sim 0.62 → 同一人

从代码看，整个案例只有几行——这正是工程封装的意义，也是初学者误以为"它就是一个函数"的原因。下一节把 app.get() 这一行拆开。

import cv2, numpy as np
from insightface.app import FaceAnalysis

app = FaceAnalysis(name='buffalo_l', providers=['CPUExecutionProvider'])
app.prepare(ctx_id=-1, det_size=(640, 640), det_thresh=0.5)   # 关键配置都在这

faces = app.get(cv2.imread('photo.jpg'))     # ← 本文全部内容，都发生在这一行里
ref   = app.get(cv2.imread('ref.jpg'))[0]

for f in faces:
    sim = float(np.dot(f.normed_embedding, ref.normed_embedding))
    print(f.bbox.astype(int), f'sim={sim:.2f}', '同一人' if sim > 0.40 else '不同人')

04 · 分工

模型负责感知，算法负责决策

把整条链路里的部件按"是否需要训练"分成两列，能力形成的结构就一目了然：模型产出的是原始感知（框、点、向量），从感知到答案的每一步都是算法。

模型 · 训练得到的权重（.onnx 文件）
  • det_10g.onnx — SCRFD检测模型：整图进，密集候选出。在 WIDER FACE 数据集上训练，负责"哪里有脸 + 五个关键点在哪"。精度上限在这里锁死：它看不见的脸，后面所有环节都无从谈起。
  • w600k_r50.onnx — ArcFace (ResNet50)识别模型：112×112 对齐脸进，512 维向量出。在 WebFace600K（约 60 万人）上用 ArcFace margin loss 训练。"两个向量近 = 同一人"这个性质，完全是这份权重赋予的。
  • genderage.onnx 等附加模型：年龄性别、106 点、3D 68 点。默认全加载，可用 allowed_modules 砍掉。
算法 · 写在代码里的确定性规则
  • 预处理：等比缩放 + letterbox 填充 + 像素归一化。纯数组运算，错了是坐标系 bug，不是精度问题。
  • 置信度过滤 + NMS：把上万候选删成几个框。det_thresh 和 IoU 阈值是这里的旋钮。
  • 五点对齐（Umeyama 相似变换）：解一个最小二乘，把任意姿态的脸旋转缩放到标准模板。识别精度对它极其敏感。
  • 余弦相似度 + 阈值判定：两次点积、一次比较。整个系统唯一的"业务决策"发生在这里——而这一步 InsightFace 根本不管，是你写的。
一个直接推论：精度不够时先别怪模型。检出的框歪了是检测模型的事，但"同一人被判成两个人"更常见的原因是对齐质量差或阈值不合适——那是算法层的问题，调参数就能救；只有确认输入质量和算法参数都没问题，才轮到"换更大的模型"。

06 · 离线与在线边界

哪些事发生在请求之前，哪些发生在请求之中

理解这个边界，就理解了"什么你能改、什么你只能换"。模型能力全部在离线阶段被冻结进 .onnx 文件；在线阶段没有任何学习发生，每一次 app.get() 都只是同一套权重的确定性回放。

离线 · 一次性发生deepinsight 团队完成，与你无关
采集训练集WIDER FACE / WebFace600K
→
训练SCRFD · ArcFace loss
→
导出 ONNX权重冻结
→
发布 model zoobuffalo_l / s / sc
离线 · 一次性发生你完成，在上线之前
首次运行自动下载~/.insightface/models/
→
注册底库已知人 → embedding 存起来
→
校准阈值用自己场景的同人/异人对画分布
在线 · 每次请求发生app.get() + 你的比对代码
读图ms 级
→
检测 + 后处理耗时大头之一
→
逐脸对齐 + 识别脸越多越慢
→
比对 / 检索点积，几乎免费

结果可信度靠什么判断？在线看两个数：det_score（检测置信度，<0.6 的框慎用其 embedding）和余弦相似度对你校准阈值的距离（0.41 vs 阈值 0.40 是"擦线"，应当降级处理或送人工）。离线的评估口径：检测看 WIDER FACE 三档 AP，识别看 LFW 准确率和 IJB-C 的 TAR@FAR——后者与你的阈值权衡是同一件事的学术表述。

07 · 工程事实

能力藏在哪些文件和参数里

只列直接决定能力形成和错误来源的工程事实：一个入口类、一个模型目录、五个真正常用的配置。

# pip install insightface onnxruntime
# 首次 FaceAnalysis(name='buffalo_l') 自动下载到:

~/.insightface/models/buffalo_l/
├── det_10g.onnx      # SCRFD 检测      [模型]
├── w600k_r50.onnx    # ArcFace 识别    [模型]
├── genderage.onnx    # 年龄性别        [模型]
├── 2d106det.onnx     # 106 点关键点    [模型]
└── 1k3d68.onnx       # 3D 68 点        [模型]

# app.get() 的真实执行顺序:
#   1. det_model.detect()        → 框 + 5 点
#   2. 对每张脸， 遍历其余已加载模型
#      各自 crop/对齐后推理， 结果挂到 Face 对象上
配置作用与踩坑点
name='buffalo_l'选模型包。决定检测和识别用哪份权重，是精度/速度的最大旋钮。
det_size=(640,640)检测输入分辨率。小脸漏检第一个调它（如 1280），代价是检测耗时线性上涨。
det_thresh=0.5置信度门槛。降低能捞回模糊脸，但会放进假阳性，污染下游 embedding。
ctx_id / providers设备选择。装了 onnxruntime 而非 onnxruntime-gpu 时静默回落 CPU，速度慢 10 倍且不报错——最经典的"没坏但很慢"。
allowed_modules只留 ['detection','recognition'] 可跳过年龄性别等模型，单脸延迟明显下降。
08 · 错误传播

失败时，先定位是哪个阶段的锅

这条流水线出错的症状高度雷同（"认不出"或"认错了"），但根因分布在完全不同的阶段。选一个症状，看它的传播路径——上方流水线里对应的阶段会同时标橙。

09 · 取舍与边界

选型三档，和一条必须知道的许可红线

同一套代码，换个 name= 就是完全不同的精度/资源档位——这是"工程与模型解耦"最直接的好处。

模型包检测 / 识别体积 & 速度适用
buffalo_lSCRFD-10GF / ResNet50 @WebFace600K数百 MB，CPU 单图数百 ms 量级默认选它。精度基准，服务器端离线分析
buffalo_sSCRFD-500MF / MobileFaceNet约为 l 的三分之一算力紧张、实时性优先，接受识别精度下降
buffalo_sc仅检测 + 识别两个模型约十几 MB嵌入式 / 边缘设备，只要"检出 + 认人"
⚠ 许可红线：insightface 的 Python 代码是 MIT 协议，但预训练模型权重仅限非商业研究用途。做商业产品要么用自己的数据重训（仓库提供完整训练代码），要么联系团队获得授权。技术选型时这条经常比精度更早淘汰它。

其他边界，按重要性：① 无活体检测，任何涉及权限/支付的场景不能单独用它做门禁；② embedding 属个人生物特征信息，采集与存储受 GDPR / 个保法约束，向量本身即敏感数据；③ 极端姿态（>60° 侧脸）、强遮挡、低分辨率（脸小于约 30px）下精度断崖，这是训练分布决定的，调参救不回来；④ 跨年龄、跨妆容的相似度衰减真实存在，底库照片需要更新机制。

10 · 你该拿它怎么办

四种关系，四个判断

学习 适合 · 作为第一条 CV 流水线

五行代码就能跑通"检测→对齐→识别"完整链路，且每个环节都能拆开单独观察（本文的七个阶段都可以在源码里找到对应文件）。比从论文入手快一个数量级。

使用 适合 · 研究与内部工具

非商业场景下它是事实标准：精度业界第一梯队、API 稳定、社区活跃。记住两件事：阈值必须用自己的数据校准；det_score 低的脸不要信它的 embedding。

集成 谨慎 · 先过许可，再谈架构

商用先解决权重许可。架构上把它当"感知件"：输入标准化（EXIF、BGR）在它上游做，跟踪（ByteTrack）、向量检索（faiss）、活体检测在下游拼——它只负责单帧的框和向量。

深挖 看方向

想懂度量学习，读 ArcFace 的 margin loss，是近十年最优雅的损失函数设计之一；想懂检测，读 SCRFD 的采样与算力分配。仓库里训练代码齐全，可复现，是少见的"论文+工程"双完整的项目。
