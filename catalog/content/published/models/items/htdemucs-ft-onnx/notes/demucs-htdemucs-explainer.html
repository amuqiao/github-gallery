DEMUCS · HTDEMUCS 任务 三代演化 数据流 训练 vs 推理 上手 对比与边界 结论
一文读懂 · Music Source Separation

Demucs / HTDemucs:
把一首混好的歌,拆回四轨

输入一段普通立体声音乐,输出 drums / bass / other / vocals 四条独立音轨。Demucs 是 Meta(FAIR)开源的音乐源分离模型家族,HTDemucs(v4)是其中"卷积 U-Net + 双域 + Transformer"的最终形态,也是目前工程上最常被直接拿来用的开源分离模型之一。

点击试听式 SOLO(高亮某一轨)→
INPUT立体声波形44.1 kHz,tensor 形状 (2, T),任意长度(内部切段处理)
OUTPUT4 条同长度立体声波形(4, 2, T):drums、bass、other、vocals,四轨相加 ≈ 原曲
核心路径波形支路 + 频谱支路两套卷积编码器,底部用 Transformer 跨域互相注意,再各自解码回波形
量级SDR ≈ 9 dBMUSDB18-HQ 测试集;单个 checkpoint 约 80 MB,CPU 可跑,GPU 更快
01 · WHY

它解决什么问题:音乐源分离

一首成品歌曲是混音的结果:鼓、贝斯、人声、吉他键盘等几十轨在录音棚里被叠加成 2 个声道。音乐源分离(music source separation)就是这个过程的逆问题——只拿到混好的 2 声道,把它拆回若干条独立音轨(stem)。它是典型的病态逆问题:加法丢失了信息,不同乐器在时间和频率上大量重叠,没有唯一解,只能靠模型学到的"乐器长什么样"的先验去猜。

输入是什么

  • 任意一段音乐音频(mp3 / wav / flac …),内部统一为 44.1 kHz 立体声波形
  • 不需要 MIDI、歌词、乐器标注等任何附加信息
  • 推理时长曲会被切成约 7.8 s 的重叠片段分别处理再拼回

输出是什么

  • 与输入等长的 4 条立体声波形:drums bass other vocals
  • other 是"剩下的一切":吉他、钢琴、合成器、弦乐都在这里
  • 模型被训练成四轨之和逼近原曲,所以"伴奏"= 原曲 − vocals ≈ 其余三轨之和

为什么会出现 Demucs 这条路线

2019 年之前的主流做法(如 Open-Unmix、Spleeter)是在频谱图上做掩码:对混音做 STFT,用网络预测每个源的 mask,乘回频谱,再用混音自己的相位做 iSTFT。这条路好训练,但有个天花板——相位是借来的,重叠区域的相位错误会造成难以消除的"水声"伪影。Demucs 的出发点是:直接在波形上端到端回归,让模型自己学相位。后来的故事(见下一节)则证明:波形和频谱两种表示各有擅长,合起来最强。

一句话边界:HTDemucs 只会把音乐拆成固定的四类(或 6 源实验版的六类)。它不做"把小提琴单独拿出来"这种任意指定乐器的分离,不做语音降噪,也不是实时模型。
02 · EVOLUTION

三代演化:波形 → 双域 → 双域 + Transformer

"Demucs"其实是一个家族名,三代架构差异很大,读代码或选模型前先分清版本:

2019–2020 · v1/v2

Demucs:纯波形 U-Net

1D 卷积编码器(stride 4)逐层压缩波形,瓶颈处放 BiLSTM 建模长时依赖,转置卷积解码,U-Net skip 连接。证明了波形端到端可以打平甚至超过频谱掩码法,代价是模型很大。

SDR ≈ 6.3 dB
2021 · v3

Hybrid Demucs:双域并联

新增一条频谱支路:STFT 后把复数当通道(CaC),沿频率轴做 2D 卷积;与波形支路在瓶颈处融合、共享,再各自解码。鼓的瞬态归波形,和声的稳态归频谱。拿下 MDX 2021 比赛 Track A 冠军。

SDR ≈ 7.7 dB
2022 · v4(本文主角)

HTDemucs:混合 Transformer

保留双支路各 4 层卷积,把最里层换成 Cross-Domain Transformer:域内 self-attention + 跨域 cross-attention 交替,让波形序列与频谱序列直接互相"看"。配合约 800 首额外训练数据。

SDR ≈ 9.0 dB(ft 版更高)

04 · TRAIN vs INFER

训练时学什么,推理时算什么

训练是一个有监督回归问题:数据集里每首歌都带真实分轨(ground-truth stems),把它们加起来得到混音喂给模型,让模型输出的四条波形逼近真实分轨,损失就是波形上的 L1 距离——不需要相位技巧,不需要 mask 标签,监督信号就是波形本身。

  • 学到的东西:编码器学"各类乐器在时域/频域长什么样"的先验;Transformer 学长程结构(主歌副歌里同一乐器音色一致);解码器学如何把判断还原成干净波形。
  • 数据:公开的 MUSDB18-HQ(150 首带分轨的歌,约 10 小时,其中 86 训练 / 14 验证 / 50 测试)+ Meta 内部约 800 首额外带分轨曲目。数据稀缺是这个领域的根本瓶颈——带分轨的版权音乐极难获得。
  • 数据增强(非常关键):随机重混(remix)——把不同歌曲的 stems 随机组合成"新歌";随机变调/变速(repitch/tempo);随机增益、声道交换。等于把 150 首歌组合爆炸成近乎无限的训练混音。
  • 训练片段固定 7.8 s:Transformer 的位置编码在这个长度上训练,这也解释了为什么推理必须切段(见下一个 tab)。
  • htdemucs_ft:在通用模型之后,每个源单独微调一个模型,推理时四个模型各跑一遍,各取所长。质量再涨一截,代价是约 4 倍推理时间。
和分类模型不同,这里没有"标签类别"——模型学的是从波形到波形的映射。因此它对训练数据分布极其敏感:流行/摇滚效果最好,民乐、电子极端音色、live 录音会明显退化。

推理时模型权重全部冻结,一首完整歌曲的处理流程是纯粹的"切段 → 前向 → 拼接":

  • 切段:整曲切成约 7.8 s 的片段,相邻片段重叠(默认 overlap=0.25)。
  • 逐段前向:每段走一遍上面的双域数据流,输出 (4, 2, T_seg)。
  • overlap-add:重叠区用三角窗加权平均,消除拼接边界的咔哒声。
  • 可选 shift trick:shifts=N 把输入随机平移 N 次分别推理再对齐平均,SDR 略有提升,耗时 ×N。
  • 耗时量级:GPU 上一首 4 分钟歌曲通常几秒~十几秒;CPU 上是分钟级(htdemucs_ft 再 ×4)。显存不够可用 segment 参数减小分段。

值得注意的确定性问题:shifts=0 时推理是确定的,同一输入永远得到同一输出;开 shifts 后带随机性(可固定种子)。

旋钮作用取舍
-n 模型名选 checkpoint:htdemucs(默认)/ htdemucs_ft / htdemucs_6s / mdx_extra 等ft 质量最好但慢 4 倍;6s 多 guitar/piano 两轨但 piano 质量一般
--two-stems=vocals只输出 vocals + 其余合并(karaoke 模式)只是合并输出,计算量并不减少
--shifts=N随机平移取平均质量小幅 ↑,时间线性 ↑,N=1~5 常见
--overlap分段重叠率(默认 0.25)调低省时间,过低有拼接痕迹
--segment分段秒数主要用于省显存;不能大幅调大,Transformer 位置编码没在长片段上训练过
-d cpu/cuda、--float32、--mp3设备与输出格式常规工程选项,对分离质量影响很小
05 · HANDS-ON

五分钟上手:最小可验证示例

# 安装(需要 Python ≥3.8 与 ffmpeg;首次运行自动下载权重,约 80 MB)
pip install demucs

# 默认模型 htdemucs,分四轨
demucs song.mp3

# 质量优先:分源微调版 + 平移平均(约 4×N 倍耗时)
demucs -n htdemucs_ft --shifts=2 song.mp3

# 只要人声/伴奏(卡拉OK)
demucs --two-stems=vocals song.mp3

# CPU 环境 + 输出 mp3 省空间
demucs -d cpu --mp3 song.mp3

就这么多——没有配置文件,没有前处理脚本。任何 ffmpeg 认识的格式都能直接喂。

import torch, torchaudio
from demucs.pretrained import get_model
from demucs.apply import apply_model

model = get_model("htdemucs")          # 自动下载并加载权重
model.eval()
print(model.sources)                   # ['drums', 'bass', 'other', 'vocals']

wav, sr = torchaudio.load("song.wav")  # 期望 44100 Hz 立体声,形状 (2, T)
wav = wav.unsqueeze(0)                 # (1, 2, T):加 batch 维

with torch.no_grad():
    # apply_model 自动完成 切段 → 前向 → overlap-add
    sources = apply_model(model, wav, overlap=0.25, shifts=1)[0]
                                        # (4, 2, T)

for name, src in zip(model.sources, sources):
    torchaudio.save(f"{name}.wav", src.cpu(), sr)

# 快速验证:四轨相加应非常接近原曲
print((sources.sum(0) - wav[0]).abs().mean())   # 一个很小的数

最后一行是最好的"理解自检":HTDemucs 的输出被训练成可加性分解,四轨之和 ≈ 输入。如果你的场景需要"分解后可无损重构",这一性质很有用。

06 · BOUNDARIES

横向对比、适用边界与常见误区

和相近模型比,它站在哪

模型域思路SDR(参考)一句话定位
Open-Unmix频谱BiLSTM 预测幅度 mask≈5.3教科书式基线,代码最好读
Spleeter频谱U-Net mask,预训练即用≈5.9曾经的工业界默认,现已过时
Demucs v2波形U-Net + BiLSTM 直接回归波形≈6.3证明波形路线可行
Hybrid Demucs v3双域时/频双支路并联≈7.7MDX 2021 冠军
HTDemucs v4双域双支路 + 跨域 Transformer≈9.0开源即用的事实标准
BS-RoFormer (2023)频谱Band-Split + RoPE Transformer≈9.7+刷榜更高,但训练数据更大、开源生态较弱

SDR 来自各论文在 MUSDB18(-HQ)测试集的报告,训练数据规模不一,只用于感受量级与代际差。

适合用它,当你要…

  • 提取伴奏 / 人声(卡拉OK、翻唱、DJ remix、采样)
  • 扒谱、听写、音乐教学前的预处理(先把目标乐器凸显出来)
  • 为下游任务批量造数据:歌声转换、歌词转写、MIR 研究
  • 离线批处理管线:输入输出干净、CLI 稳定、许可宽松(代码 MIT,权重研究许可需自查)
  • 借鉴架构思想:双域并联、跨域 cross-attention、波形 L1 监督、remix 增强

不适合,当你要…

  • 任意指定乐器的分离("把小提琴拿出来")——固定 4/6 类,其余全进 other
  • 语音增强、会议降噪、说话人分离——那是 speech 系模型的领域
  • 实时低延迟处理——非因果、按 7.8 s 分段,天然不实时
  • 录音棚级"零串音"分轨——9 dB SDR 仍意味着可闻残留与伪影
  • 极小算力端侧部署——几十 MB 权重 + 秒级 GPU 推理,不是 TinyML 目标

常见误区(点开自查)

误区一:"HTDemucs 是纯 Transformer 模型"

不是。它是 卷积 U-Net 为主体、只在最深处放 5 层 Transformer 的混合架构。绝大部分参数和计算仍在卷积编解码器里;Transformer 的职责是长程建模与跨域信息交换。把它当 "音频版 ViT" 来理解会读错代码。

误区二:"波形模型已经淘汰了频谱模型"

恰恰相反,Demucs 家族自己的演化否定了这个说法:v3/v4 的提升正来自把频谱支路加回来;而 2023 年的 BS-RoFormer 用纯频谱架构再次登顶。结论是:表示(波形/频谱)不是胜负手,数据规模、增强策略和架构细节才是。

误区三:"SDR 9 dB = 输出完美可用"

SDR 是全曲平均能量比。9 dB 意味着多数流行歌上效果惊艳,但依旧存在:人声轨里的镲片残留、贝斯与底鼓互相串音、密集段落的"水声"伪影。对最终交付质量敏感的场景(母带、商用采样)需要人工审听,或叠加多模型 ensemble。

误区四:"segment 调大点,长曲一次过,效果更好"

不行。Transformer 的位置编码只在 7.8 s 片段上训练过,输入远超此长度会显著退化(v4 论文专门讨论过这一点)。长曲质量靠的是 overlap-add 拼接,而不是加长上下文。这也是所有"定长训练 + 位置编码"模型的通病,工程上要牢记。

误区五:"--two-stems 只分两轨,应该快一倍"

不会更快。模型永远输出 4(或 6)个源,--two-stems 只是把非目标源加起来存成一个文件。想省时间应该调 overlap、关 shifts、或不用 _ft 版本。

误区六:"训练一个自己的 Demucs 很容易,反正代码开源"

代码确实全开源(含训练管线),但复现 9 dB 的隐形门槛是带分轨的训练数据:公开可用的只有 MUSDB18 的 86 首训练曲,Meta 的 800 首内部数据不公开。没有额外数据,从头训练大约只能到 v3 水平。这也是为什么绝大多数使用者直接用官方权重或做小规模微调。

07 · TL;DR

带走这五句话

  • 任务:音乐源分离——2 声道混音进,drums / bass / other / vocals 四条波形出,四轨之和 ≈ 原曲。
  • 架构:波形与频谱两条卷积 U-Net 支路,在瓶颈处用 5 层 self + cross attention 的 Transformer 互相注意,再各自解码、相加。
  • 训练:MUSDB18-HQ + 800 首内部分轨数据,波形 L1 损失,remix/变调等增强是关键;推理靠 7.8 s 切段 + overlap-add。
  • 选型:要开箱即用选 htdemucs;要极致质量选 htdemucs_ft(慢 4 倍);要吉他/钢琴试 htdemucs_6s;要刷 SDR 榜再看 BS-RoFormer 系。
  • 可借鉴:双域互补 + 跨域注意力这个模式,不止适用于音乐——任何"同一信号存在多种互补表示"的任务(雷达、脑电、金融时序)都值得抄这份作业。
