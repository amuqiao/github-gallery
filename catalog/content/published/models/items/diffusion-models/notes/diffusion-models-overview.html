01 · What Diffusion Really Is

先理解:Diffusion Model 到底是什么

很多人第一次接触这个词,是通过 Stable Diffusion 或 Midjourney 这样的产品,于是很自然地以为"Diffusion Model 就是那个画图的 AI"。这是本文要纠正的第一件事:Diffusion Model 是一个模型家族、一种生成建模范式,而不是某个单一模型。它规定的是"怎么把生成问题建成数学问题",而不是某一套具体的网络权重。

一个准确的类比是:

  • Diffusion Model 之于 Stable Diffusion,就像 Transformer 之于 GPT——前者是方法论类别,后者是基于它构建的具体系统;
  • 说"我用了 Diffusion Model",信息量类似于说"我用了 Transformer":你还没说清用的是哪个数学框架、哪种采样算法、哪种网络结构、在什么空间上建模。

全家共享的核心:一条被拆碎的生成路径

家族成员再怎么分化,都围绕同一对过程展开:

  • forward process(前向过程):对真实数据一步步注入噪声,直到它彻底变成没有信息的纯噪声。这个过程不需要学习,是人为设计的"破坏程序"。
  • reverse process(反向过程):训练一个神经网络,学习把这个破坏过程一步步倒放——从纯噪声出发,逐步去噪,最终"长出"一个像真实数据的新样本。
clean data → partially noisy data → pure noise ⇢ denoise step by step ⇢ generated data

首屏那组三联画演示的就是这条链路:左边是干净样本 x₀,中间是加噪到第 t 步的 x_t,右边是反向去噪时模型对干净样本的当前估计。注意右边的规律:t 很大时只能恢复出粗糙的整体结构,t 越小细节越清晰——多步去噪本质上是"先定构图、再补细节"。

共享思想之下,成员差别可以非常大

同一条加噪-去噪主线,可以在至少五个维度上分化:数学框架(离散概率过程、score、SDE、流匹配)、采样算法(上千步随机采样、几十步确定性求解、一步生成)、网络结构(U-Net、Transformer)、作用空间(像素、潜空间、原子坐标)、应用领域(图像、视频、音频、3D、蛋白质)。第 5 章的分层地图就是沿这些维度画出来的。

判断标准。怎么判断一个方法能不能放进这个家族讨论?看它是否围绕"从简单噪声分布到数据分布的逐步生成/去噪路径"来建模。满足这一点,就可以放进扩散或扩散相关的生成范式一起讨论;但具体归到哪一支,要看它的训练目标(预测噪声?score?速度场?)和采样过程(随机多步?确定性 ODE?一步映射?)——这也是第 3 章那套"五个变量"阅读框架的由来。
02 · Why This Paradigm

为什么需要这种生成范式

生成建模要解决的根本问题只有一句话:给定一堆来自未知分布的数据,学会从这个分布里采出新样本。难点在于真实数据分布(比如"所有自然图像的分布")极其复杂,直接建模几乎不可行。GAN、VAE、Autoregressive Model、Diffusion 是四条不同的绕行路线。

扩散模型这条路线的直觉是:

  • 它不要求一步到位。GAN 的生成器要一口气从随机向量变出整张图,这个映射非常难学、训练容易不稳定;扩散模型把它换成"每次只去掉一点点噪声",单步任务简单得多。
  • 它把一个复杂问题拆成一串简单问题。"从纯噪声生成图像"很难,"给一张 95% 是噪声的图去掉一点噪声"相对容易——而后者重复几百次,就等价于前者。这和"把复杂函数拆成多层简单变换"的深度学习哲学一脉相承。
  • 训练目标是稳定的回归损失。典型做法是随机取一个时间步、加噪、让网络预测所加的噪声,用均方误差训练。没有 GAN 那种对抗博弈,训练明显更稳,规模化更容易。
  • 代价主要在采样端。生成一个样本要跑几十到上千次网络前向,天然比一步生成的 GAN 慢——这个短板正是后面 DDIM、DPM-Solver、Consistency Models、Rectified Flow 等一大批工作的共同动机。
模型范式生成方式训练稳定性采样速度典型优势典型代价
GAN一次前向直接生成较差(对抗训练易崩)非常快推理快、结果锐利模式塌缩、多样性难保证
VAE编码-解码一次生成好快有显式潜空间、可插值样本常偏模糊
Autoregressive逐 token 顺序生成好随序列长度线性变慢似然可算、与 LLM 同构高维连续数据序列极长
Diffusion多步迭代去噪修正好(回归损失)慢(多步前向)质量与多样性俱佳、训练稳、易加条件推理成本高,需采样加速

理解了"质量与稳定换速度"这笔账,就能看懂家族后续几乎所有演化:Latent Diffusion 降低每一步的成本,DDIM / DPM-Solver 减少步数,Consistency / Rectified Flow 追求少步甚至一步——都是在补采样慢这块短板,而不是推翻加噪-去噪这条主线。

03 · A Reading Frame

读这类模型,先抓五个变量

家族地图上名字很多,但任何一个扩散相关模型,都可以用同一张"体检表"看穿。以后读任何论文或模型卡,先回答这五个问题,它在家族里的位置就基本确定了。

① 数据表示在哪里(空间)

扩散发生在什么空间上?可以是 pixel space(直接对像素加噪,如 DDPM、Imagen 的级联像素扩散),可以是 latent space(先用 autoencoder 压缩再扩散,如 Stable Diffusion),也可以是 token / patch 序列、音频波形或频谱、视频时空块、3D 点云或隐式场、蛋白质原子坐标。换空间不换范式,但强烈影响成本和工程形态。

② 时间或路径怎么定义

从数据到噪声的这条路是怎么参数化的?discrete timestep(DDPM 的 t = 1…1000)、continuous time(SDE 框架的 t ∈ [0,1])、还是 learned / designed transport path(Flow Matching 直接指定一条插值路径,Rectified Flow 进一步把它拉直)。

③ 模型每一步预测什么(训练目标)

网络的输出可以是:所加的噪声 ε、干净样本 x₀、score(log 密度梯度)、速度 v,或更一般的 flow / 更新方向。这些目标在数学上大多可以互相换算,但选哪个作为回归目标,是区分 DDPM 系、score 系和流匹配系最直接的指纹。

④ 怎么采样

stochastic sampling(每步注入随机性,DDPM 祖先采样)、deterministic sampling(DDIM、probability-flow ODE)、用高阶 ODE / SDE solver(DPM-Solver),还是 few-step / one-step(Consistency Models、蒸馏方法)。同一个训练好的模型往往可以配多种采样器——所以"采样器"是可插拔的一层,不要和训练框架混为一谈。

⑤ 条件如何进入

无条件生成很少直接可用,产品化的关键是条件:class label、text embedding(cross-attention 注入)、图像 / 视频 / 音频条件、mask / depth / pose 等控制信号,以及 guidance(如 classifier-free guidance)或 ControlNet 类外挂控制模块。

04 · Core Mechanism

最核心机制:加噪与去噪

这一章把首屏那条链路拆开讲清楚。全家族的"发动机"就这一对过程,后面所有分支都是在给这台发动机换零件。

前向:人为设计的破坏程序

前向过程对数据反复注入高斯噪声。以 DDPM 的记号,第 t 步的样本可以一步写出(这是全家族最值得记住的一个关系):

x_t = √ᾱ_t · x₀ + √(1−ᾱ_t) · ε ,  ε ~ N(0, I)

其中 ᾱ_t 从 1 单调降到接近 0,由噪声调度(noise schedule)决定:它控制每一步破坏多少信息。调度是设计选择——linear 调度在中段破坏很快,cosine 调度破坏更平缓,给中间时间步保留更多可学信号。

反向:学出来的还原程序

反向过程从纯噪声 x_T 出发,每一步让网络看着当前的 x_t 和时间 t,预测一个"去噪方向",走一小步得到 x_{t−1},循环直到 x₀。网络训练时学的可以是下面任意一种,它们互相之间只差已知的换算:

  • 预测噪声 ε:DDPM 的经典目标,损失就是 ‖ε − ε_θ(x_t, t)‖²;
  • 预测干净样本 x₀:与 ε 目标由上面那条公式直接互换;
  • 预测 score(∇ log p(x_t)):score 系的目标,在高斯加噪下与 ε 只差一个缩放符号;
  • 预测 velocity v:x₀ 与 ε 的一种混合参数化,也是流匹配类方法的核心目标形态。

公式到此为止——记住"一条公式 + 四种可互换的预测目标"就足够支撑全文了,推导留给后续 DDPM 专题。

05 · The Family Map

家族地图:这些名字分别在哪一层

把 DDPM、DDIM、Latent Diffusion、DiT、Stable Diffusion 平铺在一起比较,是混乱的根源——它们根本不在同一层。正确的图景是一栈可以自由组合的层:上面的层回答"学什么、怎么走",下面的层回答"在哪算、用什么网络",最底下才是把各层选择打包成型的具体模型。

  • 核心思想层:加噪-去噪;从简单分布出发,沿一条路径走到数据分布。所有人的公共祖先。
  • 概率建模层:DDPM(离散时间概率过程)、Score-based Models(密度梯度)、SDE framework(连续时间统一视角)。回答"训练时在拟合什么数学对象"。
  • 采样与加速层:DDIM、DPM-Solver、Consistency Models 及各类少步方法。回答"反向过程怎么走、走几步"。
  • 表示空间层:Pixel Diffusion 与 Latent Diffusion。回答"扩散发生在什么空间"。
  • 路径 / 流相关层:Flow Matching、Rectified Flow。它们把"路径本身"当成第一设计对象,是与扩散相邻、可互相转换的推广。
  • 网络结构层:U-Net、DiT,以及 cross-attention / CFG / ControlNet 等条件控制模块。回答"每一步的预测由什么网络完成、听谁指挥"。
  • 模型实例层:Stable Diffusion、Imagen、DALL·E、Midjourney、Sora、音频扩散、AlphaFold 3 等。它们是上面各层的一组具体搭配 + 训练数据 + 工程。

06 · The Classic Baseline

DDPM:经典扩散模型基线

DDPM(Denoising Diffusion Probabilistic Models, Ho et al. 2020)不是扩散思想的发明者(思想可追溯到 Sohl-Dickstein et al. 2015),但它第一次把这套思想调到了"生成质量可与 GAN 正面竞争"的水平,并给出了一个极其简洁的训练配方,从此成为全家族的参照系。后来几乎每个分支介绍自己时,都是以"相对 DDPM 改了什么"来定义的。

它的配方

  • 时间步:离散的 t = 1 … T(典型 T = 1000);
  • 前向:固定的马尔可夫加噪链,噪声调度 β_t 人为设计,不学习;
  • 训练目标:随机采一个 t,加噪得到 x_t,让网络预测所加噪声,优化 ‖ε − ε_θ(x_t, t)‖²;
  • 采样:从 x_T ~ N(0, I) 出发,逐步随机采样(每步都注入新噪声),走满上千步。
x₀ →(加噪到第 t 步)→ x_t →(网络预测 ε̂)→ 由 ε̂ 计算均值 →(采样)→ x_{t−1} → … → x̂₀

它的位置:基线,而非全家

DDPM 是理解家族的最佳入口,但它不等于整个 Diffusion Model 家族。把它当参照系,后续分支的关系一句话就能说清:

  • DDIM:不改训练,改采样路径——同一个 DDPM 权重可以直接用 DDIM 少步采样;
  • Score-based / SDE:给同一件事换数学视角——连续时间、密度梯度,并由此派生出各种 solver;
  • Latent Diffusion:改扩散发生的空间——从像素搬进 autoencoder 的潜空间;
  • DiT:改去噪网络结构——U-Net 换成 Transformer;
  • Flow Matching / Rectified Flow:改路径的定义与训练目标——不从加噪过程反推,直接学传输路径。

1000 步采样与少步采样的直觉差异,在下一章的对比器里直接拖给你看:步数足够多时,每步修正很小、误差不断被纠正;步数骤减后,每一步要"跨"得更远,对轨迹近似的精度要求就高得多——这正是采样加速这一层存在的原因。

最易混淆。DDPM 最容易和"扩散模型"这个词本身混淆。记法:论文语境里 DDPM 指 2020 年那个具体框架(离散时间 + ε 预测 + 随机祖先采样);"扩散模型"泛指整个家族。说"Sora 是 DDPM"是错的,说"Sora 被介绍为扩散(相关)模型"才稳妥。
07 · Faster Sampling

DDIM 与采样加速

DDPM 的痛点直白:生成一张图要跑上千次网络前向。DDIM(Song, Meng & Ermon 2020)给出的答案同样直白:训练一个字都不改,换一条反向轨迹来走。它构造了一族与 DDPM 训练目标兼容的非马尔可夫反向过程,其中最有名的特例是完全确定性的:给定同一个起始噪声,输出唯一确定,而且可以只在少数几十个时间步上"跳着走"。

三个要点:

  • 减步数:从 1000 步压到 50、20 甚至 10 步,质量损失往往可接受;
  • 确定性:同一噪声种子给出同一结果,使得插值、反演(把真实图像编码回噪声)等操作成为可能;
  • 它不是新的训练范式:DDIM 提供的是对反向采样轨迹的另一种理解,复用 DDPM 训练好的网络——这条确定性轨迹后来在 SDE 框架里被统一理解为 probability-flow ODE。

沿着"把反向过程当 ODE 解"的思路,DPM-Solver 等高阶数值求解器进一步把步数压到 10–25 步。这一层的共同特征是:换算法,不换模型。与之相对,第 11 章的 Consistency Models 走的是另一条路:换训练目标,让模型本身具备少步能力。

08 · Score & SDE View

Score-based Models / SDE 视角

同一台发动机,还有另一套图纸。score 指的是数据分布对样本求梯度的量 ∇_x log p(x)——直观地说,它是"站在样本空间任何一点,指向概率密度升高最快方向"的箭头场。Song & Ermon(2019)的洞见是:与其建模密度本身,不如直接学这个箭头场;学会之后,把任意一团噪声点沿着箭头往高密度区推,推着推着就落在了数据流形上。

这与去噪是同一件事:在高斯加噪的设定下,"预测所加噪声"和"估计加噪后分布的 score"只差一个已知的缩放和符号。DDPM 训练出的网络,本质上就是各噪声水平下的 score 估计器。

SDE:把离散楼梯抹成连续坡道

Score-SDE(Song et al., ICLR 2021)把这幅图景推到连续时间:前向加噪是一条随机微分方程(SDE)描述的连续扩散;反向生成对应一条反向 SDE,它只依赖 score。同一过程还存在一条边缘分布完全相同的确定性 ODE(probability-flow ODE)——DDIM 的确定性轨迹、DPM-Solver 的高阶求解,都可以在这条 ODE 上获得统一解释。

  • DDPM 从离散时间的加噪 / 去噪概率过程出发,好处是训练配方直观、实现简单;
  • Score / SDE 从连续时间随机过程与密度梯度出发,好处是数学统一——采样器设计、噪声调度、离散化误差都有了统一语言;
  • 二者不是互斥阵营,而是同一对象的两套坐标系:DDPM 是这套连续框架的一种离散化,score 与 ε 可互相换算。工程上写代码常用 DDPM 的记号,分析和设计新采样器常用 SDE 的记号。
09 · Where Diffusion Happens

Latent Diffusion:为什么不总在像素空间扩散

在像素空间做扩散,成本随分辨率平方级膨胀:一张 1024×1024 RGB 图有三百多万个数值,反向过程的每一步都要让网络处理全部像素,还要重复几十步。早期高分辨率像素扩散(如级联式的 Imagen)只能靠"低分辨率生成 + 多级超分"硬扛,训练与推理都极其昂贵。

Latent Diffusion(Rombach et al. 2021/2022)的核心动作只有一个:换地方扩散。

image→ encoder ℰ→ latent z(在这里加噪 / 去噪)→ decoder 𝒟→ image

先训练一个 autoencoder,把图像压缩成一个小得多但保留语义与结构的 latent(典型压缩 8 倍边长,通道数 4 左右);扩散的加噪、去噪、采样全部发生在这个潜空间;最后把去噪完成的 latent 解码回像素。Stable Diffusion 正是这个方法最著名的实例——"SD 属于 Latent Diffusion"这句话的意思是:它在方法层选了"潜空间"这个选项,而不是说二者是同义词。

交互 · Pixel vs Latent 成本对比器
回答的理解问题:把扩散搬进潜空间,到底省下了什么量级的计算?选择分辨率,对比两种空间中"每一步去噪要处理的数值规模"。

代价与取舍

  • 省:单步计算量下降一到两个数量级,消费级 GPU 也能训练微调、实时出图,这是文生图得以平民化的直接原因;
  • 赌:扩散模型再强,也只能生成 autoencoder 能表达的内容——细节保真的上限由压缩表示决定。小字、手指、纹理等高频细节的失真,很多时候来自 decoder 而不是扩散本身;
  • 对照:Pixel Diffusion 直接在可见数据空间建模,链路直观、无编码瓶颈,但成本高;Latent Diffusion 高效,但引入了编码器 / 解码器这个新的质量瓶颈。二者是表示空间层上的两个选项,与用什么训练框架、什么网络结构正交。
10 · Flows, Adjacent But Distinct

Flow Matching / Rectified Flow:相关,但别混为一谈

近两年的新旗舰(SD3、Flux 等)介绍自己时,常说用的是 flow matching 或 rectified flow 而不是"经典扩散"。它们和扩散是什么关系?一句话:同一个目标(把简单分布运输成数据分布)、同一种产品形态(迭代求解一条从噪声到样本的路径),但换了出发点和训练目标。

共同点

  • 都在学习"从简单分布(高斯噪声)到数据分布"的连续生成路径;
  • 采样都可以写成沿一条 ODE(或 SDE)从噪声积分到数据;
  • 在特定的路径与参数化选择下,flow matching 与扩散的目标可以互相转换——它们是近亲,不是陌生人。

不同点:路径是设计出来的,不是反推出来的

  • 传统 diffusion:先设计一个加噪过程,再通过 score / ε 估计把它"倒放"——路径是加噪过程的副产品,通常是弯曲的;
  • Flow Matching(Lipman et al. 2022):跳过加噪叙事,直接指定一条从噪声到数据的插值路径(最常用的就是两点连直线),训练网络回归这条路径上每一点的速度场 v。训练目标是干净的回归,连续时间天然内建;
  • Rectified Flow(Liu et al. 2022):在此基础上追求把路径拉直——通过 reflow 等操作迭代校直传输轨迹。路径越直,ODE 求解需要的步数越少,极限情况一步走完。SD3 论文明确采用了 rectified flow 类训练目标。
交互 · 弯路径 vs 直路径
回答的理解问题:为什么"路径更直"意味着"步数更少"?切换路径类型,并调整求解步数,看折线(数值求解)偏离真实路径多少。

为什么新模型爱用它

  • 训练目标更直接:回归速度场,少一层"从加噪过程反推"的间接性,调度与加权的设计空间更干净;
  • 路径可能更短更直:直接对应更少的采样步数;
  • 与 Transformer 和大规模训练合拍:连续时间 + 简洁目标,和 DiT 类主干、多模态 token 拼接的工程栈组合起来很顺手。
边界。Flow Matching / Rectified Flow 是扩散思想的推广与邻近范式:讨论"扩散相关生成模型"时应该把它们放进来,但不要把所有 flow-based 方法都粗暴叫成 DDPM,也不要因为名字里没有 diffusion 就以为是完全另一套东西。判断依据回到第 3 章五变量:看训练目标(速度场)与路径定义(设计的插值路径),而不是看名字。
11 · Few-Step Generation

Consistency Models 与少步生成

DDIM 和 DPM-Solver 把步数从 1000 压到了 10–50,但要继续压到 1–4 步,solver 思路开始撞墙:步子太大,数值解偏离真实轨迹太远。Consistency Models(Song et al. 2023)换了个问法:与其更聪明地"走"这条轨迹,能不能训练一个模型直接"跳"到终点?

核心直觉:处处输出一致

反向过程的一条轨迹上有无数个点(不同噪声水平的同一个样本的"祖先")。Consistency 的训练约束是:把这条轨迹上任何一点喂给模型,它都应该输出同一个干净样本——即"自洽 / 一致性"。学会了这一点,生成就可以一步完成:随便采一团噪声,直接映射到样本;想要更高质量,也可以走 2–4 步的"跳-加噪-再跳"。它可以从头训练,更常见的是从预训练扩散模型蒸馏而来(LCM 等把这一思路带进了 Stable Diffusion 生态)。

和 solver 类方法的分界线

  • DDIM / DPM-Solver:改采样算法,模型权重不动——是"推理期"的加速;
  • Consistency Models:改训练目标,让模型本身获得少步生成能力——是"训练期"的加速;
  • 相邻但不同的还有 Rectified Flow:它从路径几何(把路拉直)入手逼近少步,Consistency 从输出一致性约束入手,殊途同归于"few-step"。

取舍

  • 快:1–4 步出图,交互式应用、端侧部署因此可行;
  • 贵在训练:蒸馏 / 一致性训练的设置比标准扩散训练复杂,常依赖一个强教师模型;
  • 质量、多样性与稳定性需要具体模型具体判断:少步模型常在细节丰富度和可控性上有折损,不能一概而论地说"已经追平多步"。
最易混淆。Consistency Models 常与 DDIM 混为"都是加速"。分界记法:DDIM 是同一个模型的另一种走法;Consistency 是另一个(训练出来的)模型。前者随时可换,后者需要重新训练或蒸馏。
12 · Backbones & Control

网络结构:U-Net、DiT 和条件控制

容易被忽略的一点:扩散框架本身不绑定任何网络结构。框架(DDPM / SDE / Flow Matching)定义的是"训练什么目标、采样怎么走";每一步里真正做预测的那个神经网络,是一个可替换的零件。这一层有两个主流选择,外加一组条件控制模块。

U-Net:图像扩散的长期主力

卷积编码-解码结构,带跨尺度跳连:一路下采样抓全局结构,一路上采样恢复分辨率,跳连把细节直接递给解码侧。这与去噪任务的需求高度匹配——去噪既要看懂全局("这是一只猫"),又要修好局部("胡须的走向")。从 DDPM 到 SD 1.x / SDXL,U-Net(加上注入时间步嵌入、插入 cross-attention)一直是图像扩散的默认主干。

DiT:把去噪交给 Transformer

DiT / Diffusion Transformer(Peebles & Xie)把图像(或视频)的 latent 切成 patch token,用标准 Transformer 块做去噪,时间步与条件通过 adaLN 等机制注入。它的吸引力在于:规模化行为好(算力换质量的曲线平滑)、与多模态 token 序列拼接自然。SD3、Flux 采用 DiT 类主干(MMDiT),Sora 也被官方介绍为在时空 patch 上工作的 diffusion transformer 方向。

条件控制模块:让去噪"听指挥"

  • Cross-Attention:把文本 embedding 作为 key/value 插进主干,让每一步去噪都能"读题";
  • Classifier-Free Guidance(CFG):训练时随机丢弃条件,推理时用"有条件预测"与"无条件预测"的差值外推,一个旋钮调节服从度(下一章可玩);
  • ControlNet / adapter 类结构:在冻结的主干旁挂一条可训练支路,把边缘、深度、姿态、mask 等空间条件注入去噪过程,实现结构级控制。
不要混层(再次)。U-Net / DiT 是去噪网络结构;DDPM / SDE / Flow Matching 是训练或生成路径框架;Stable Diffusion / Sora 是具体模型或产品方向。"SD3 把 U-Net 换成了 DiT、把 DDPM 式目标换成了 rectified flow"——一句话里动了两层,但潜空间那层(Latent Diffusion)没动。能这样一层层读改动,家族地图就算真正建立了。
13 · Conditioning & Guidance

条件生成:文本、图像、视频如何控制去噪

无条件扩散模型只能"随机掉落"一个样本;产品需要的是"按需生成"。条件信息进入模型的常见通道:class label(嵌入后与时间步一起注入)、text embedding(经 CLIP / T5 等文本编码器,cross-attention 注入)、image condition(图生图:从加噪的参考图出发;或作为额外通道拼入)、mask / depth / pose / audio(经 ControlNet / adapter 注入空间或时序约束)。

Classifier-Free Guidance:服从度的旋钮

训练时以一定概率把条件置空,模型同时学会"有条件"与"无条件"两种预测;推理时按 ε̂ = ε_uncond + s · (ε_cond − ε_uncond) 外推。guidance scale s 的效果:调大,文本服从度上升、样本更"典型",但多样性下降,过大时画面过饱和、构图僵硬甚至畸变;调小,更自由多样,但可能跑题。negative prompt 则是把"不想要的条件"放进无条件端,把采样方向从它那里推开。

14 · Beyond Images

从图像到视频、音频、3D、蛋白质

"逐步生成 / 逐步去噪"这个思想不挑数据类型——只要能给一种数据定义"加噪"和"表示空间",就能把这台发动机搬过去。但每个领域都要重新回答第 3 章的五个变量,尤其是数据表示和领域特有的一致性约束:

  • 图像:在像素或 latent 上扩散,最成熟的领域;
  • 视频:多了时间维——不仅每帧要好,帧与帧之间要时空一致(物体不闪烁、运动连贯),常在时空 latent / 时空 patch 上建模;
  • 音频:可作用于原始波形、频谱图(当图像处理)或音频 latent,条件可以是文本、旋律、参考音色;
  • 3D:表示本身就五花八门——点云、体素、隐式场(NeRF 类)、多视图图像;还有一条借力路线:用预训练 2D 扩散蒸馏 3D(DreamFusion 的 SDS);
  • 蛋白质 / 分子结构:在原子三维坐标上做扩散,从噪声坐标逐步"折叠"出合理构象,还需满足物理与化学约束——AlphaFold 3 的结构生成模块是这一方向的代表。

16 · Instances On The Map

具体模型如何放回家族地图

最后一步训练:拿到一个具体产品名,把它拆成"各层选了什么"。注意两条纪律:产品不是理论框架;闭源模型的内部细节不宜过度断言——以下对开源模型按论文描述归位,对闭源产品只标注"可作为某方向代表"。

  • Stable Diffusion(1.x / 2.x):表示空间层选 Latent Diffusion;条件为文本(CLIP 文本编码器 + cross-attention);主干为 U-Net;训练目标是 ε 预测;采样常配 DDIM / DPM-Solver 等。它是"各层选择打包成开源系统"的教科书案例。
  • SDXL → SD3 → Flux:同一生态的演化线。SDXL 放大 U-Net 与条件编码;SD3 把主干换成 MMDiT(DiT 类)、训练目标换成 rectified flow;Flux 是同方向的后继模型。逐版对照,正好练习"分层读改动"。
  • Imagen:文本到图像扩散的另一代表,论文版本以强文本编码器(T5)+ 级联像素扩散著称——说明"文生图不一定要走潜空间"。后续产品迭代的内部细节以官方披露为准。
  • DALL·E / Midjourney:作为文生图产品或模型族的代表。DALL·E 2 论文(unCLIP)使用了扩散组件;DALL·E 3 与 Midjourney 公开细节有限,归类时说"扩散 / 扩散相关产品代表"即可,不要断言其内部架构。
  • Sora 及视频生成模型:扩散(相关)范式在视频领域的代表方向。官方技术报告将其描述为在时空 patch 上工作的 diffusion transformer 路线;相对图像,核心增量是时间一致性与长时序建模。内部实现同样不宜过度断言。
  • AlphaFold 3 结构生成模块:扩散思想迁移到科学结构生成的例子——用扩散模块直接生成原子坐标,取代了前代的确定性结构模块。它提醒我们:这个家族的边界远在"生成好看图片"之外。
  • 音频扩散模型:AudioLDM、Stable Audio 等表明扩散可作用于波形、频谱或音频 latent,文本 / 旋律作条件。
练习。回到首屏家族总图,切到"具体模型"视角,点开每张卡片看它的"配方标签"——每个标签就是该模型在某一层的选择。能独立复述配方,这一章就过关了。
17 · Misconceptions & Quiz

常见误区与归位测验

每条误区点开看纠正。这些不是稻草人——几乎每一条都来自真实的高频误读。

误区 01“Diffusion Model 就是 Stable Diffusion。”
纠正:Diffusion Model 是建模范式(类别),Stable Diffusion 是该范式下一个具体的开源系统(实例)。关系如 Transformer 之于 GPT。SD 的实现细节(潜空间、U-Net、CFG)都是可替换的层内选择,不能反推为家族定义。
误区 02“DDPM 就代表所有扩散模型。”
纠正:DDPM 是 2020 年确立的经典基线:离散时间 + ε 预测 + 随机祖先采样。家族里还有 score/SDE 的连续时间视角、流匹配的路径视角、Consistency 的少步训练目标——它们都不是 DDPM,却都是家族成员。
误区 03“扩散模型只能生成图片。”
纠正:视频(Sora 方向)、音频(AudioLDM 等)、3D(DreamFusion 等)、蛋白质结构(AlphaFold 3 扩散模块、RFdiffusion)都在用。只要能定义"表示空间 + 加噪方式",范式就能迁移;变的是表示、结构、条件与评价指标。
误区 04“扩散模型一定在像素空间工作。”
纠正:在哪扩散是"表示空间层"的选择。Latent Diffusion 在压缩潜空间工作(SD 即如此),还有在波形、频谱、原子坐标、时空 patch 上工作的成员。像素只是选项之一。
误区 05“采样步数越多一定越好。”
纠正:步数带来的收益会饱和:超过一定步数后质量提升可忽略,耗时却线性增长;确定性 solver 在几十步内就能贴近极限,少步蒸馏模型甚至 1–4 步可用。合理说法是"步数太少可能不够,不是越多越好"。第 7 章的对比器展示了这条饱和曲线的直觉。
误区 06“U-Net 是扩散模型的必需组件。”
纠正:扩散框架不绑定网络结构。U-Net 只是图像扩散长期常用的主干;DiT 用 Transformer 同样(甚至在规模化上更)胜任,SD3、Flux 已经换用 DiT 类主干。框架层与结构层是两层。
误区 07“Flow Matching / Rectified Flow 和 DDPM 完全一样。”
纠正:它们同属"从简单分布到数据分布的连续路径"思想,特定设定下目标可互相转换,但训练目标(回归速度场 vs 预测噪声)、路径参数化(设计的直线插值 vs 加噪过程的反演)、采样形式不同。是近亲,不是同一人;也不要反过来说毫无关系。
误区 08“看懂 Stable Diffusion 就等于看懂扩散模型全家族。”
纠正:SD 只覆盖了每层的一种选择:潜空间、U-Net、ε 预测、CFG。没碰到的还有像素扩散、score/SDE 理论、流匹配训练、DiT 主干、Consistency 少步、以及图像之外的所有领域。SD 是很好的切片,但只是切片。
误区 09“扩散模型就是在不断把图片模糊再还原。”
纠正:加的是噪声不是模糊,而且关键不在"还原某张图",而在学习数据分布上的生成路径:训练时模型在所有噪声水平上学习"往数据分布走的方向"(score / ε / v),采样时从新的随机噪声出发走这条路径,得到的是分布中的新样本,不是训练图的复原。
误区 10“全局视角只要把名词列一遍,细节以后再说。”
纠正:只记名词的"地图"是假地图。入门就必须能说清:全家共享的机制(加噪-去噪 / 路径建模)、每个主要分支解决什么问题、以及相邻概念的核心区别(本文每章的"最易混淆"框)。论文级推导可以留给专题,分支间的区别不能留。

后续学习路线

本文的目标是地图;下面是按地图分层推进的路线,每一层都可以拆成独立专题深入(论文推导、代码实现、工程细节留到那里)。建议顺序学,因为每层都以上一层为语言。

  1. 核心思想:加噪、去噪、时间步、噪声调度。检验:能默写 x_t = √ᾱ_t·x₀ + √(1−ᾱ_t)·ε 并解释每一项。
  2. 经典框架:DDPM、DDIM、Score-based Models、SDE。检验:能说清 ε、x₀、score、v 四种目标怎么互换;能解释 DDIM 为什么不用重训。
  3. 工程化生成:Latent Diffusion、Stable Diffusion、classifier-free guidance。检验:能画出 SD 的完整管线(文本编码器 → 潜空间去噪 → decoder),并解释 guidance scale 的作用曲线。
  4. 现代扩展:DiT、Flow Matching、Rectified Flow、Consistency Models。检验:能解释 SD3 相对 SD1.5 在哪两层动了刀;能区分"solver 加速"与"训练出少步能力"。
  5. 具体领域:图像、视频、音频、3D、蛋白质结构生成。检验:任给一个领域,能回答第 3 章五个变量分别取什么值。
  6. 具体模型专题:Stable Diffusion 全解 → SDXL / SD3 → Flux → Sora(公开资料范围内)→ 感兴趣的音频或 3D 扩散模型。到这一层,读任何新模型的技术报告,都应该能在 10 分钟内把它放回地图。
