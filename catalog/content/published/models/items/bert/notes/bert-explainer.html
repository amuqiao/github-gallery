Why · 它为什么出现
01

同一个词，在不同句子里意思不同

早期的词向量（Word2Vec、GloVe）给每个词一个固定的向量：不管上下文，"bank" 永远是同一个数字。BERT 要解决的正是这件事——让表示随上下文变化。

She sat by the river bank .
Word2Vec 给出的 "bank"： [0.21, -0.44, 0.08, …] ← 两句话完全相同
BERT 给出的 "bank"： [0.63, 0.05, -0.71, …] ← 结合了 river，指「河岸」

为得到这种「上下文相关」的表示，BERT 做了当时的关键突破：深层双向。它之前的方案要么是单向的（GPT 只能从左往右看），要么是浅层拼接的（ELMo 用两个方向的 LSTM 各看一半再拼起来）。BERT 让每个词在每一层都能同时看到左右所有词。

一句话定位：BERT = 只保留 Transformer 的 encoder，用「完形填空」式的预训练，学出深层双向的上下文表示。它是「理解器」，不是「生成器」。
I/O · 输入怎么来，输出是什么
02

输入：拼装；输出：每个位置一个向量

文本进不了神经网络，得先切成 token、查成 ID，再加上位置和句子归属信息。点下面的例子看 WordPiece 怎么切词。

① WordPiece 分词 · ■ 特殊 token · 虚线框 = 子词（## 表示接在前一个词后面）
② 每个 token 的向量 = 三种嵌入相加，再过 LayerNorm：
token embedding + segment embedding (句 A=0 / 句 B=1) + position embedding (0…511)

输出 A · 每个词的向量

形状 [序列长度 L, 768]。每个位置都是一个「读懂上下文后」的 768 维向量，用于 NER、抽取式问答（判断每个 token 是不是答案边界）等逐词任务。

输出 B · [CLS] 位置的向量

序列第一个位置 [CLS] 的向量常被当作整句表示，接一个分类头做情感分析、句子分类等整句任务。

常见误区：未经微调时，原始 [CLS] 向量并不是好的「句向量」，直接拿来算句子相似度效果很差。需要句向量请用 Sentence-BERT 或 mean-pooling。

双向注意力：每个词都看向所有词

这是 BERT 与 GPT 最本质的区别。下面矩阵的每一行是一个词，格子越蓝表示它对某个词的注意力越强。BERT 里整张表都可以点亮；GPT 只能点亮下三角（不能看未来）。

"it" 这一行可以关注到右边的 "tired"，从而知道 "it" 指代 "cat"——这需要向右看。

一层 = 两个子模块

① Multi-Head Self-Attention（base 有 12 个头，各看不同关系）→ ② Feed-Forward（768→3072→768）。每个子模块外都套 残差连接 + LayerNorm。

堆 12 层的意义

浅层偏向语法、局部搭配，深层偏向语义、指代、任务相关信息。层层叠加，表示越来越「懂意思」。

Train vs. Infer · 训练学什么，推理算什么
05

预训练靠完形填空自学，再微调到具体任务

BERT 没有人工标注就能学：随机盖住 15% 的词（[MASK]），让模型根据两边的上下文猜回来。这就是 Masked Language Model (MLM)。点句子里的任意词，把它盖住试试。

阶段一 · 预训练 （一次，很贵）

在海量无标注文本上学通用语言能力：

MLM：填被盖住的词（15% 中 80% 换 [MASK]、10% 换随机词、10% 不变）。
NSP：判断句 B 是否紧接句 A（后续 RoBERTa 证明这步可去掉）。
数据：BooksCorpus + English Wikipedia（约 33 亿词）。

阶段二 · 微调 & 推理 （便宜，你来做）

微调：接一个小任务头，用少量标注数据在几个 epoch 内训练完，主干权重也一起微调。
推理：只做一次前向传播，不再更新权重。

影响结果的关键：预训练权重版本（uncased/cased/多语言）、最大长度、微调数据质量、任务头设计。

为什么 MLM 不等于会写作？MLM 是「已知两边、填中间一个空」，不是「从左往右逐字生成」。所以 BERT 不能像 GPT 那样连续生成流畅文本——这是架构决定的，不是训练不够。

该不该用 BERT？

✓ 适合

  • 文本分类、情感分析、意图识别
  • 命名实体识别（NER）、序列标注
  • 抽取式问答（从原文划出答案）
  • 语义检索的编码器（配 Sentence-BERT）
  • 有一定标注数据、追求准确率的理解任务

✕ 不适合

  • 写文章、对话、续写等生成任务 → 用 GPT 类
  • 翻译 / 摘要等序列到序列 → 用 T5 / BART
  • 超长文档（>512 token 需截断或换 Longformer）
  • 想直接零样本用作句向量（需微调或用 SBERT）
  • 极低延迟 / 端侧场景（可考虑 DistilBERT）
Hands-on · 最小可运行示例
07

三行代码看到它的真实输出

用 Hugging Face transformers，先看 MLM 填空，再看拿到的向量形状。

# pip install transformers torch
from transformers import pipeline, AutoTokenizer, AutoModel
import torch

# ① 直接体验预训练目标：完形填空
fill = pipeline("fill-mask", model="bert-base-uncased")
print(fill("The man went to the [MASK] to buy milk.")[0])
# → {'token_str': 'store', 'score': 0.52, ...}

# ② 取出每个词的上下文向量
tok = AutoTokenizer.from_pretrained("bert-base-uncased")
model = AutoModel.from_pretrained("bert-base-uncased")

x = tok("the cat sat on the mat", return_tensors="pt")
with torch.no_grad():
    out = model(**x)

print(out.last_hidden_state.shape)  # torch.Size([1, 8, 768])
#   1 = batch, 8 = [CLS]+6词+[SEP], 768 = 每词向量维度
cls_vec = out.last_hidden_state[:, 0]     # [CLS] → 整句表示 [1, 768]

部署与工程取舍

生产上常做：ONNX / TorchScript 导出加速、量化（int8）降显存、按最大长度截断/分桶、GPU 批处理提吞吐。延迟敏感就换 DistilBERT 或 ALBERT。

还想问的几件事

为什么最大长度是 512？
位置嵌入是学出来的，只训练了 0–511 共 512 个位置。超过就没有对应的位置向量。想处理长文本得截断、滑窗，或改用 Longformer / BigBird 这类稀疏注意力模型。
uncased 和 cased 选哪个？
uncased 会把文本转小写、去重音，适合大小写不重要的任务；cased 保留大小写，做 NER 等对大小写敏感的任务更好（如区分 Apple 公司 vs apple 水果）。
[MASK] 只在预训练出现，微调/推理时还有吗？
没有。[MASK] 只是预训练 MLM 的工具。这会造成「预训练见得到、下游见不到」的不匹配——所以原论文里 15% 被选中的词只有 80% 真换成 [MASK]，另 10% 换随机词、10% 保持原样，缓解这个差距。
微调需要多少数据和算力？
远小于预训练。常见任务几千到几万条标注、单张消费级 GPU 跑几个 epoch（几分钟到几小时）即可。这正是「预训练一次、到处微调」范式省钱的地方。
