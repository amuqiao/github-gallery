它是什么，为什么出现

主动说话人检测（ASD）回答一个很具体的问题：给定视频画面中的一张人脸，此刻这个人是否在发出可听见的语音？纯音频只能告诉你「有人在说」，纯视觉又会被咀嚼、微笑等嘴部动作骗到——所以这个任务天然是音视频融合问题。它是说话人日志（speaker diarization）、视频会议导播、影视字幕对齐、多模态数据清洗等下游系统的基础组件。

之前的做法

主流方法只看很短的时间窗（几百毫秒的嘴动 + 声音），短时的抖动和无声嘴动很容易误判。

TalkNet 的核心主张

用长时序特征做判断：视觉流用 TCN 看更长的嘴部动态，音视频之间用交叉注意力对齐，再用自注意力捕捉长程音画同步证据。

拿到的结果

AVA-ActiveSpeaker 验证集 mAP 92.3（当年领先约 2.2%），Columbia 数据集 F1 96.3。

这个仓库给你的

不只是模型代码：训练、评测、野外视频端到端 demo、两个预训练权重，以及作者维护的 ASD 论文清单 awesomeASD.md。

它做什么

逐帧二分类打分

输入是一条人脸轨迹（连续帧的人脸裁剪）加对应音频，输出是这条轨迹每一帧的说话置信分。分数 > 0 判为说话。就这么一件事，做到很准。

它不做什么

不认人、不分离语音

它一次只看一条人脸轨迹，不建模画面中多张脸的相互关系（谁在听谁）；不做人脸识别、说话人识别，也不做语音分离或转写。多脸场景是对每条轨迹独立打分。

在生态中的位置

承上启下的中间件

上游依赖人脸检测 + 跟踪（仓库内置 S3FD），下游把「谁在说话」的时间轴喂给 diarization、视频剪辑、导播切换等系统。它是这条链路里的判断核心。

模型架构：两条流，三次注意力

模型定义集中在 model/talkNetModel.py，不到 100 行，结构非常清晰：音频流（琥珀色）和视觉流（蓝色）各自编码成 128 维、帧率对齐的序列，先互相做交叉注意力（拿对方的信息修正自己），再拼接成 256 维做自注意力，最后一个全连接层输出二分类。悬停每个模块看细节。

AUDIO STREAM · audioEncoder.py
VISUAL STREAM · visualEncoder.py
音频输入 MFCC 13-dim @100fps
↓
audioEncoder SE-ResNet 2D CNN → T × 128
视觉输入 灰度人脸 112×112 @25fps
↓
visualFrontend + TCN 3D Conv + ResNet18 → TCN → T × 128
↓           ↓
crossA2V audio attends to video · 8 heads
crossV2A video attends to audio · 8 heads
↓ concat → 256-dim ↓
selfAV 自注意力 attentionLayer(d_model=256, nhead=8) → reshape (T, 256)
↓
FC 256 → 2 逐帧输出：speaking score（>0 判为说话）
L = LAV + 0.4 · LA + 0.4 · LV   — 两个单模态辅助损失（loss.py）逼着每条流各自也学会判断，防止一条流偷懒

三条使用路径：按你的目的选入口

仓库只有两个可执行入口：demoTalkNet.py（推理/野外评测）和 trainTalkNet.py（AVA 训练/评测），没有配置文件，所有参数走命令行 argparse。对应三种典型目的：

环境（注意版本年代）

# 作者环境是 Python 3.7.9 时代，requirement.txt 里还有 youtube-dl
conda create -n TalkNet python=3.7.9 anaconda
conda activate TalkNet
pip install -r requirement.txt   # torch≥1.6, scenedetect, opencv, python_speech_features, gdown…

把视频丢进 demo/ 目录，一条命令

# mp4 / avi 都可以；首次运行会用 gdown 从 Google Drive 自动下载 pretrain_TalkSet.model
cp 你的视频.mp4 demo/001.mp4
python demoTalkNet.py --videoName 001
# 只处理片段：--start 10 --duration 30；人脸太小可调 --minFaceSize / --facedetScale

你会看到的日志和产物

2026-07-31 10:00:01 Extract the video and save in demo/001/pyavi/video.avi
2026-07-31 10:00:05 Extract the audio …  → audio.wav (16kHz mono)
2026-07-31 10:00:12 Scene detection …
2026-07-31 10:01:30 Face detection …  （S3FD，逐帧，全流程最慢的一步）
2026-07-31 10:02:10 Face track and detected 4 tracks
2026-07-31 10:03:40 Scores extracted and saved in demo/001/pywork
→ 最终结果：demo/001/pyavi/video_out.avi（绿框=说话，红框=沉默）

想集成到自己系统里？不要 import 这个仓库——它没有包结构。正确姿势是把 demoTalkNet.py 当参考实现，抄走「MFCC 提取 + 人脸 112×112 灰度化 + talkNet.loadParameters() + lossAV.forward(x, labels=None) 取分数」这条最小链路，人脸检测跟踪换成你自己的（但注意下面「边界与坑」第 1 条）。CPU 推理需手改代码：把 cuda 全部替换为 cpu，并给 torch.load 加 map_location。

一键下载并预处理 AVA-ActiveSpeaker（很大，需耐心）

python trainTalkNet.py --dataPathAVA AVADataPath --download
# 目录约定写在 utils/tools.py 的 preprocess_AVA 里：clips_videos / clips_audios / csv 标注

端到端训练

python trainTalkNet.py --dataPathAVA AVADataPath
# 默认 lr=1e-4，逐 epoch 衰减 0.95，maxEpoch=25
# batchSize=2500 指「动态批：每批约 2500 帧」——同长度视频排序分桶，解决变长输入
# 产物：exps/exp1/score.txt（训练日志）、model/model_00xx.model、val_res.csv

用官方预训练权重直接评测

python trainTalkNet.py --dataPathAVA AVADataPath --evaluation
# 自动下载 pretrain_AVA.model
# 预期：val mAP ≈ 92.3（作者复跑波动区间 92.1–92.6），test mAP 90.8（需上传官方评测）

参考成本（FAQ 给出）：15.01M 参数，单张 22G 显存 GPU 上每个 epoch 训练约 15 分钟、验证约 5 分钟，25 个 epoch 内收敛，总计约 7 小时。这在 ASD 复现里算相当友好的。

为什么有第三条路：AVA 模型出了 AVA 就不太行

FAQ Q3.1 说得很坦白：AVA 的人脸框来自其自有检测器，风格难以复现。你用 S3FD 等其他检测器裁出来的脸，和 AVA 训练分布不一致，AVA 权重在野外视频上表现会掉。于是作者用 VoxCeleb2 + LRS3 重组出 TalkSet——一个人脸全部由 S3FD 检出的「野外」训练集，共 9 万余段、含 TAudio / TSilence / TFAudio / FAudio / FSilence 五类音画组合。

数据集不直接提供，给你的是配方

# TalkSet/ 目录下：
lists/lists_in/    # 用到的 VoxCeleb2 / LRS3 源文件清单
lists/lists_out/   # 生成后的五类样本 + train/test 划分
generate_TalkSet.py  # 生成脚本（作者注明：未再验证，仅供参考）

直接用现成的 TalkSet 权重在 Columbia 上评测

python demoTalkNet.py --evalCol --colSavePath colDataPath
# 自动下载 Columbia 视频、标注和 pretrain_TalkSet.model；预处理一次约 1.5h、占 20G
# 预期 F1：Bell 98.1 / Boll 88.8 / Lieb 98.7 / Long 98.0 / Sick 97.7 → Avg 96.3

实用结论：拿去用在自己的视频上，选 pretrain_TalkSet.model（demo 默认就是它）；要刷 AVA 榜或做学术对比，用 pretrain_AVA.model。

边界、误区与工程成本

适合
  • 离线批处理：给访谈、会议录像、影视素材生成「谁在何时说话」的时间轴
  • 数据管线：清洗/筛选音画同步的说话人片段（如构建 AVSpeech 类数据集）
  • 学习与科研基线：代码短、结构清晰、7 小时可复现论文结果，是 ASD 入门的标准起点，后续 Light-ASD 等工作直接沿用了它的 demo 流水线
不适合 / 需要二次开发
  • 实时场景：demo 流水线是多阶段离线设计（先全量拆帧再检测），逐帧 S3FD 很慢，直接拿来做直播导播会失望
  • 极端画面：作者自述短于 1 秒的片段、小脸、大侧脸效果不佳；脸检不出来则整条链路失效
  • 多人交互建模：不利用「同屏其他脸」的上下文，这类需求应看 ASC / LoCoNet 一系
坑 01预训练权重和人脸检测器是绑定的
这是本项目最重要的隐性约束：pretrain_AVA.model 只认 AVA 风格的人脸框，pretrain_TalkSet.model 只认 S3FD 风格的人脸框（含 --cropScale 0.40 的外扩裁剪）。如果你把人脸检测器换成 RetinaFace / InsightFace 而不重训或不对齐裁剪方式，精度会无声下降。换检测器 ≠ 即插即用。
坑 02依赖年代久远，环境要「考古」
目标环境是 Python 3.7.9 + torch≥1.6；requirement.txt 里有已停止维护的 youtube-dl，scenedetect 新版 API 与代码中 VideoManager 用法不兼容，需要锁旧版本（如 scenedetect<0.6）。ffmpeg 是硬性运行时依赖（视频/音频/拆帧全靠 shell 调用）。新显卡遇到 CUDA error: no kernel image 时需按 FAQ 换 PyTorch 构建。
坑 03权重与数据从 Google Drive 走 gdown 下载
首次运行会静默调用 gdown --id 1AbN9… 拉取模型。无法访问 Google Drive 的网络环境会卡住且报错不明显；gdown 也时常遇到配额限制。建议手动下好 pretrain_TalkSet.model 放到仓库根目录，脚本检测到文件存在就会跳过下载。
坑 04CUDA 写死在代码里，输出目录会被清空
talkNet.py 里 .cuda() 是硬编码，CPU 推理要手改（README 给了改法）。另外 demoTalkNet.py 每次运行会 rmtree 删掉 demo/<videoName>/ 整个输出目录重来——中间产物别放贵重东西，长视频重跑代价高。
坑 05「score > 0 = 说话」之前还有一次平滑
可视化时每帧分数取了前后共 5 帧的滑动平均（numpy.mean(score[fidx-2 : fidx+3])）再判正负。如果你直接读 pywork/scores.pckl 做下游逻辑，记得决定要不要复刻这个平滑，否则边界帧的判定会和 video_out.avi 里看到的不一致。

同类项目对比与采用建议

ASD 是个活跃的小领域（作者自己在 awesomeASD.md 里维护论文清单）。放在坐标系里看 TalkNet 的位置：

项目出处AVA val mAP*思路特点什么时候选它
ASC (Active Speakers in Context)CVPR 2020~87建模同屏多脸上下文研究多人交互关系本身
TalkNet-ASD（本项目）ACM MM 202192.3长时序 + 交叉/自注意力，单轨迹独立判断要一条完整可跑的端到端流水线、要野外权重、要易读的基线

* 均为各论文报告值，非同机复测；写作本文时数值可能已被更新工作超越。

一句话判断

把它当「参考实现 + 可用工具」而不是「生产级 SDK」。如果你的需求是离线视频里标出谁在说话，clone 下来锁好旧依赖、跑通 demo，大概率半天内能出结果；如果要进生产，预期的二次开发包括：换掉多阶段离线预处理、处理 CUDA/CPU 硬编码、绕开 Google Drive 分发、以及最关键的——保证人脸裁剪方式与所用权重一致。

作为学习材料它几乎没有对手：模型 100 行、训练循环 100 行、流水线 400 行，一个下午能读完，读完你就同时理解了「ASD 这个任务」和「音视频融合模型的标准做法」。MIT 风格开源（见 LICENSE.md），作者在 issues 和 FAQ 里回复相当勤快。
